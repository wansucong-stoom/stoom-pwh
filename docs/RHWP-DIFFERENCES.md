# rhwp 원본과 Pwh의 차이

Pwh는 [rhwp](https://github.com/edwardkim/rhwp)와 rhwp Studio를 기반으로 합니다. 이 문서는 원본을 대체하거나 원 제작자의 기여를 줄여 설명하기 위한 것이 아니라, Pwh에서 유지하는 변경과 추가 기능을 추적하기 위한 안내입니다.

## 비교 기준

- **기준 원본:** rhwp 0.8.7, 커밋 [`1a76570e833917d15817415a53c09ad61ab3203f`](https://github.com/edwardkim/rhwp/commit/1a76570e833917d15817415a53c09ad61ab3203f).
- **공통 코어:** 이 버전 소스는 `rhwp-0.8.7-pwh-r17`의 누적 26개 패치와 공통 Studio 편집기 보완을 포함합니다. 이전 r16·r15 기록은 별도로 보존합니다. 배포 런타임의 Windows x64 자산과 확정된 해시는 [runtime-lock.json](../runtime-lock.json)에 기록합니다.
- **비교 범위:** 위 고정 버전 대비 Pwh에서 보존한 코어 패치와 Studio 빌드 변경, 그리고 별도의 pwh 연결 기능입니다. 현재 최신 rhwp와의 비교는 아닙니다.
- **배포 방식:** 고정 소스와 패치·빌드 입력을 보존해 재빌드하는 방식입니다. 전체 upstream 저장소의 Git 포크나 모든 원본 파일을 그대로 포함한 저장소라는 뜻은 아닙니다.
- **반영 상태:** 아래는 pwh 쪽 변경입니다. rhwp 원본에 병합되었다고 주장하지 않습니다.

## 1. rhwp 조판 코어 변경

### r17: 글자 커서와 중첩 표 연속 배치

**Pwh 0.6.44 · Desktop 0.1.25 / r17.** 두 제품이 같은 공통 WASM을 사용하며 r16 뒤에 23~26번 패치를 추가합니다. 원문이나 화면 좌표를 문서별로 보정하지 않습니다.

| 변경 | 확인한 발생 계층 | 보완한 규칙 |
| --- | --- | --- |
| 높은 개체 줄의 거대 커서 | **rhwp 원본에서 유래한 코어 조회 경로.** 일부 API가 실제 TextRun의 줄 상자를 삽입 커서 높이로 사용했습니다. | 글자 크기·baseline을 클릭·셀 조회·줄 이동에 공유합니다. hit 영역과 줄 배치는 그대로 두며 세로·회전 글자의 기존 방향을 유지합니다. |
| 중첩 인라인 표의 후속 행 누락 | **Pwh의 추가 코어 패치층에서 발생한 분할 회귀.** r10과 r13 출력 사이의 회귀를 확인했으나 최초 유발 패치는 확정하지 않았습니다. | 자식의 실제 RowCut과 저장된 다음 쪽 경계를 상위 투영·행 전체 수용·그리기까지 전달합니다. 원본 조건을 만족하지 않는 문서는 기존 경로로 처리합니다. |
| 반복 머리행 뒤의 겹침 | **Pwh 추가 물리 공간 계산.** 그리기에서 반복한 머리행을 상위 표 높이 예약에서는 빠뜨렸습니다. | 실제 이어지는 자식 조각에 반복 머리행과 셀 간격을 한 번만 예약합니다. 원문 소비 커서는 늘리지 않습니다. |
| 문단 기준 표와 앞 제목의 순서 | **고정 rhwp 원천 코어의 source-order fallback.** 컨트롤의 텍스트 위치로 앞뒤 순서를 정하는 경로가 문단 기준의 실제 배치를 반영하지 못했습니다. | Pwh가 원본 프레임·완전한 행 prefix·본문 수용 조건을 확인하는 경우에 한해 순서 판정을 보완합니다. 다른 배치와 기존 제외 조건은 유지합니다. |

26개 WASM 패치와 별도로 Studio 공통 편집기의 클릭 좌표 캐시와 깊은 셀 Home/End 기하를 보완했습니다. 아래 Studio 절에 발생 계층을 구분합니다. 정식 코어·공통 편집기·실제 PDF를 연결한 결과는 [r17 검증 범위](LAYOUT-FIDELITY.md#r17-caret-and-continuation), 지원 조건과 반례는 [커서와 표 연속 분할](engine-patches/CARET-AND-CONTINUATION.md)을 참고하세요. 배포물별 결과는 해당 릴리스의 `DESKTOP-VERIFICATION.json`으로 확인합니다.

### r16: 중첩 표의 원문 소유권과 편집 응답성

**Pwh 0.6.43 · Desktop 0.1.24 / r16.** 기존 열여덟 패치 뒤에 19~22번을 순서대로 적용합니다. 19번은 [`rhwp-0.8.7-nested-forward-frame-ownership.patch`](engine-patches/rhwp-0.8.7-nested-forward-frame-ownership.patch)입니다. 이 원문 소유권 수정의 발생 계층은 **Pwh가 rhwp 위에 유지하는 공통 코어 추가 패치층**이며, Desktop 전용 수정이나 모든 rhwp 원본에 공통인 결함으로 설명하지 않습니다. 20~22번의 원인은 아래에서 각각 구분합니다.

| 변경 | 보완한 규칙 | 적용 한계 |
| --- | --- | --- |
| 중첩 표의 다음 쪽 내용 | 저장된 원문 분할 경계를 일반 스캐너·블록 수용·상위 분할 커서가 함께 사용합니다. 다음 쪽의 내부 표 행을 앞 쪽에서 미리 소비하지 않습니다. | 원본 줄·자식 구조·소유 범위가 증명되는 경우에 한합니다. 편집·합성 근거로 새 저장 경계를 만들지 않습니다. |
| 내용 범위와 물리적 공간 | 이번 쪽에서 소비하는 원문과 행이 차지하는 높이를 구분합니다. 짧은 내용에 맞춰 프레임을 축소하거나, 남은 빈 공간을 다음 쪽 내용으로 채우지 않습니다. | 현재 본문 용량과 원문 속성으로 배정하며, 문서별 고정 이동량이나 전체 선언 높이의 일괄 강제는 사용하지 않습니다. |
| 부모·자식 여백 | 부모 셀의 안 여백과 자식 표의 바깥 여백을 각각 한 번 처리하고, 가운데 정렬을 해당 행의 실제 내용·공간으로 계산합니다. | 다른 소유자가 이미 예약한 여백을 다시 차감하거나 더하지 않습니다. |
| 중첩 문단의 저장·재열기 | 편집으로 기존 프레임 근거가 무효화되었다는 이력을 HWPX 보조 JSON으로 보존합니다. 동일한 header·구역 XML 해시와 구조 경로·문단 지문이 맞을 때만 복원합니다. | 표준 XML·공백 메트릭을 합성하지 않습니다. 외부 앱이 이력을 제거하거나 XML을 바꾸면 복원을 보장하지 않습니다. |

원인은 Pwh의 저장 프레임 해석에서 내용 소비와 물리적 배정을 혼용한 경로입니다. 편집 후 재열기 문제는 이번 Pwh 후보가 판정에 사용한 일시적 재조판 이력을 저장하지 못해 발생한 회귀로, 함께 수정했습니다. 새 보조 이력은 원본 프레임의 **재사용을 거절하는 정보**이며 새 배치를 인증하거나 문서의 모든 조판 상태를 복원하는 정보가 아닙니다. 같은 구역의 다른 표에 전역 편집 상태를 적용하지 않습니다.

공식 22개 패치를 적용한 최종 코어와 실제 PDF를 연결해 기존 승인 1~7쪽을 유지하고 8쪽 목표를 통과했습니다. 앞선 19개 패치 단계의 PDF와 전체 39쪽 픽셀·정규화 텍스트가 같음을 확인했으며, 최종 PDF의 1~8쪽 점수도 새로 계산했습니다. 최종 코어 시험은 468건 중 407건 통과·61건 환경별 제외·실패 0건입니다. 전체 브라우저 검사는 474건 중 460건 통과·14건 환경별 제외·실패 0건입니다. 두 검사 집합은 겹칩니다. 설치 파일의 별도 검증은 릴리스의 [DESKTOP-VERIFICATION.json](https://github.com/wansucong-stoom/stoom-pwh/releases/download/v0.6.43/DESKTOP-VERIFICATION.json)을 참조하세요. [정량 결과와 남은 차이](LAYOUT-FIDELITY.md#r16-forward-frame-ownership), [검증 기록](verification/fidelity-weekly-0.6.43.json)을 기준으로 최종 반영 상태를 확인합니다.

| 추가 패치 | 원인 계층 | 보완과 범위 |
| --- | --- | --- |
| 20. 작은 용지의 float 투영 | **Pwh의 기존 17번 코어 패치 회귀.** 행 투영에서는 외형만 확인하고 예약·그리기에서는 전체 원문 프레임을 검사해 조건이 달랐습니다. | 같은 전체 프레임 판정을 사용합니다. 본문에 들어가지 않는 저장 프레임은 기존 분할로 돌아가며, r13과 비교한 작은 용지 시험의 기대값을 바꾸지 않습니다. |
| 21. 이어진 셀의 커서 기하 | **고정 rhwp 원천 코어.** 글줄이 없는 셀 조각의 높이를 커서 높이로 사용했습니다. | 같은 구역·셀 경로의 실제 글줄 경계로 이동합니다. 진짜 빈 셀은 글자 모양·DPI·여백을 사용하며 깊은 중첩 경로·쪽 힌트·빈 텍스트 run을 구분합니다. |
| 22. 높이 변경·표 경계 조회 | **고정 rhwp 원천 코어의 변경·측정·조회 경로.** 높이만 바꿔도 같은 문단의 형제 표를 다시 측정하고 경계 조회에서 불필요한 전체 처리를 수행했습니다. | 정리된 비배치 상태이고 조판 프로필이 같을 때만 바뀌지 않은 형제 측정값을 한 호출 안에서 재사용합니다. 변경된 표·하위 표와 전체 쪽 나눔은 유지하며, 폭·혼합·미완료 작업 등은 기존 처리로 돌아갑니다. |

20번은 작은 용지에서 실제 표시 중복·누락·음수 좌표를 일으켰던 기존 회귀입니다. 선택적 기준 코어 환경변수가 빠져 CI에서 건너뛰던 3개 시험을 독립 r13 기준선에 연결했습니다. 새 후보를 기준선으로 삼거나 기존 assertion을 느슨하게 바꾸지 않았습니다.

21·22번은 Pwh와 Desktop이 함께 사용하는 코어 수정입니다. 앞선 Chrome 후보 계측과 최종 코어·UI의 실제 Electron 통제 비교, 39쪽 전체 SVG·배치·XML 보존 검사를 구분합니다. Electron 비교에서 높이 변경 약 58%·일반 셀 입력 실행 취소 약 42.7% 감소를 측정했지만 이전 설치판의 직접 비교는 아닙니다. 글자 입력 향상은 주장하지 않으며, 제외한 최초 반복 키 시도의 선택 유실 1회는 원인 미확정으로 기록합니다. GPU 합성은 이미 켜져 있으며 Worker·OffscreenCanvas 지원이 현재 편집기의 병렬 조판을 뜻하지 않습니다. [성능 수치·재사용 조건·검증 한계](EDITOR-PERFORMANCE.md), [20~22번 패치 상세](engine-patches/README.md#r16-interaction-and-fallback)를 참고하세요.

Desktop 전용 Codex 플러그인 설치에서는 Windows 디렉터리 게시의 일시 실패를 제한적으로 재시도하고, 다른 실행이 만든 런타임은 소유 표식과 파일을 검증한 뒤 사용하도록 보완했습니다. 지속 실패를 성공으로 처리하거나 사용자 지정 경로를 덮어쓰지 않습니다. 조판 코어 변경과 별개이며, 추가한 6개 설치 회귀시험은 최종 전체 브라우저 실행에 포함됐습니다.

### r15: 같은 코어의 검증·보존 갱신

Pwh 0.6.42와 Desktop 0.1.23은 r14와 **같은 WASM·JavaScript 연결부와 열여덟 패치**를 사용합니다. 조판 알고리즘은 추가 변경하지 않았습니다. r15는 새 제품 버전과 실제 잉크 검증 소스를 함께 보존한 런타임 개정입니다.

합성 SVG 검증은 글꼴의 전체 상자 대신 실제 PNG 잉크를 검사합니다. 공통 정책의 150 dpi·2픽셀을 유지하고, 원래·대체 글꼴 및 부분·전체 잘림 반례를 확인합니다. 발생 계층은 제품 코드와 구분되는 **검증 도구**입니다. [방법과 한계](INK-VALIDATION.md)

### r14: 저장 프레임과 중첩 개체 소유권

Pwh 0.6.41과 Desktop 0.1.22는 **r14**의 같은 코어를 사용합니다. 고정 원본에 기존 열네 패치와 새 네 패치를 순서대로 적용하며, 소스·코어·편집기 번들·manifest를 함께 빌드합니다.

| 변경 | 코어에서 보완한 규칙 | 제한 |
| --- | --- | --- |
| 저장된 표 프레임의 여백·최소 공간 | 같은 빈 호스트의 개체 프레임에서 바깥 여백을 처리하고, 열 전체를 채우는 나란한 셀의 공통 선언 최소 높이를 실제 쪽 조각에 보존합니다. 승인한 소유권을 그리기·커서에 전달합니다. | 저장된 물리 원점·열 소유 범위로 입증되는 경우에 한합니다. 다른 최소 높이·교차 행 병합 등은 기존 경로를 유지합니다. |
| 쪽 번호 설정의 시작 위치 | 원문 설정 컨트롤과 실제 소유 표 조각의 순서로 적용 시작 쪽을 판단합니다. | 기존 번호 재시작·감추기·일반 글줄 판정은 유지합니다. |
| 중첩 표·떠 있는 표의 물리 점유 | 뒤 형제 표가 새 쪽에서 시작할 때 이미 소비한 문단 오프셋을 중복 적용하지 않습니다. 원본이 입증한 인라인 개체의 첫 물리 프레임과 바깥 여백을 보존하고, 가시 호스트 줄 아래의 float는 같은 닫힌 원본 프레임을 측정·그리기에 사용합니다. | 원본·실제 조합 줄·본문 용량을 함께 확인합니다. 편집·현재 재조판 이력, 작은 용지와 충돌하는 저장 좌표, 출처가 없는 조각은 기존 경로를 유지합니다. |
| 다음 쪽 행과 온전한 셀의 배치 | 검증된 다음 쪽 경계를 행 전체 수용·일반 스캐너·상위 표 커서에 유지합니다. 원본 행의 여백과 그림의 문단 기준점을 보존하며, 그림 공간 속성 변경 후에는 해당 원본 캐시를 무효화합니다. | 정확한 원본 닫힘과 현재 본문·측정을 함께 검증합니다. 미지원 개체·경계 병합·다단을 추정하지 않습니다. [조건과 검증 범위](engine-patches/STORED-NESTED-TAIL.md) |

발생 위치는 **rhwp 조판 코어**이며 Pwh·Pwh Desktop이 같은 WASM을 사용합니다. 이 중 float의 컨트롤 위치를 표시 순서로 해석한 문제는 **Pwh r13 코어 패치에서 생긴 회귀**입니다. 모든 원인을 수정 전 rhwp 원본의 오류로 설명하지 않습니다. Studio의 메뉴·선택 연결이나 Desktop 전용 좌표 보정과도 구분합니다.

원문·글꼴·여백·선언 셀 크기는 보존합니다. 원본 프레임·쪽 번호 시험 19건·22건과 새 float·형제 오프셋·개체 프레임 시험 33건·9건·18건을 분리합니다. 새 원본 함수 시험 87건과 다음 쪽 소비·그림 편집·저장·재열기·실행 취소 검사도 추가했습니다. 정식 코어의 실제 전체 PDF에서 앞 **1~7쪽**이 순차 검증을 통과했습니다. 다음 대상은 **8쪽**이며 39쪽 전체 승인과 구분합니다. [프레임 소유권](engine-patches/STORED-FRAME-OWNERSHIP.md), [중첩 개체의 원본 프레임](engine-patches/NESTED-FLOAT-FRAMES.md), [쪽별 결과와 한계](LAYOUT-FIDELITY.md#r14-source-frame-candidate)를 함께 확인하세요.

### 이전 r13에서 유지한 보완

r13은 분할 계산과 화면 배치가 같은 표·본문 순서를 사용하도록 보완합니다. `CELL` 분할은 저장된 쪽 재시작이 없어도 남은 공간을 사용할 수 있으며, 실제 저장 쪽 경계를 강제하는 판정은 별도로 유지합니다. 여러 저장 프레임을 가진 행의 선언 높이에 포함된 빈 공간을 내용으로 다시 더하지 않고, 글줄 없는 조각에서도 선택된 자식 표 행을 표시합니다. 컨트롤 위치의 문자 인덱스와 UTF-16 저장 위치도 구분합니다.

r12는 빈 호스트에 담긴 중첩 표에서도 저장된 행의 자식별 분할 커서를 전달하고, 한 줄에 온전히 저장된 인라인 표의 개체 줄을 보존합니다. 선언 높이를 줄이거나 표시 영역을 넓혀 잘림을 숨기는 방식은 사용하지 않습니다. Pwh 0.6.40과 Desktop 0.1.21에 같은 코어로 적용하며, 앞선 r11의 원점·빈 호스트 점유 보완도 유지합니다.

r11은 r9·r10에서 유지한 열 패치에 쪽 시작 원점과 중첩 표 호스트 점유 패치를 추가한 **편집기 WASM 코어**입니다. Pwh 0.6.39와 Desktop 0.1.20은 같은 새 코어를 사용합니다. r10과 Pwh 0.6.38의 빌드·타입 검사 보완은 그대로 유지합니다.

**적용 경로를 구분해야 합니다.** r3 이후 코어 보완은 편집기용 WASM을 다시 빌드합니다. 보존된 네이티브 CLI와 별도 Studio에 묶인 WASM은 이 코어 패치로 교체하지 않았습니다. 따라서 모든 PNG/PDF 출력이나 별도 Studio에도 동일한 수정이 적용됐다고 보장하지 않습니다. [런타임 보존 및 재빌드](engine-preservation.md)

### 중첩 표의 페이지 소유 정보 보존

배포 코어는 본문과 여러 행의 표가 같은 문단에 있는 경우, 자식 표의 행·셀 분할 범위를 실제 조판과 렌더링에 전달하는 코어 패치를 적용합니다. 앞 페이지에서 소진된 라벨 셀을 제외하고 이어지는 원문 문단의 소유 범위를 확인하며, 글만 소유한 조각이 같은 표를 다시 그리지 않게 합니다. 원문이나 저장된 셀 크기를 바꿔 화면을 맞추는 방식은 아닙니다.

HWP·HWPX의 중첩 표 사례, 합성 문서의 가시성·저장·실행 취소와 원래 셀 주소를 검증했습니다. 이 변경은 r4에서 반영되어 현재 보존 런타임에도 포함되며, Pwh와 Pwh Desktop이 같은 편집기 엔진으로 사용합니다. 적용 조건과 소스 해시는 [엔진 패치 상세](engine-patches/README.md)에 있습니다.

65쪽 기준 출력의 전후 결과와 남은 차이는 [조판 일치 검증](LAYOUT-FIDELITY.md)에 정리했습니다. 새 Canvas 속성을 사용하는 JavaScript 연결부도 코어와 같은 빌드로 검증하며 공통·Desktop 편집기에 함께 반영합니다.

**남아 있는 중첩 표 분할 제한:** 2026-11-02의 추가 HWPX 검증에서 한컴 39쪽과 달리 공식 npm rhwp 0.8.7 및 Pwh r11이 모두 43쪽을 계산했습니다. 진단 문구의 페이지 아래 배치와 다음 쪽 이월 누락도 두 코어의 SVG에서 동일하게 재현됩니다. 따라서 해당 페이지 수 차이와 잘림은 Desktop 인쇄나 r11에서 새로 생긴 회귀로 볼 수 없습니다. 빈 문단에 담긴 중첩 표에서 일반 글·내부 표가 섞인 행을 자식별 분할 유닛으로 투영하지 못하는 원천 코어의 조건을 확인했습니다. 기존 보완이 모든 중첩 표를 해결했다고 볼 수 없습니다. 정적 코드 진단, 원문 보존과 출력 누락의 차이, 미검증 범위는 [긴 중첩 표 검증](LAYOUT-FIDELITY.md#긴-중첩-표-hwpx의-추가-검증)에 구분했습니다. 이번에는 새 엔진 패치를 적용하지 않았습니다.

## 2. rhwp Studio 편집기 변경

Pwh의 내장 편집기는 rhwp Studio를 바탕으로 빌드하며, 원본 Studio 입력에 보존된 변경과 Pwh 빌드 단계의 추가 변경을 적용합니다. 대표적인 차이는 다음과 같습니다.

| 영역 | Pwh에서 적용한 변경 |

| 개체 속성 명령 | 원본 Studio의 상단 버튼 경로에서 빠졌던 표 개체 주소와 그림의 셀·머리말·꼬리말 참조를 보존합니다. 셀 안에서도 표 속성을 열며, 지원하지 않는 중첩 표를 바깥 표로 바꿔 열지 않습니다. [대상 보존과 검증](OBJECT-PROPERTIES.md) |
| 본문·주석 커서 연결 | 코어의 인라인 컨트롤을 포함한 위치와 Studio의 본문 글자 위치를 구분합니다. 주석 앞뒤의 방향을 보존하고 본문 입력·선택·서식에는 본문 오프셋을 전달합니다. |
| 선택 표시와 반응성 | 본문 선택 표시를 실제 조판 결과에 맞춰 보정하고, 선택 동작 중 계산을 재사용하도록 개선합니다. 단어·문단 선택의 실제 양 끝 쪽 정보를 전달해 표 선택이 문서 전체를 조사하지 않도록 합니다. |
| 설치 글꼴 | 시스템·사용자 글꼴을 편집기 목록과 렌더링에 연결하고, 확인된 로컬 글꼴을 우선 사용합니다. |
| 표와 클립보드 | 선택 셀 복사, 한글 문서 모델 및 Windows 클립보드 보조 경로, 셀 안의 표 붙여넣기와 넘친 표의 잘림 표시를 연결합니다. 셀 삭제 시 선택 범위에 따라 내용 또는 줄·칸 삭제를 선택할 수 있습니다. |
| 표 서식과 사용성 | 셀 속성·테두리 단축키와 우클릭 메뉴, 안쪽·바깥쪽 선 미리보기, 선 모양 표시, 공통 색상표와 최근 색상을 추가합니다. |
| 그림 표시 | 호스트의 이미지 보안 정책에 맞춰 내장 이미지와 클립보드 이미지의 표시 경로를 보완합니다. |
| 내장 화면과 협업 | Codex 패널에 맞춘 편집기 초기화, 문서 상태·선택 연결, AI 수정 요청 메뉴 및 상태 확인을 추가합니다. |
| 인쇄 미리보기와 편집 용지 | 화면 전용 확대·축소·맞춤과 준비된 쪽의 순차 표시, 용지 그림 주변의 여백 입력과 위치 강조를 추가합니다. 실제 인쇄 크기와 기존 용지 설정·실행 취소 경로를 유지합니다. |

중첩 표의 내부 복사·붙여넣기에는 rhwp가 원래 제공하는 엔진 기능을 사용하고, Pwh가 외부 표 가져오기와 선택 메뉴를 연결합니다. Studio에서 원래 제공한 기능 전체를 Pwh가 새로 만들었다는 뜻은 아닙니다. 실제 변경 지점은 [편집기 빌드 스크립트](../scripts/build-inline.mjs)와 관련 [소스](../src/)에서 확인할 수 있습니다. 성능과 이미지 표시의 검증 범위는 [선택·글꼴 성능](performance-2026-10-16.md), [내장 그림 표시](embedded-images-2026-10-19.md)에 기록합니다.

글꼴 준비·글자 모양 창은 rhwp Studio에서 이어받은 경로를 Pwh에서 보완한 것입니다. 단어·문단 다중 클릭의 쪽 정보 누락은 Pwh가 추가한 선택 연결의 문제였습니다. 상세 검증과 남은 성능 한계는 [편집기 성능 검증](EDITOR-PERFORMANCE.md)을 참고하세요.

## 3. Pwh가 별도로 제공하는 기능

다음은 rhwp 코어 패치와 구분되는 Pwh의 기능입니다.

- Codex와 AI 요청을 연결하는 스킬·MCP 도구 및 동일 문서에서의 선택 영역 수정
- 본문·셀·중첩 셀의 원문 검색과 텍스트 부분 수정, 혼합 서식·주변 개체 보존
- 요청 대상의 상태 확인, 충돌 방지, 변경 결과 확인과 실행 취소 연계
- 기존 표 셀 채우기, 구조화된 표 삽입, 병합 제목 행과 셀별 테두리 적용, 표 서식 적용 및 그림 교체
- HWPX 양식 분석·부분 수정, 새 수정본 저장, 런타임 설치와 검증

기능별 지원 범위는 [README](../README.md)와 [pwh 스킬](../skills/pwh/SKILL.md)을 참고하세요.

## 변경을 직접 확인하고 재현하기

- 코어 패치와 입력·출력 해시, 테스트: [엔진 패치 상세](engine-patches/README.md)
- 고정 원본, Studio 패치·빌드 입력, 라이선스와 보존 자산: [런타임 보존 안내](engine-preservation.md), [runtime-lock.json](../runtime-lock.json)
- 현재 내장 편집기에서 추가 적용하는 변경: [build-inline.mjs](../scripts/build-inline.mjs), [pwh 소스](../src/)
- 버전별 pwh 사용자 기능: [변경 이력](CHANGELOG.md)

r1/r2에서 보존한 Studio 차이와 이후 Pwh 편집기 변경이 함께 있으므로, **파일 수나 코드 줄 수 하나로 전체 차이를 표현하지 않습니다.** 정확한 비교에는 해당 릴리스의 보존 입력·패치와 현재 빌드 소스를 함께 봐야 합니다. 검증은 명시된 사례에 한하며, 한컴 한글과 모든 문서의 조판 결과가 같다는 뜻은 아닙니다.
