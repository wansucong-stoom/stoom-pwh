# rhwp 원본과 Pwh의 차이

Pwh는 [rhwp](https://github.com/edwardkim/rhwp)와 rhwp Studio를 기반으로 합니다. 이 문서는 원본을 대체하거나 원 제작자의 기여를 줄여 설명하기 위한 것이 아니라, Pwh에서 유지하는 변경과 추가 기능을 추적하기 위한 안내입니다.

## 비교 기준

- **기준 원본:** rhwp 0.8.7, 커밋 [`1a76570e833917d15817415a53c09ad61ab3203f`](https://github.com/edwardkim/rhwp/commit/1a76570e833917d15817415a53c09ad61ab3203f).
- **기본 런타임:** `rhwp-0.8.7-pwh-r9`, Windows x64. 설치 자산과 해시는 [runtime-lock.json](../runtime-lock.json)에 기록합니다.
- **비교 범위:** 위 고정 버전 대비 Pwh에서 보존한 코어 패치와 Studio 빌드 변경, 그리고 별도의 pwh 연결 기능입니다. 현재 최신 rhwp와의 비교는 아닙니다.
- **배포 방식:** 고정 소스와 패치·빌드 입력을 보존해 재빌드하는 방식입니다. 전체 upstream 저장소의 Git 포크나 모든 원본 파일을 그대로 포함한 저장소라는 뜻은 아닙니다.
- **반영 상태:** 아래는 pwh 쪽 변경입니다. rhwp 원본에 병합되었다고 주장하지 않습니다.

## 1. rhwp 조판 코어 변경

pwh-r9의 **편집기 WASM 코어**에는 다음 열 패치를 적용합니다.

| 변경 | 원본 대비 보완 | 적용 범위 |
| --- | --- | --- |
| 중첩 표의 페이지 소유와 높이 | 자식 표의 원문 분할 범위와 실제 부분 행 높이·셀 여백을 부모의 조판 예약에 전달합니다. 글만 소유한 조각이 표를 중복해서 그리지 않게 합니다. | 명시된 자식 행·셀 분할 원장을 가진 중첩 표 조판 |
| 표 내용에 맞는 행 높이 | 줄 배치 정보가 저장되지 않은 일부 표에서, 줄바꿈한 내용 때문에 늘어난 행이 다시 줄어들어 내용이 잘리는 경우를 보완합니다. | 조건에 맞는 가로쓰기 표 셀의 조판 |
| 편집으로 커진 표의 쪽 나눔 | 저장된 글자처럼 취급한 표의 글이 늘어나면 실제로 측정한 높이를 쪽 나눔에도 반영합니다. | 저장된 크기보다 내용이 커진 조건에 맞는 단순 텍스트 행 |
| 글자처럼 취급한 표 뒤 간격 | 특정 문단의 줄 간격 설정에서 표 뒤 문단이 지나치게 가까워지는 경우를 보완합니다. | 저장된 줄 배치가 없는 단일 인라인 표와 해당 줄 간격 조건 |
| 떠 있는 표 다음 본문 흐름 | 저장된 줄 배치가 없는 문단에서 표의 실제 끝을 다음 본문 위치에 반영합니다. | 조건에 맞는 단일 위아래 배치 표 |
| 문단 중간의 떠 있는 표 | 앞뒤 글자와 실제 컨트롤 위치로 표의 호스트 줄을 확인합니다. | 저장 위치가 명확한 문단 내부 표 |
| 저장 표의 후속 문단 원점 | 빈 호스트 표와 다음 문단이 같은 저장 프레임을 닫으면 공통 원점을 전달해 간격을 중복 계산하지 않습니다. | 편집·재조판이 없고 측정 높이·여백·배치 예산이 일치하는 단일 표 |
| 내장 기본 글머리표 | BULLET 참조 0의 기본 원형 표시와 본문 서식을 복원합니다. | 기본 참조 0; 명시 참조와 일반 문단은 별도 유지 |
| 도형 투명도와 둥근 모서리 | 채움 투명도 바이트를 보존하고 테두리와 분리하며, 모서리 비율을 짧은 변에 적용합니다. | 편집기 WASM의 도형 파싱·저장·화면/SVG 그리기 |
| 각주·미주의 원문 주소 | 표시·클릭·커서·삭제의 논리 주소를 맞추고, 원본 UTF-16 컨트롤 위치로 글자 서식을 보존합니다. | 본문의 각주·미주 참조 |

표 관련 패치는 문서의 원문 텍스트나 저장된 셀 높이를 일괄 변경하는 방식이 아니라 조판 계산에 적용됩니다. 주석 패치는 표시용 문자열과 본문·컨트롤 주소를 구분합니다. 조건과 회귀시험, 실제 패치 파일 및 재빌드 방법은 [엔진 패치 상세](engine-patches/README.md)에 있습니다.

**적용 경로를 구분해야 합니다.** r3 이후 코어 보완은 편집기용 WASM을 다시 빌드합니다. 보존된 네이티브 CLI와 별도 Studio에 묶인 WASM은 이 코어 패치로 교체하지 않았습니다. 따라서 모든 PNG/PDF 출력이나 별도 Studio에도 동일한 수정이 적용됐다고 보장하지 않습니다. [런타임 보존 및 재빌드](engine-preservation.md)

### 중첩 표의 페이지 소유 정보 보존

배포 코어는 본문과 여러 행의 표가 같은 문단에 있는 경우, 자식 표의 행·셀 분할 범위를 실제 조판과 렌더링에 전달하는 코어 패치를 적용합니다. 앞 페이지에서 소진된 라벨 셀을 제외하고 이어지는 원문 문단의 소유 범위를 확인하며, 글만 소유한 조각이 같은 표를 다시 그리지 않게 합니다. 원문이나 저장된 셀 크기를 바꿔 화면을 맞추는 방식은 아닙니다.

HWP·HWPX의 중첩 표 사례, 합성 문서의 가시성·저장·실행 취소와 원래 셀 주소를 검증했습니다. 이 변경은 r4에서 반영되어 현재 기본 런타임 r9에도 포함되며, Pwh와 Pwh Desktop이 같은 편집기 엔진으로 사용합니다. 적용 조건과 소스 해시는 [엔진 패치 상세](engine-patches/README.md)에 있습니다.

65쪽 기준 출력의 전후 결과와 남은 차이는 [조판 일치 검증](LAYOUT-FIDELITY.md)에 정리했습니다. 새 Canvas 속성을 사용하는 JavaScript 연결부도 코어와 같은 빌드로 검증하며 공통·Desktop 편집기에 함께 반영합니다.

## 2. rhwp Studio 편집기 변경

Pwh의 내장 편집기는 rhwp Studio를 바탕으로 빌드하며, 원본 Studio 입력에 보존된 변경과 Pwh 빌드 단계의 추가 변경을 적용합니다. 대표적인 차이는 다음과 같습니다.

| 영역 | Pwh에서 적용한 변경 |
| --- | --- |
| 대형 문서 입력 | 글자 수정마다 모든 쪽의 렌더 트리를 만들던 글꼴 준비를 문서의 글꼴 메타데이터 조회로 대체합니다. 기존 글꼴 해석기와 로딩 경로를 유지합니다. |
| 글자 모양 창 | 원본 Studio의 선택 필수 조건을 보완해 커서만 둔 경우에도 창을 열고 다음 입력 서식을 지정합니다. |
| 본문·주석 커서 연결 | 코어의 인라인 컨트롤을 포함한 위치와 Studio의 본문 글자 위치를 구분합니다. 주석 앞뒤의 방향을 보존하고 본문 입력·선택·서식에는 본문 오프셋을 전달합니다. |
| 선택 표시와 반응성 | 본문 선택 표시를 실제 조판 결과에 맞춰 보정하고, 선택 동작 중 계산을 재사용하도록 개선합니다. 단어·문단 선택의 실제 양 끝 쪽 정보를 전달해 표 선택이 문서 전체를 조사하지 않도록 합니다. |
| 설치 글꼴 | 시스템·사용자 글꼴을 편집기 목록과 렌더링에 연결하고, 확인된 로컬 글꼴을 우선 사용합니다. |
| 표와 클립보드 | 선택 셀 복사, 한글 문서 모델 및 Windows 클립보드 보조 경로, 셀 안의 표 붙여넣기와 넘친 표의 잘림 표시를 연결합니다. 셀 삭제 시 선택 범위에 따라 내용 또는 줄·칸 삭제를 선택할 수 있습니다. |
| 표 서식과 사용성 | 셀 속성·테두리 단축키와 우클릭 메뉴, 안쪽·바깥쪽 선 미리보기, 선 모양 표시, 공통 색상표와 최근 색상을 추가합니다. |
| 그림 표시 | 호스트의 이미지 보안 정책에 맞춰 내장 이미지와 클립보드 이미지의 표시 경로를 보완합니다. |
| 내장 화면과 협업 | Codex 패널에 맞춘 편집기 초기화, 문서 상태·선택 연결, AI 수정 요청 메뉴 및 상태 확인을 추가합니다. |

중첩 표의 내부 복사·붙여넣기에는 rhwp가 원래 제공하는 엔진 기능을 사용하고, Pwh가 외부 표 가져오기와 선택 메뉴를 연결합니다. Studio에서 원래 제공한 기능 전체를 Pwh가 새로 만들었다는 뜻은 아닙니다. 실제 변경 지점은 [편집기 빌드 스크립트](../scripts/build-inline.mjs)와 관련 [소스](../src/)에서 확인할 수 있습니다. 성능과 이미지 표시의 검증 범위는 [선택·글꼴 성능](performance-2026-10-16.md), [내장 그림 표시](embedded-images-2026-10-19.md)에 기록합니다.

글꼴 준비·글자 모양 창은 rhwp Studio에서 이어받은 경로를 Pwh에서 보완한 것입니다. 단어·문단 다중 클릭의 쪽 정보 누락은 Pwh가 추가한 선택 연결의 문제였습니다. 상세 검증과 남은 성능 한계는 [편집기 성능 검증](EDITOR-PERFORMANCE.md)을 참고하세요.

## 3. Pwh가 별도로 제공하는 기능

다음은 rhwp 코어 패치와 구분되는 Pwh의 기능입니다.

- Codex와 AI 요청을 연결하는 스킬·MCP 도구 및 동일 문서에서의 선택 영역 수정
- 본문·셀·중첩 셀의 원문 검색과 텍스트 부분 수정, 혼합 서식·주변 개체 보존
- 요청 대상의 상태 확인, 충돌 방지, 변경 결과 확인과 실행 취소 연계
- 기존 표 셀 채우기, 구조화된 표 삽입, 병합 제목 행과 셀별 테두리 적용, 표 서식 적용 및 그림 교체
- HWPX 양식 분석·부분 수정, 새 수정본 저장, 런타임 설치와 검증

기능별 지원 범위는 [README](../README.md)와 [pwh 스킬](../skills/pwh/SKILL.md)을 참고하세요.

## 변경을 직접 확인하고 재현하기

- 코어 패치와 입력·출력 해시, 테스트: [엔진 패치 상세](engine-patches/README.md)
- 고정 원본, Studio 패치·빌드 입력, 라이선스와 보존 자산: [런타임 보존 안내](engine-preservation.md), [runtime-lock.json](../runtime-lock.json)
- 현재 내장 편집기에서 추가 적용하는 변경: [build-inline.mjs](../scripts/build-inline.mjs), [pwh 소스](../src/)
- 버전별 pwh 사용자 기능: [변경 이력](CHANGELOG.md)

r1/r2에서 보존한 Studio 차이와 이후 Pwh 편집기 변경이 함께 있으므로, **파일 수나 코드 줄 수 하나로 전체 차이를 표현하지 않습니다.** 정확한 비교에는 해당 릴리스의 보존 입력·패치와 현재 빌드 소스를 함께 봐야 합니다. 검증은 명시된 사례에 한하며, 한컴 한글과 모든 문서의 조판 결과가 같다는 뜻은 아닙니다.
