# rhwp 원본과 Pwh의 차이

Pwh는 [rhwp](https://github.com/edwardkim/rhwp)와 rhwp Studio를 기반으로 합니다. 이 문서는 원본을 대체하거나 원 제작자의 기여를 줄여 설명하기 위한 것이 아니라, Pwh에서 유지하는 변경과 추가 기능을 추적하기 위한 안내입니다.

## 비교 기준

- **기준 원본:** rhwp 0.8.7, 커밋 [`1a76570e833917d15817415a53c09ad61ab3203f`](https://github.com/edwardkim/rhwp/commit/1a76570e833917d15817415a53c09ad61ab3203f).
- **공통 코어:** 이 버전 소스는 `rhwp-0.8.7-pwh-r22`의 누적 75개 패치와 공통 Studio 편집기 보완을 포함합니다. 이전 r18 이하의 검증 기록은 보존합니다. 배포 런타임의 Windows x64 자산과 확정된 해시는 [runtime-lock.json](../runtime-lock.json)에 기록합니다.
- **비교 범위:** 위 고정 버전 대비 Pwh에서 보존한 코어 패치와 Studio 빌드 변경, 그리고 별도의 pwh 연결 기능입니다. 현재 최신 rhwp와의 비교는 아닙니다.
- **배포 방식:** 고정 소스와 패치·빌드 입력을 보존해 재빌드하는 방식입니다. 전체 upstream 저장소의 Git 포크나 모든 원본 파일을 그대로 포함한 저장소라는 뜻은 아닙니다.
- **반영 상태:** 아래는 pwh 쪽 변경입니다. rhwp 원본에 병합되었다고 주장하지 않습니다.

## 1. rhwp 조판 코어 변경

<a id="viewport-table-cell-selection"></a>
### 셀 크기 변경과 선택 표시 최적화

r22는 rhwp 원천 코어 위에 표의 행·열·병합 구조를 그리기 없이 읽는 조회와 지정 쪽의 셀 좌표만 읽는 조회를 추가합니다. rhwp Studio에서 유래한 Pwh 공통 편집기는 F5 상태의 키보드 크기 조절에 표 구조를 쓰고, 선택 표시와 스크롤에는 화면에 보이는 쪽의 좌표를 씁니다. 크기 변경 후 조판과 실행 취소는 기존 흐름을 사용합니다. 이 변경은 Pwh와 Pwh Desktop이 공유합니다. [패치 기록](engine-patches/README.md#viewport-table-cell-selection)

같은 긴 표 시험 사본을 Pwh Desktop의 로컬 시험 호스트와 Chrome에서 열고, F5 선택 후 Ctrl+방향키 입력부터 두 번째 화면 프레임까지 측정했습니다. 같은 위치에서 높이·너비 조절을 각 네 번 시험한 중앙값은 높이 3.80초 → 1.25초, 너비 3.56초 → 1.02초입니다. 개선 후에는 코어의 쪽 나눔 재계산이 가장 긴 단계입니다. 별도 WASM 계측에서는 깊이 1 셀의 지연 조판 입력이 1~8ms였고, 중첩 셀 입력은 즉시 쪽 나눔을 갱신하며 0.93~1.08초가 걸렸습니다. 이 패치는 중첩 셀의 입력 조판을 변경하지 않습니다.

추가 CPU 샘플링에서 크기 변경과 중첩 셀 입력의 약 99%가 쪽 나눔 경로에 있었고, 글줄 재조합은 전체 표본의 70~74%를 포함했습니다. 글꼴 이름을 소문자로 변환하는 연산 자체가 18~20%를 차지했습니다. 하위 호출을 포함한 수치라 합산하지 않습니다. 셀 편집 조판은 편집 스레드에서 동기로 실행됩니다.

<a id="prepare-font-measurement-per-run"></a>
### 글줄 안에서 글꼴 판별 재사용

r22 공통 코어에서 글꼴 이름을 글자마다 파싱하고 소문자로 바꾸던 연산을 글줄 단위로 줄였습니다. 같은 최적화 시험 프로필에서 각 8회 코어 작업의 중앙값은 높이 817 → 650ms, 너비 708 → 689ms, 중첩 셀 입력 876 → 699ms였습니다. 두 익명 시험 문서의 네 출력 상태에서 총 215쪽을 비교했고 쪽 수, 화면 SVG, 글자 좌표 JSON 해시가 모두 같았습니다. 해당 수치는 WASM 코어 작업이며, 화면 반응 시간은 위의 브라우저 측정과 별도입니다. [패치 기록](engine-patches/README.md#prepare-font-measurement-per-run)

<a id="reuse-font-metric-decisions-per-run"></a>
### 글꼴 폭 표 조회 재사용

같은 서식의 문자열에서 글꼴 이름, 별칭, 굵기와 기울임에 맞는 내장 폭 표를 한 번 조회하고 줄바꿈·글자 위치 계산에 재사용합니다. 표가 없는 경우의 기존 대체 폭과 영문 구두점 슬롯도 유지합니다. 같은 시험 사본에서 워밍업을 제외한 7회 작업의 코어 중앙값은 높이 613 → 589ms, 너비 657 → 574ms, 중첩 셀 입력 670 → 618ms였습니다. 두 시험 문서의 열기와 편집 결과를 합쳐 227쪽의 화면 SVG와 글자 좌표 JSON이 동일했습니다. [패치 기록](engine-patches/README.md#reuse-font-metric-decisions-per-run)

<a id="nested-text-capacity-continuation"></a>
### 중첩 표 편집 뒤 남은 본문 영역

쪽의 가용 높이로 이미 나뉜 표가 다음 쪽에서 안쪽 행의 중간부터 이어질 때, 예전 저장 좌표의 평문 경계가 남아 있어도 기존의 본문 중간 여유 판정을 통과하고 다음 줄이 실제로 들어가면 같은 쪽에 배치합니다. 명시적 쪽·단 나눔과 독립된 물리 프레임은 보존합니다. 높이 조절과 Enter가 같은 코어 경로를 사용하며, 현재 쪽의 여백과 반복 제목 줄을 반영한 높이를 적용합니다. [패치 범위와 합성 시험](engine-patches/README.md#nested-text-capacity-continuation)

편집하지 않은 세 익명 시험 문서 150쪽을 직전 코어와 대조해 화면 SVG와 글자 좌표가 모두 일치했습니다. 실제 키 입력으로 확인한 표 편집에서는 Enter 뒤 문제 쪽의 글줄 수가 1 → 36, 셀 높이 조절 뒤 4 → 38이었습니다. 명시적 쪽·단 나눔, 셀 단위 나눔, HWPX 저장·재열기도 검사했습니다.

<a id="rebuild-cell-flow-after-width-change"></a>
### 셀 폭 변경과 후속 문단

셀 폭이 바뀌면 공통 코어는 새 폭으로 줄을 나눈 뒤 각 문단의 줄 높이와 간격을 합쳐 다음 문단의 시작 위치를 계산합니다. 이전 폭의 쪽 분할 좌표는 폭이 달라진 셀에서 갱신합니다. 최외곽·중첩 표에 공통 적용되며, W 단축키와 기존 크기 조절이 같은 코어 경로를 사용합니다. [패치 기록](engine-patches/README.md#rebuild-cell-flow-after-width-change)

### 70번 패치의 표 원점과 문단 후속 줄

rhwp 기반 Pwh 공통 코어에서 저장된 표 외곽 상자와 실제 테두리 위치를 구분하고, 같은 문단의 여러 표가 서로 다른 쪽을 소유하는 경우 뒤 본문 줄을 원래 쪽에 배치합니다. 원본 제어 문자 위치와 저장 줄이 두 배치를 확인합니다. [적용 범위와 검증](engine-patches/README.md#hwpx-owned-table-insets-and-reset-suffix)

### 65~69번 패치

Pwh의 공통 코어는 원본 HWPX의 단 기준 왼쪽 정렬과 앞뒤 저장 글줄로 확인한 표의 원점을 반영합니다. 마지막 행의 내용이 모두 들어간 경우에도 원본이 입증한 물리 높이를 쪽 나눔과 테두리에 함께 적용합니다. 인쇄에 사용할 글꼴 선택은 별도 코어 사본으로 전달합니다. 선택 화면은 Pwh Desktop에 있고, 글꼴 선언 확인·조판·SVG 출력은 공통 코어가 처리합니다. [코어 패치 기록](engine-patches/README.md#hwpx-nested-column-left-anchor)

### 64번 패치의 마지막 행 분할 높이

rhwp 기반 Pwh 공통 코어에서 다음 저장 문단이 종료 조각의 높이와 바깥 여백을 함께 입증하면, 같은 원본 선언으로 첫 조각의 높이를 결정합니다. 기존 내용 컷을 보존하면서 예약, 셀 정렬, 테두리에 그 프레임을 사용합니다. [적용 범위와 검증](engine-patches/README.md#hwpx-paired-rowbreak-opening-frame)

### 63번 패치의 문단 기준 오른쪽 정렬 표

rhwp 기반 Pwh 공통 코어에서 표의 오른쪽 바깥 상자를 문단 오른쪽 기준점과 부호 있는 오프셋에 맞춥니다. 표가 문단보다 넓을 때도 그 폭을 그대로 계산합니다. 빈 호스트의 저장 위치가 앞 글줄 전진량과 일치하고 다음 문단이 새 쪽에서 시작하면, 단 기준 표가 이미 쓰던 원본 프레임 판정을 문단 기준 표에도 사용합니다. [적용 범위와 검증](engine-patches/README.md#hwpx-paragraph-right-float-frame)

### 62번 패치의 인쇄 글자 추출

rhwp 기반 Pwh 공통 SVG 렌더러의 인쇄 프로필에서 일반 글줄의 합성 굵기 획을 그래픽으로 분리합니다. Chromium이 채움과 획을 각각 텍스트로 저장하는 경우에도 PDF에서 본문을 한 번만 추출할 수 있습니다. 화면 글자 굵기와 조판 좌표는 기존 계산을 따릅니다. [적용 범위와 검증](engine-patches/README.md#print-faux-bold-text)

### 61번 패치의 쪽 끝 인라인 표

rhwp 기반 Pwh 공통 코어가 앞 표의 저장 글줄 시작점에 높이와 줄 간격을 더해 다음 표의 원점을 확인합니다. 현재 표의 본체와 바깥 여백이 전용 글줄의 높이와 같고 다음 문단이 새 쪽에서 시작할 때 이 원점을 씁니다. 측정한 행 높이의 합도 선언과 맞으면 이미 검증한 물리 단위 환산을 같은 표의 행 높이에 적용합니다. [적용 범위](engine-patches/README.md#hwpx-terminal-inline-frame)

### 60번 패치의 원본 앵커와 목차 정렬

rhwp 기반 Pwh 공통 코어가 원래 글줄의 높이와 다음 문단 시작이 일치하는 인라인 표를 저장 좌표에 놓습니다. 글상자 안쪽의 명시적 오른쪽 탭은 저장된 폭을 기준으로 가운데 정렬합니다. 쪽 끝 떠 있는 표는 앞 글줄과의 연속성 및 실제 가용 공간을 검증한 경우 저장 앵커를 사용합니다. [적용 범위](engine-patches/README.md#hwpx-source-inline-tab-and-float-anchors)

### 59번 패치의 재개 표 여백

rhwp 기반 Pwh 공통 코어가 앞 조각에서 끝난 셀과 뒤 조각에서 처음 시작하는 떠 있는 표를 원본 커서로 구분합니다. 재개된 상위 표의 바깥 위 여백을 높이와 배치에 공유합니다. 안쪽 표의 위 여백은 이미 확보한 행 높이 안에서 적용합니다. [적용 범위](engine-patches/README.md#hwpx-resumed-peer-frame-margins)

### 58번 패치의 중첩 표 마지막 조각

중첩 표의 저장 높이가 앞선 완전한 행들과 현재 쪽에 보이는 셀 높이의 합으로 확인되면, rhwp 기반 Pwh 공통 코어가 그 경계에 맞춰 내용과 테두리를 배치합니다. 같은 행의 떠 있는 표는 자기 원본 커서부터 다음 조각을 시작합니다. [적용 범위](engine-patches/README.md#hwpx-terminal-peer-leaf-frame)

### 57번 패치의 여러 셀과 같은 쪽 경계

같은 행의 여러 셀이 각자의 원본 글줄로 쪽 경계를 확인하면 rhwp 기반 Pwh 공통 코어가 각 셀의 줄을 같은 조각에 배치합니다. 두 셀이 독립적으로 재시작을 기록했을 때에는 한 줄뿐인 조각도 인식합니다. [적용 범위](engine-patches/README.md#hwpx-parallel-declared-source-frames)

### 56번 패치의 떠 있는 표와 온전한 행

rhwp 기반 Pwh 공통 코어는 글줄·앵커·표 높이가 원본 좌표에서 완결되고 실제 내용이 현재 쪽에 들어가면 그 행의 내용 소비를 끝냅니다. 마지막 글줄의 좌표와 세로 정렬은 현재 쪽에 실제로 배치한 행 상자를 사용합니다. [적용 범위](engine-patches/README.md#hwpx-complete-float-row-frame)

### 55번 패치의 연속 표 높이 기준

rhwp 기반 Pwh 공통 코어에서 원본 앵커와 글줄로 확인한 연속 표는 완전한 중간 행과 분할 행의 남은 높이를 공통 좌표계에서 계산합니다. 다음 조각의 인라인 표가 전용 저장 줄로 더 큰 공간을 입증하면 그 높이를 보존합니다. [적용 범위](engine-patches/README.md#hwpx-source-frame-height-reconciliation)

### 54번 패치의 인라인 표 전용 줄

인라인 표가 전용 줄의 저장 높이를 소유하고 다음 글줄까지의 전진량도 일치하면, rhwp 기반 Pwh 공통 코어가 표를 포함한 앞 조각의 행 높이와 뒤 조각의 남은 높이를 계산합니다. [적용 범위](engine-patches/README.md#hwpx-inline-declared-row-frame)

### 53번 패치의 여러 쪽에 걸친 저장 행 높이

rhwp 기반 Pwh 공통 코어에서 셀이 같은 행 높이를 저장하고, 이어지는 셀의 원래 글줄·개체 위치가 각 쪽 경계를 입증하면 행 높이를 조각별로 나눕니다. 분할 계산과 그리기는 같은 조각 높이를 쓰며 가운데·아래 정렬에 해당 조각의 글줄 높이를 적용합니다. [적용 범위](engine-patches/README.md#hwpx-declared-row-fragment-balance)

### 51·52번 패치의 원본 행 분할과 후속 표 앵커

### 이전 r13에서 유지한 보완

r13은 분할 계산과 화면 배치가 같은 표·본문 순서를 사용하도록 보완합니다. `CELL` 분할은 저장된 쪽 재시작이 없어도 남은 공간을 사용할 수 있으며, 실제 저장 쪽 경계를 강제하는 판정은 별도로 유지합니다. 여러 저장 프레임을 가진 행의 선언 높이에 포함된 빈 공간을 내용으로 다시 더하지 않고, 글줄 없는 조각에서도 선택된 자식 표 행을 표시합니다. 컨트롤 위치의 문자 인덱스와 UTF-16 저장 위치도 구분합니다.

r12는 빈 호스트에 담긴 중첩 표에서도 저장된 행의 자식별 분할 커서를 전달하고, 한 줄에 온전히 저장된 인라인 표의 개체 줄을 보존합니다. 선언 높이를 줄이거나 표시 영역을 넓혀 잘림을 숨기는 방식은 사용하지 않습니다. Pwh 0.6.40과 Desktop 0.1.21에 같은 코어로 적용하며, 앞선 r11의 원점·빈 호스트 점유 보완도 유지합니다.

r11은 r9·r10에서 유지한 열 패치에 쪽 시작 원점과 중첩 표 호스트 점유 패치를 추가한 **편집기 WASM 코어**입니다. Pwh 0.6.39와 Desktop 0.1.20은 같은 새 코어를 사용합니다. r10과 Pwh 0.6.38의 빌드·타입 검사 보완은 그대로 유지합니다.

| 중첩 표의 페이지 소유와 높이 | 자식 표의 원문 분할 범위와 실제 부분 행 높이·셀 여백을 부모의 조판 예약에 전달합니다. 글만 소유한 조각이 표를 중복해서 그리지 않게 합니다. | 명시된 자식 행·셀 분할 원장을 가진 중첩 표 조판 |

| 편집으로 커진 표의 쪽 나눔 | 저장된 글자처럼 취급한 표의 글이 늘어나면 실제로 측정한 높이를 쪽 나눔에도 반영합니다. | 저장된 크기보다 내용이 커진 조건에 맞는 단순 텍스트 행 |
| 글자처럼 취급한 표 뒤 간격 | 특정 문단의 줄 간격 설정에서 표 뒤 문단이 지나치게 가까워지는 경우를 보완합니다. | 저장된 줄 배치가 없는 단일 인라인 표와 해당 줄 간격 조건 |
| 떠 있는 표 다음 본문 흐름 | 저장된 줄 배치가 없는 문단에서 표의 실제 끝을 다음 본문 위치에 반영합니다. | 조건에 맞는 단일 위아래 배치 표 |
| 문단 중간의 떠 있는 표 | 앞뒤 글자와 실제 컨트롤 위치로 표의 호스트 줄을 확인합니다. | 저장 위치가 명확한 문단 내부 표 |
| 저장 표의 후속 문단 원점 | 빈 호스트 표와 다음 문단이 같은 저장 프레임을 닫으면 공통 원점을 전달해 간격을 중복 계산하지 않습니다. | 편집·재조판이 없고 측정 높이·여백·배치 예산이 일치하는 단일 표 |
| 쪽 시작 문단의 앞·뒤 간격 | 첫 줄의 앞 간격과 다음 문단까지의 저장 간격이 일치하면 쪽 원점을 유지해 후속 글·표가 위로 당겨지지 않게 합니다. | 저장 줄과 간격이 검증되는 문단; 명시적 쪽 나눔 포함, 편집·합성·개체 원점은 제외 |
| 첫 표·그림 뒤의 저장 원점 | 문단 항목이 없는 첫 TAC 표도 검증된 앞 간격을 측정·렌더에 전달하고, 첫 호스트 개체 뒤에 같은 원점을 유지합니다. | 단일 저장 표의 전체 바깥 상자가 확인되는 경우; 메모 등 폭 중립 부호 허용 |
| 빈 중첩 표 호스트의 점유 높이 | 빈 호스트 줄과 내부 표가 같은 상자를 소유하면 큰 쪽의 높이로 측정합니다. 분할 원장·렌더와 같은 점유 높이를 씁니다. | 셀 첫 원점에 저장된 단일 빈 문단·단일 위아래 배치 표; 가시 글·추가 문단·편집된 호스트 제외 |
| 내장 기본 글머리표 | BULLET 참조 0의 기본 원형 표시와 본문 서식을 복원합니다. | 기본 참조 0; 명시 참조와 일반 문단은 별도 유지 |
| 도형 투명도와 둥근 모서리 | 채움 투명도 바이트를 보존하고 테두리와 분리하며, 모서리 비율을 짧은 변에 적용합니다. | 편집기 WASM의 도형 파싱·저장·화면/SVG 그리기 |
| 각주·미주의 원문 주소 | 표시·클릭·커서·삭제의 논리 주소를 맞추고, 원본 UTF-16 컨트롤 위치로 글자 서식을 보존합니다. | 본문의 각주·미주 참조 |
| 선언 높이가 있는 중첩 행의 분할 | 자식별 시작·끝 커서를 부모에 전달해 남은 공간을 사용하고, 검증된 저장 프레임 경계는 별도로 유지합니다. | 빈 호스트·혼합 호스트의 단일 위아래 배치 RowBreak 표; 교차 행 병합은 기존 경로, 변경·합성 좌표로 저장 쪽 경계를 증명하지 않음 |
| 혼합 문단의 표·본문 흐름 | 원문 앞뒤 순서를 계산·일반 셀·부분 셀 배치가 공유하고 표 높이·저장 프레임의 빈 공간을 중복 소비하지 않습니다. | 원문 텍스트 경계에 놓인 단일 위아래 배치 표의 명시적 분할 단위; 중간 앵커·다중 컨트롤·겹침 개체는 기존 경로 |
| 인라인 표의 저장 개체 줄 | 한 줄 상자 안에 완전히 들어 있는 표를 하나의 줄로 넘깁니다. | 저장된 단일 빈 호스트의 단일 TAC 표; 캡션·불완전 상자·편집된 줄은 기존 경로 |

표 관련 패치는 문서의 원문 텍스트나 저장된 셀 높이를 일괄 변경하는 방식이 아니라 조판 계산에 적용됩니다. 주석 패치는 표시용 문자열과 본문·컨트롤 주소를 구분합니다. 조건과 회귀시험, 실제 패치 파일 및 재빌드 방법은 [엔진 패치 상세](engine-patches/README.md)에 있습니다.

**적용 경로를 구분해야 합니다.** r3 이후 코어 보완은 편집기용 WASM을 다시 빌드합니다. 보존된 네이티브 CLI와 별도 Studio에 묶인 WASM은 이 코어 패치로 교체하지 않았습니다. 따라서 모든 PNG/PDF 출력이나 별도 Studio에도 동일한 수정이 적용됐다고 보장하지 않습니다. [런타임 보존 및 재빌드](engine-preservation.md)

### 중첩 표의 페이지 소유 정보 보존

배포 코어는 본문과 여러 행의 표가 같은 문단에 있는 경우, 자식 표의 행·셀 분할 범위를 실제 조판과 렌더링에 전달하는 코어 패치를 적용합니다. 앞 페이지에서 소진된 라벨 셀을 제외하고 이어지는 원문 문단의 소유 범위를 확인하며, 글만 소유한 조각이 같은 표를 다시 그리지 않게 합니다. 원문이나 저장된 셀 크기를 바꿔 화면을 맞추는 방식은 아닙니다.

HWP·HWPX의 중첩 표 사례, 합성 문서의 가시성·저장·실행 취소와 원래 셀 주소를 검증했습니다. 이 변경은 r4에서 반영되어 현재 보존 런타임에도 포함되며, Pwh와 Pwh Desktop이 같은 편집기 엔진으로 사용합니다. 적용 조건과 소스 해시는 [엔진 패치 상세](engine-patches/README.md)에 있습니다.

65쪽 기준 출력의 전후 결과와 남은 차이는 [조판 일치 검증](LAYOUT-FIDELITY.md)에 정리했습니다. 새 Canvas 속성을 사용하는 JavaScript 연결부도 코어와 같은 빌드로 검증하며 공통·Desktop 편집기에 함께 반영합니다.

**남아 있는 중첩 표 분할 제한:** 2026-11-02의 추가 HWPX 검증에서 한컴 39쪽과 달리 공식 npm rhwp 0.8.7 및 Pwh r11이 모두 43쪽을 계산했습니다. 진단 문구의 페이지 아래 배치와 다음 쪽 이월 누락도 두 코어의 SVG에서 동일하게 재현됩니다. 따라서 해당 페이지 수 차이와 잘림은 Desktop 인쇄나 r11에서 새로 생긴 회귀로 볼 수 없습니다. 빈 문단에 담긴 중첩 표에서 일반 글·내부 표가 섞인 행을 자식별 분할 유닛으로 투영하지 못하는 원천 코어의 조건을 확인했습니다. 기존 보완이 모든 중첩 표를 해결했다고 볼 수 없습니다. 정적 코드 진단, 원문 보존과 출력 누락의 차이, 미검증 범위는 [긴 중첩 표 검증](LAYOUT-FIDELITY.md#긴-중첩-표-hwpx의-추가-검증)에 구분했습니다. 이번에는 새 엔진 패치를 적용하지 않았습니다.

## 2. rhwp Studio 편집기 변경

### 한글 호환 단축키의 편집 상태 구분

Pwh 0.6.49와 Desktop 0.1.30은 공통 편집기에서 본문, 셀 입력, F5 셀 블록을 구분합니다. 셀 블록의 고정 크기 조절은 문서 모델의 행·열과 병합 범위에서 경계 양쪽의 치수 변경을 계산한 뒤 r22의 표 변경 API로 함께 적용합니다. 줄 지우기와 행 지우기는 기존 선택 삭제와 표 변경의 실행 취소 경로를 사용합니다. [한글 호환 단축키](USER-GUIDE.md#한글-호환-단축키) · [Studio 빌드 패치](../scripts/patch-hancom-key-contexts.mjs)

Pwh의 내장 편집기는 rhwp Studio를 바탕으로 빌드하며, 원본 Studio 입력에 보존된 변경과 Pwh 빌드 단계의 추가 변경을 적용합니다. 대표적인 차이는 다음과 같습니다.

| 영역 | Pwh에서 적용한 변경 |
| --- | --- |
| 대형 문서 입력 | 글자 수정마다 모든 쪽의 렌더 트리를 만들던 글꼴 준비를 문서의 글꼴 메타데이터 조회로 대체합니다. 기존 글꼴 해석기와 로딩 경로를 유지합니다. |
| 단순 셀 입력 실행 취소 | 일반적인 한 단계 셀의 평문 삽입을 되돌릴 때, 코어의 삭제 역연산이 전체 쪽 나눔을 완료하므로 직전 지연 미리보기 작업은 취소하고 중복 선행 조판을 생략합니다. 깊은 중첩·본문·캡션·치환·조각 복원·예약 서식·줄바꿈·탭은 기존 완료 경계를 유지합니다. |
| 키 이동 뒤 커서 위치 | rhwp Studio에서 이어받은 이전 hit 좌표를 해당 논리 위치에만 사용하고, 이동·기하 무효화 뒤에는 폐기합니다. 깊은 셀 Home/End는 안쪽 셀을 식별하지 못하는 평면 줄 API 대신 전체 셀 경로의 코어 기하를 사용합니다. 기존 논리 끝점은 유지하며 두 제품에 함께 적용합니다. [조건과 검증](engine-patches/CARET-AND-CONTINUATION.md#studio-pointer-hit-geometry) |
| 글자 모양 창 | 원본 Studio의 선택 필수 조건을 보완해 커서만 둔 경우에도 창을 열고 다음 입력 서식을 지정합니다. |
| 개체 속성 명령 | 원본 Studio의 상단 버튼 경로에서 빠졌던 표 개체 주소와 그림의 셀·머리말·꼬리말 참조를 보존합니다. 셀 안에서도 표 속성을 열며, 지원하지 않는 중첩 표를 바깥 표로 바꿔 열지 않습니다. [대상 보존과 검증](OBJECT-PROPERTIES.md) |
| 본문·주석 커서 연결 | 코어의 인라인 컨트롤을 포함한 위치와 Studio의 본문 글자 위치를 구분합니다. 주석 앞뒤의 방향을 보존하고 본문 입력·선택·서식에는 본문 오프셋을 전달합니다. |
| 선택 표시와 반응성 | 본문 선택 표시를 실제 조판 결과에 맞춰 보정하고, 선택 동작 중 계산을 재사용하도록 개선합니다. 단어·문단 선택의 실제 양 끝 쪽 정보를 전달해 표 선택이 문서 전체를 조사하지 않도록 합니다. |
| 설치 글꼴 | 시스템·사용자 글꼴을 편집기 목록과 렌더링에 연결하고, 확인된 로컬 글꼴을 우선 사용합니다. |
| 표와 클립보드 | 선택 셀 복사, 한글 문서 모델 및 Windows 클립보드 보조 경로, 셀 안의 표 붙여넣기와 넘친 표의 잘림 표시를 연결합니다. 셀 삭제 시 선택 범위에 따라 내용 또는 줄·칸 삭제를 선택할 수 있습니다. |
| 표 서식과 사용성 | 셀 속성·테두리 단축키와 우클릭 메뉴, 안쪽·바깥쪽 선 미리보기, 선 모양 표시, 공통 색상표와 최근 색상을 추가합니다. |
| 그림 표시 | 호스트의 이미지 보안 정책에 맞춰 내장 이미지와 클립보드 이미지의 표시 경로를 보완합니다. |
| 내장 화면과 협업 | Codex 패널에 맞춘 편집기 초기화, 문서 상태·선택 연결, AI 수정 요청 메뉴 및 상태 확인을 추가합니다. |
| 인쇄 미리보기와 편집 용지 | 화면 전용 확대·축소·맞춤과 준비된 쪽의 순차 표시, 용지 그림 주변의 여백 입력과 위치 강조를 추가합니다. 실제 인쇄 크기와 기존 용지 설정·실행 취소 경로를 유지합니다. |

중첩 표의 내부 복사·붙여넣기에는 rhwp가 원래 제공하는 엔진 기능을 사용하고, Pwh가 외부 표 가져오기와 선택 메뉴를 연결합니다. Studio에서 원래 제공한 기능 전체를 Pwh가 새로 만들었다는 뜻은 아닙니다. 실제 변경 지점은 [편집기 빌드 스크립트](../scripts/build-inline.mjs)와 관련 [소스](../src/)에서 확인할 수 있습니다. 성능과 이미지 표시의 검증 범위는 [선택·글꼴 성능](EDITOR-PERFORMANCE.md#editor-performance-history), [내장 그림 표시](ARCHITECTURE.md#embedded-image-history)에 기록합니다.

글꼴 준비·글자 모양 창은 rhwp Studio에서 이어받은 경로를 Pwh에서 보완한 것입니다. 단어·문단 다중 클릭의 쪽 정보 누락은 Pwh가 추가한 선택 연결의 문제였습니다. 상세 검증과 남은 성능 한계는 [편집기 성능 검증](EDITOR-PERFORMANCE.md)을 참고하세요.

## 3. Pwh가 별도로 제공하는 기능

다음은 rhwp 코어 패치와 구분되는 Pwh의 기능입니다.

- Codex와 AI 요청을 연결하는 스킬·MCP 도구 및 동일 문서에서의 선택 영역 수정
- 본문·셀·중첩 셀의 원문 검색과 텍스트 부분 수정, 혼합 서식·주변 개체 보존
- 요청 대상의 상태 확인, 충돌 방지, 변경 결과 확인과 실행 취소 연계
- 기존 표 셀 채우기, 구조화된 표 삽입, 병합 제목 행과 셀별 테두리 적용, 표 서식 적용 및 그림 교체
- HWPX 양식 분석·부분 수정, 새 수정본 저장, 런타임 설치와 검증

기능별 지원 범위는 [README](../README.md)와 [pwh 스킬](../skills/pwh/SKILL.md)을 참고하세요.

## 변경을 직접 확인하고 재현하기

- 코어 패치와 입력·출력 해시, 테스트: [엔진 패치 상세](engine-patches/README.md)
- 고정 원본, Studio 패치·빌드 입력, 라이선스와 보존 자산: [런타임 보존 안내](engine-preservation.md), [runtime-lock.json](../runtime-lock.json)
- 현재 내장 편집기에서 추가 적용하는 변경: [build-inline.mjs](../scripts/build-inline.mjs), [pwh 소스](../src/)
- 버전별 pwh 사용자 기능: [변경 이력](CHANGELOG.md)

r1/r2에서 보존한 Studio 차이와 이후 Pwh 편집기 변경이 함께 있으므로, **파일 수나 코드 줄 수 하나로 전체 차이를 표현하지 않습니다.** 정확한 비교에는 해당 릴리스의 보존 입력·패치와 현재 빌드 소스를 함께 봐야 합니다. 검증은 명시된 사례에 한하며, 한컴 한글과 모든 문서의 조판 결과가 같다는 뜻은 아닙니다.
