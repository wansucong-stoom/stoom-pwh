# 한글 출력과의 조판 일치 검증

같은 원본의 HWPX 속성·텍스트·컨트롤 위치와 한글에서 내보낸 PDF를 대조해 공통 조판 규칙을 보완합니다. 특정 문서의 쪽수나 좌표를 고정하거나 원문·셀 크기·글꼴을 바꿔 결과를 맞추지 않습니다. 비교에 사용한 문서와 출력 이미지는 공개 배포물에 포함하지 않습니다.

## r11: 저장 원점과 중첩 표의 점유

발생 계층은 모두 **rhwp 원천 코어**입니다. Pwh·Desktop 화면에서 문서별 좌표를 덧붙이는 방식은 사용하지 않습니다.

| 원인 | 공통 규칙 보완 |
| --- | --- |
| 첫 저장 줄의 앞 간격을 쪽 기준점으로 빼거나, 두 문단 사이 뒤 간격과 다음 앞 간격 0을 판정에서 누락했습니다. | 첫 저장 줄과 다음 줄의 높이·줄 간격·앞뒤 간격이 함께 닫히면 같은 쪽 원점을 유지합니다. 명시적 쪽 나눔도 이 증거를 버리지 않습니다. |
| 문단 항목 없이 표가 단을 시작하면 앞 간격을 처리하지 못했고, 첫 호스트의 개체를 그린 뒤에는 확인한 원점을 다시 지웠습니다. | 전체 바깥 상자가 저장된 단일 TAC 표의 앞 간격을 측정·렌더에 함께 전달하고 첫 호스트의 원점을 유지합니다. 기존 폭 중립 분류로 메모·구역 설정을 구분합니다. |
| 저장된 빈 호스트 줄과 큰 내부 표의 높이를 합산했습니다. 분할 원장·렌더는 이미 같은 점유 상자를 사용해 부모 셀이 남는 공간만큼 늘어났습니다. | 셀 원점의 단일 빈 저장 문단·단일 위아래 배치 표에서 큰 쪽의 점유 높이를 사용합니다. 가시 글·뒤 문단·오프셋·겹침·변경된 호스트에는 이 규칙을 적용하지 않습니다. |

편집·합성 줄·개체가 별도 원점을 소유하는 경우, 다른 쪽의 다음 줄, 일치하지 않는 저장 간격은 기존 경로를 유지합니다. 중첩 표의 저장 셀 크기를 바꿔 맞추지 않습니다. 정식 빌드는 진단용 API를 제거한 고정 원본과 검토 가능한 두 패치에서 생성하며, 기존 열 패치와 합쳐 총 열두 패치를 유지합니다.

Pwh 0.6.38 / r10과 새 Pwh 0.6.39 / r11을 같은 PC의 실제 Desktop 인쇄 경로로 출력했습니다. 두 PDF와 한컴 기준 PDF를 PDFium 150 dpi로 비교했으며 이동·확대·쪽 대응 변경은 하지 않았습니다.

| 항목 | r10 | r11 | 변화 |
| --- | ---: | ---: | ---: |
| 전체 쪽 수 | 65 | 65 | 기준 65쪽 유지 |
| 전체 잉크 겹침 F1, 임계값 245 | 95.4732% | 97.4468% | +1.9736%p |
| 진한 글자·선 F1, 임계값 180 | 93.3195% | 95.6349% | +2.3154%p |
| 39쪽 F1 | 55.2077% | 99.7186% | +44.5109%p |
| 41쪽 F1 | 78.4339% | 99.4584% | +21.0245%p |
| 43쪽 F1 | 71.0985% | 73.4308% | +2.3323%p |
| 44쪽 F1 | 96.9619% | 98.5541% | +1.5922%p |
| 64쪽 F1 | 99.8170% | 99.9819% | +0.1649%p |
| 65쪽 F1 | 70.2625% | 99.9854% | +29.7229%p |

나머지 59쪽의 비교 점수는 바뀌지 않았고 악화된 쪽은 없습니다. 위치 오차 허용은 2픽셀입니다. F1은 원문 정확도나 모든 문서의 호환성을 보증하지 않습니다. **43쪽은 첫 제목 표를 개선했으나 후속 표의 시작 위치 등은 여전히 다릅니다.** 목차 리더, 일부 글꼴·문단 간격도 남아 있습니다.

공개 합성 회귀 28건은 tests/stored-page-margin.test.mjs와 tests/stored-nested-block-host.test.mjs에 있습니다. HWP·HWPX 저장 후 재열기, 원래 셀 크기 보존, 중첩 표가 쪽 경계에 가까운 경우의 분할 원장과 실제 글 표시, 가시 글·추가 빈 문단의 반례를 검사합니다. 최종 코어 검사 268건(51건 환경별 제외)과 전체 브라우저 검사 305건(14건 환경별 제외)이 각각 통과했습니다. 다른 세 문서도 43·4·2쪽과 원문·내보내기 텍스트를 유지했습니다.

기관 원문·기준 PDF·출력 이미지·로컬 경로는 공개 자산에 포함하지 않습니다. Pwh와 Desktop의 공통 WASM에 적용하며 네이티브 CLI와 과거 전체 Studio의 보존 바이너리는 별도입니다.

## r11 추가 문서 검증

같은 65쪽 문서에만 맞춰진 보완인지 확인하기 위해, 기존에 사용자가 제공한 다른 HWP 양식 두 개를 Pwh 0.6.39 / Desktop 0.1.20의 실제 인쇄 경로로 출력했습니다. 새 엔진 패치는 적용하지 않았습니다.

| 추가 검증 문서 | 한컴 / Pwh 쪽 수 | 잉크 겹침 F1 | 진한 글자·선 F1 |
| --- | ---: | ---: | ---: |
| 표·일정·심사기준을 포함한 HWP | 4 / 4 | 98.9683% | 97.8532% |
| 결재 필드·그림·예산표를 포함한 HWP | 2 / 2 | 99.9787% | 100.0000% |

조건은 앞선 검증과 같은 PDFium 150 dpi, 명도 임계값 245·180, 위치 허용 오차 2픽셀입니다. 모든 쪽을 나란히 검토했으며, 두 원본의 SHA-256과 비교 입력이 그대로인지 확인했습니다. HWPX로 내보낸 뒤 다시 열었을 때 본문·표의 텍스트와 4·2쪽을 유지했고 편집기에서 미저장 변경은 발생하지 않았습니다. 현재 설치된 앱을 수정하거나 실제 프린터에 보내지 않았습니다.

두 번째 한컴 PDF는 쪽 내용이 이미지로 저장돼 있어 PDF 텍스트 개체끼리의 비교는 할 수 없습니다. 이 문서의 높은 F1은 허용 오차 안의 위치·모양 일치이며 글자 데이터나 픽셀이 완전히 같다는 의미가 아닙니다. 허용 오차 없는 전체 잉크 F1은 첫 문서 86.5941%, 두 번째 88.8793%여서 렌더링·안티앨리어싱 등의 차이도 남습니다. 문서마다 기준 출력 형태를 기록하고 성급하게 공통 엔진을 바꾸지 않습니다.

추가 검증 결과는 [개인 정보가 제외된 검증 기록](verification/fidelity-corpus-0.6.39.json)에 있습니다. 원본·기준 PDF·출력 PDF·이미지·로컬 경로는 포함하지 않습니다. 43쪽 중첩 표 문서는 현재 Pwh의 PDF 출력과 원문 보존까지만 확인했습니다. 이 환경에서 한컴 자동화가 문서 열기에서 대기하고 GUI 활성화도 실패해 기준 PDF 생성을 완료하지 못했으므로, 해당 문서의 조판 일치도는 산정하지 않습니다.

## r9의 공통 규칙 보완

| 발생 계층 | 원인 | 보완 |
| --- | --- | --- |
| rhwp 원천 코어: 표 배치 | 빈 앵커 문단의 별도 배치 경로가 이미 확인한 다음 문단의 저장 원점을 잃어, 간격을 다시 더했습니다. | 저장된 앵커·측정 높이·바깥 여백·다음 문단이 같은 상자를 닫는 경우 기존 공통 프레임을 사용합니다. 편집·재조판·겹침·용지 범위가 맞지 않으면 기존 흐름 경로를 유지합니다. |
| rhwp 원천 코어: 글머리표 | `BULLET`의 참조 0을 표시 없음으로 취급했습니다. | 내장 기본 원형 글머리표와 본문 글자 모양을 사용합니다. 명시된 정의와 잘못된 비영 참조, 일반 문단의 동작은 구분합니다. |
| rhwp 원천 코어: 도형 | HWPX의 채움 투명도 바이트를 0~1로 제한하고 테두리에도 적용했습니다. | 0~255 저장값을 보존하고, 채움의 불투명도와 개체 전체의 불투명도를 구분합니다. 화면 Canvas·SVG·그리기 데이터와 관련 Skia 경로에서 같은 속성을 사용합니다. |
| rhwp 원천 코어: 도형 | 둥근 사각형의 비율을 짧은 변의 절반에 다시 곱했습니다. | 짧은 변에 비율을 적용하고 반지름을 그 변의 절반으로 제한합니다. |

변경은 고정된 rhwp 0.8.7 대비 Pwh가 유지하는 패치입니다. **Pwh 공통 편집기와 Pwh Desktop은 같은 새 WASM과 일치하는 JavaScript 연결부로 함께 빌드합니다.** Desktop 전용 좌표 보정은 없습니다. 네이티브 CLI와 과거 전체 Studio의 보존 바이너리는 별도이며 이 WASM 수정과 같은 결과를 보장하지 않습니다.

## 전후 비교 조건

운영 r8과 수정 r9에서 동일한 원본 사본을 읽고, 같은 PC에서 Pwh의 실제 인쇄 미리보기 경로로 모든 쪽을 PDF로 출력합니다. 기준은 사용자가 한컴 PDF로 출력한 문서입니다. 한컴 기준 PDF와 Pwh 수정 전·후 PDF를 모두 같은 PDFium으로 150 dpi 이미지화합니다. 실제 프린터로 작업을 보내거나 기준 PDF를 다시 출력하지 않습니다. 한글의 정수 포인트 용지 반올림은 가장자리의 작은 흰 띠로만 허용합니다. 쪽을 늘이거나 이동하거나 뒤의 쪽을 앞쪽에 대응시키지 않습니다.

65쪽 기준 문서의 전체 비교에서 기존 66쪽이 65쪽으로 정리됐습니다. 150 dpi, 명도 임계값 245, 위치 오차 2픽셀을 허용한 **잉크 겹침 F1은 33.50%에서 95.47%로 개선**됐습니다. 큰 개선의 주원인은 앞부분에서 생기던 추가 쪽을 없애 뒤의 쪽 대응을 회복한 것입니다. 개별 글자의 형태가 그 비율만큼 향상됐다는 뜻은 아닙니다. 연한 배경 채움의 영향을 줄인 명도 임계값 180 비교도 31.39%에서 93.32%로 개선됐습니다. 화면 Canvas와 기준 PDF를 비교한 33.16% → 95.01%는 보조 진단 결과이며, 최종 비교값은 PDF끼리의 결과입니다.

F1은 흰 여백을 제외한 글자·선·채움 픽셀의 정밀도와 재현율을 합칩니다. 누락·추가 쪽의 픽셀도 분모에 포함합니다. 이 수치는 글꼴, 안티앨리어싱과 허용 오차의 영향을 받으며, 원문 정확도나 모든 문서의 호환성을 보증하지 않습니다. 쪽별 겹침 이미지, 오차가 큰 쪽과 원문 보존 검사를 함께 확인해야 합니다.

## 회귀 검사와 남은 차이

- 합성 저장 프레임의 표 높이·여백·후속 문단 위치, 닫히지 않는 프레임의 폴백, 원문 내보내기·재열기를 검사합니다.
- 기본·명시·잘못된 글머리표 참조를 구분하고 본문 글자 모양 상속을 검사합니다.
- 도형의 투명도 0·1·128·204·255, 둥근 모서리 비율, 저장·재열기와 실제 Canvas/SVG의 채움·테두리 픽셀 및 Canvas 상태 복원을 검사합니다.
- 기존 표 높이·중첩 표·쪽 경계·각주·미주·셀 텍스트 수정·실행 취소 검사도 새 코어에서 다시 실행합니다. 사용자 원본은 자동 편집하지 않습니다.

일부 문단·표의 세로 간격, 목차 리더의 점 크기·굵기, 특수문자와 대체 글꼴에는 차이가 남습니다. 이 차이를 가리거나 임의 픽셀 보정으로 없애지 않습니다. 다른 문서에도 적용할 수 있는 속성 규칙과 반례를 확인한 뒤 보완합니다.

재현 방법은 [비교 도구](RENDER-COMPARISON.md), 패치와 고정 입력은 [엔진 패치 상세](engine-patches/README.md)에 있습니다.
