# 한글 출력과의 조판 일치 검증

같은 원본의 HWPX 속성·텍스트·컨트롤 위치와 한글에서 내보낸 PDF를 대조해 공통 조판 규칙을 보완합니다. 특정 문서의 쪽수나 좌표를 고정하거나 원문·셀 크기·글꼴을 바꿔 결과를 맞추지 않습니다. 비교에 사용한 문서와 출력 이미지는 공개 배포물에 포함하지 않습니다.

## r16: 8쪽의 내용 분할과 물리 프레임

**Pwh 0.6.43 · Desktop 0.1.24 / r16 코어·편집기 검증 기록.** 고정 원본에 22개 패치를 재적용한 공식 코어와 실제 인쇄 PDF를 연결해, 물리 **1~8쪽**의 순차 품질·내용·경계 감사를 통과했습니다. 다음 대상은 **9쪽**입니다. 공식 코어의 전체 회귀는 **468건 중 407건 통과·61건 환경별 제외·실패 0건**이며 구성된 코어·기준선 누락은 없습니다. 전체 브라우저 검사는 474건 중 460건 통과·14건 환경별 제외·실패 0건입니다. 두 검사 집합은 겹칩니다. 설치 파일의 별도 검증은 릴리스의 [DESKTOP-VERIFICATION.json](https://github.com/wansucong-stoom/stoom-pwh/releases/download/v0.6.43/DESKTOP-VERIFICATION.json)을 참조하세요. 조판 감사 통과와 설치판 배포 완료는 구분합니다. [코어·출력·검증 연결 기록](verification/fidelity-weekly-0.6.43.json)

발생 계층은 **Pwh의 공통 rhwp 코어 추가 패치층**입니다. 다음 쪽에 속한 중첩 표 내용을 너무 일찍 소비하던 분할 경계와, 내용 범위를 바로잡으면 물리적 행 공간도 짧아지던 배정을 분리했습니다. 부모 셀의 안 여백과 자식 표의 바깥 여백을 소유자별로 한 번 처리하며, 가운데 정렬은 해당 행의 내용·프레임으로 계산합니다. 원문 값이나 실측 좌표를 고정한 보정은 사용하지 않습니다.

### 고정 조건의 전후 비교

동일 원문에서 한컴 PDF와 실제 Pwh 인쇄 경로의 전체 PDF를 만들었습니다. PDFium **150 dpi**, 명도 임계값 **245·180**, 허용 거리 **2픽셀**, 같은 물리 쪽·원점·크기를 유지합니다. 맞춤 확대·축소, 위치 이동, 쪽 재대응은 적용하지 않습니다.

| 물리 8쪽 | 이전 r15 누적 엔진 | 정식 r16 누적 엔진 | 개선 폭 | 고정 목표 |
| --- | ---: | ---: | ---: | ---: |
| 일반 잉크 F1 | 80.9888% | 97.0159% | +16.0271%p | 95% 이상 |
| 진한 글자·선 F1 | 68.9251% | 92.0944% | +23.1693%p | 90% 이상 |

두 지표와 별도 내용·경계 감사를 통과했습니다. 8쪽의 정규화 문자 **542/542자**를 확인했고 PDF 글머리표 매핑·그리기 순서 차이는 실제 누락·중복과 구분했습니다. 전체 39쪽을 유지하며 기존 승인 **1~7쪽**은 이전 실제 PDF와 픽셀·정규화 텍스트가 같습니다. 배치가 달라진 8~11쪽 전체의 문자 구성을 보존했고, 12~39쪽도 이전 출력과 픽셀·텍스트가 같습니다. 이는 9~39쪽의 한컴 대비 품질 승인과는 다릅니다.

실제 PDF에서 페이지 밖 글자가 없고, 8쪽 렌더 트리의 비어 있지 않은 텍스트 상자 121개에서도 상위 페이지·본문·셀 경계를 0.5px 넘는 사례가 없었습니다. 출력의 내용 잘림도 관찰되지 않았습니다. 상자 검사만으로 잉크 전체의 무결성을 판단하지 않으며, 실제 출력과 함께 감사합니다. 내부·외부 표 아래 경계에는 각각 **약 1.30pt·1.36pt** 차이가 남고 원인은 아직 확정하지 않았습니다. 지표 목표 충족이 한컴과의 1:1 일치를 뜻하지 않습니다.

최종 22개 패치 정식 재빌드와 앞선 19개 패치 감사 단계의 실제 PDF는 **39쪽 전체의 픽셀·정규화 텍스트가 동일**합니다. 8쪽 글자 542개·선 48개·사각형 16개·곡선 271개의 좌표·속성도 직접 비교해 같음을 확인하고, 실제로 인스턴스화한 WASM과 PDF 해시를 연결했습니다. 앞선 내용·잘림 감사는 이 출력 동등성을 근거로 승계하되, 위 F1은 **최종 22개 패치 PDF에서 1~8쪽을 새로 계산**했습니다. 기존 승인 PDF와 1~7쪽의 픽셀·텍스트도 직접 재검증했습니다. 19개 패치 단계의 해시와 결과는 역사적 비교 기준으로 보존하며 최종 배포 코어로 표시하지 않습니다.

별도의 65·4·2쪽 문서도 같은 공식 22개 패치 코어에서 총 71쪽 인쇄 SVG·원문 조사 결과가 19개 패치 단계와 같았고, 저장·재열기 텍스트와 쪽 수를 유지했습니다. 이 코퍼스 검사는 재열기 이후 모든 쪽 SVG까지 비교한 것은 아닙니다. 사용자 원본은 변경하지 않았습니다.

### 편집·저장 이력의 범위

이번 Pwh 후보의 저장 프레임 증명이 메모리의 재조판 이력에 의존하여, 편집 후 저장·재열기에서 오래된 프레임을 다시 승인하는 회귀가 발생했습니다. 이를 rhwp 원본 전체의 결함으로 분류하지 않습니다. 새 HWPX 보조 JSON은 정확한 header·구역 XML 해시와 안정된 구조 경로·문단 지문이 맞을 때만 이력을 복원합니다. 원본 프레임 재사용을 거절하는 정보이며, 표준 XML 속성·실제 공백 메트릭·모든 조판 상태를 복원하는 기능은 아닙니다. 외부 편집기가 보조 이력을 제거하거나 XML을 바꾸면 동일 배치를 보장하지 않습니다.

회귀 시험은 중첩 글 수정, 두 번의 저장·재열기, 입력의 삭제 역연산, 문단 분할·병합, 스냅샷 실행 취소, 셀 벡터 순서 변경, 같은 구역의 독립된 두 표 중 하나만 수정한 경우를 포함합니다. 메타데이터의 버전·해시·경로·중복·깊이·알 수 없는 필드와 외부 XML 변경도 검사합니다. 최종 코어에는 독립 r13 기준의 작은 용지 3건, 높이 측정 재사용과 전체 처리의 대조 8건, 합성 커서 17건, 표 경계 구역 소유권 1건, 셀 입력 역연산 14건도 포함됐습니다. 브라우저 시험과 코어 시험의 집계는 중복될 수 있어 합산하지 않습니다.

정식 누적 엔진에서 연속 승인 구간은 **1~8쪽**이며 **9쪽**부터 같은 기준으로 진행합니다. 전체 39쪽 승인 또는 모든 HWP/HWPX 문서의 호환성 보장을 뜻하지 않습니다. 이전 r15·r14 결과와 당시 검사 집계는 아래에 보존합니다.

## r15: 같은 조판 결과의 검증 보완

Pwh 0.6.42·Desktop 0.1.23의 r15 런타임은 아래 r14와 같은 WASM 코어·연결부·열여덟 패치를 사용합니다. 조판 결과를 바꾸는 추가 Rust 패치는 없습니다. 글꼴 상자와 실제 잉크를 구분하는 자동 검증을 보완하며, 기존 150 dpi·2픽셀과 F1 0.95·0.90 목표를 유지합니다. 원래·대체 글꼴 및 부분·전체 잘림 반례를 구분합니다. [검증 방법](INK-VALIDATION.md)

현재 r15 구성의 전체 코어 검사는 **392건 중 330건 통과·62건 환경별 제외·실패 0건**, 브라우저 검사는 **375건 통과·17건 환경별 제외·실패 0건**입니다. 두 집합에는 겹치는 항목이 있습니다. [같은 코어와 검증을 연결한 기록](verification/fidelity-weekly-0.6.42.json)을 보존합니다.

## r14: 앞쪽 순차 검증과 정식 빌드

r14는 저장된 표·중첩 개체 프레임의 공간 소유, float 앵커, 다음 쪽 원문과 쪽 번호 설정의 시작을 보완합니다. **Pwh 0.6.41 · Desktop 0.1.22**의 공통 엔진으로 빌드합니다. 발생 계층은 **rhwp 기반 공통 조판 코어**입니다. Pwh·Desktop이 공유하는 WASM을 보완하며 Studio의 메뉴나 Desktop 호스트에서 문서별 좌표를 덧붙이지 않습니다. 공개 릴리스 여부와 아래 품질 검증 범위는 구분합니다.

빈 저장 호스트에 놓인 표의 바깥 여백을 프레임으로 처리하고, 나란한 셀이 같은 선언 최소 높이를 공유하면 승인된 각 쪽의 실제 몸통 높이를 기록하여 마지막 조각에 잔여 공간을 보존합니다. 그리기는 쪽 나눔에서 명시한 소유권만 사용합니다. 물리 쪽 원점과 짧은 문단의 로컬 되감김, 편집·합성 좌표를 구분하며 원문·글꼴·여백·셀 크기는 바꾸지 않습니다. 쪽 번호 설정도 원문 컨트롤 순서와 실제 소유 표 조각에서 시작합니다. [공통 규칙·제외 조건](engine-patches/STORED-FRAME-OWNERSHIP.md)

### 고정된 승인 기준

같은 실제 Desktop 인쇄 경로로 만든 후보 PDF와 한컴 기준 PDF를 PDFium 150 dpi, 임계값 245·180, 위치 허용 오차 2픽셀로 비교합니다. **같은 물리 쪽과 척도**를 유지하며 맞춤·이동·쪽 재대응을 하지 않습니다. 일반 잉크 F1 **0.95 이상**, 진한 글자·선 F1 **0.90 이상**을 모두 요구합니다. 내용 누락·중복과 기하의 겹침·넘침은 F1에서 추정하지 않고 별도로 감사합니다.

[`check-layout-gates.mjs`](../scripts/check-layout-gates.mjs)는 비교·감사 입력의 해시와 측정 조건을 확인하고 첫 실패 또는 미감사 쪽에서 승인을 중단합니다. 뒤쪽의 높은 점수로 앞쪽 실패를 상쇄하지 않으며 이미 승인한 앞쪽도 계속 통과해야 합니다.

기존 7쪽은 수치가 높아도 다음 쪽 행의 원문 21글자를 너무 일찍 소비해 승인하지 않았습니다. 열여덟 번째 패치는 이 원문을 실제 다음 쪽으로 돌리고 온전한 셀의 그림 기준점을 보존합니다. 정식 엔진으로 다시 만든 전체 PDF의 7쪽은 일반 F1 **95.7781%**, 진한 잉크 F1 **91.4565%**, 정규화 원문 **445/445자**입니다. 앞 1~6쪽의 실제 150 dpi RGB·텍스트도 유지했습니다. 출력할 때 관측한 WASM 해시를 판정 기록에 결합했으며, 현재 연속 승인 범위는 **앞 1~7쪽**, 다음 검증 대상은 **8쪽**입니다. [소비·배치·편집 조건](engine-patches/STORED-NESTED-TAIL.md)

7쪽의 두 그림은 원래 표의 기준점에 놓이며 모든 상위 클립 안에 들어갑니다. 글자 경계 상자 경고와 실제 잉크 잘림은 구분했습니다. 클립을 해제한 글자 전용 출력과 비교한 잔차는 61픽셀이며 최대 경계 깊이 **1.711픽셀**로 고정 허용 오차 2픽셀 안입니다. 아래 표 경계는 한컴보다 약 **2.525 pt** 짧아 완전한 픽셀 일치는 아닙니다. 이 잔차는 숨기지 않고 기하 감사에 남겼습니다.

소스 함수와 공개 합성 문서로 원본 소유권·본문 용량·편집 후 일반 재조판·실행 취소·SVG 클립을 구분해 검사합니다. 작은 용지와 충돌하는 저장 프레임은 새 규칙의 적용 대상에서 제외하며, 기존 경로에 남아 있는 중첩 표 중간 조각의 중복·누락까지 해결했다고 주장하지 않습니다. 일반 편집 상태의 기준은 실제 배포 r13을 사용하며, 이전 후보의 잘못된 불변 프레임을 정답으로 삼지 않습니다.

### 긴 중첩 표 HWPX의 추가 검증

이번 비교는 **한컴 PDF 39쪽과 Pwh PDF 43쪽**을 같은 물리 쪽 번호로 대조했습니다. 공통 39쪽과 Pwh에만 있는 추가 4쪽을 모두 전체 잉크 계산에 포함했으며, 뒤의 쪽을 앞쪽에 대응시키거나 이동·확대하지 않았습니다. PDFium 150 dpi, 임계값 245·180, 허용 오차 2픽셀 조건을 유지했습니다. 허용 오차 없는 전체 잉크 F1은 **39.9217%**입니다. 이 값은 새 수정의 전후 개선율이 아니라 현재 r11의 추가 문서 기준선입니다.

첫 쪽과 5쪽에도 일부 높이 차이가 있으며, 큰 쪽 흐름 차이는 6쪽부터 확인됐습니다. 한컴은 다음 업무행의 일부를 같은 쪽에 배치하지만 Pwh는 그 행을 다음 쪽으로 넘겨 아래에 빈 공간을 남깁니다. 이런 차이가 누적되므로 낮은 전체 겹침 값을 글자 모양의 차이만으로 해석할 수 없습니다. 일부 중첩 표에서는 실제 출력 누락도 확인했습니다. 한컴 26쪽의 내부 표 일부가 Pwh 28쪽 아래에서 잘린 뒤 29쪽에 이어지지 않습니다.

원본 SHA-256은 검증 전후 동일합니다. 모델의 전체 텍스트 조회와 HWPX 내보내기 후 재열기에서도 텍스트와 Pwh 쪽 수 43쪽이 유지됐습니다. **모델에 텍스트가 보존된 사실과 PDF에 그 내용이 실제로 보이는지는 별도 검사입니다.** 모델 보존 검사를 통과했다고 출력 누락이 없다고 판단하지 않습니다.

공식 npm `@rhwp/core` 0.8.7도 같은 원본을 43쪽으로 계산합니다. 개별 누락도 공식 원본과 Pwh r11 코어의 SVG를 별도로 대조했습니다. 진단한 원문 문구 6개는 두 코어 모두 28쪽에만 배치되고, 뒤쪽 어느 SVG에도 이어지지 않습니다. 해당 문구의 좌표·클립 범위·표시 영역 비율도 일치했습니다. 최소 두 문구는 용지 표시 영역 밖에 완전히 놓여 있어 **원천 코어에도 존재하는 잘림과 이월 누락**이 확인됩니다. 이 판정은 해당 문구의 SVG 대조에 한하며 문서 전체의 좌표가 두 코어에서 같다는 뜻은 아닙니다. 원문과 한컴 PDF에 있는 고유 문구 6개가 Pwh PDF의 추출 텍스트에서 완전한 문자열로 발견되지 않았지만, 그중 앞부분 문구는 코어 SVG에 상당 부분 보이므로 PDF 출력 경로의 추가 잘림·텍스트 추출 차이까지 모두 같은 원인으로 확정하지 않습니다.

### 중첩 행 분할의 정적 진단과 남은 검증

6쪽에서 시작되는 큰 쪽 흐름 차이에 대해서는 rhwp 코어의 중첩 행 분할 원장(`RowCut`) 생성 조건이 유력한 원인입니다. XML의 상세 표와 내부 표는 `pageBreak="CELL"`이며, 조사한 첫 두 업무행에는 행 병합이나 문단의 `keepWithNext`·`keepLines`·명시적 쪽 나눔으로 행 전체를 이월해야 하는 조건이 없습니다. 파서도 `CELL`을 행 내부 분할이 가능한 `RowBreak`로 해석합니다. 이 매핑을 바꾸거나 원문의 셀 높이를 줄여 맞출 근거는 없습니다.

`src/renderer/layout/table_layout.rs`의 중첩 행 투영은 자동 높이, 표 행만으로 구성된 대표 셀, 일정한 혼합 호스트 조건 중 하나를 만족할 때 자식별 분할 커서를 만듭니다. 이번 구조는 선언 높이가 있는 셀 안에 일반 글과 더 안쪽 표가 섞이고, 이를 담는 호스트 문단 자체는 비어 있어 해당 조건에서 제외됩니다. 폴백은 내부 행 전체를 하나의 유닛으로 남깁니다. 따라서 남은 공간에 다음 행의 일부를 배치할 분할 경계가 만들어지지 않는 코드 경로가 원문 구조와 맞습니다. 이 제한은 기존 upstream 코드에도 있으며, [Pwh의 소유권 보완 패치](engine-patches/rhwp-0.8.7-nested-source-ownership.patch)는 그 일부 범위만 확장한 상태입니다.

이 진단은 **XML 속성과 소스 조건을 대조한 정적 근거**입니다. 내부 분할 원장의 동적 추적이나 수정 후 재출력은 아직 하지 않았으며, 이 조건 하나를 보완하면 전체 4쪽 차이나 개별 출력 누락까지 해소된다는 검증도 없습니다. 후속 보완은 원문의 선언 크기·여백·저장 줄 위치와 각 자식의 연속 커서를 함께 보존하는 공통 규칙과 반례로 확인해야 합니다. 이번 추가 검증에서는 엔진과 앱을 수정하지 않았고 사용자 원본도 변경하지 않았습니다.

## 전후 비교 조건

운영 r8과 수정 r9에서 동일한 원본 사본을 읽고, 같은 PC에서 Pwh의 실제 인쇄 미리보기 경로로 모든 쪽을 PDF로 출력합니다. 기준은 사용자가 한컴 PDF로 출력한 문서입니다. 한컴 기준 PDF와 Pwh 수정 전·후 PDF를 모두 같은 PDFium으로 150 dpi 이미지화합니다. 실제 프린터로 작업을 보내거나 기준 PDF를 다시 출력하지 않습니다. 한글의 정수 포인트 용지 반올림은 가장자리의 작은 흰 띠로만 허용합니다. 쪽을 늘이거나 이동하거나 뒤의 쪽을 앞쪽에 대응시키지 않습니다.

65쪽 기준 문서의 전체 비교에서 기존 66쪽이 65쪽으로 정리됐습니다. 150 dpi, 명도 임계값 245, 위치 오차 2픽셀을 허용한 **잉크 겹침 F1은 33.50%에서 95.47%로 개선**됐습니다. 큰 개선의 주원인은 앞부분에서 생기던 추가 쪽을 없애 뒤의 쪽 대응을 회복한 것입니다. 개별 글자의 형태가 그 비율만큼 향상됐다는 뜻은 아닙니다. 연한 배경 채움의 영향을 줄인 명도 임계값 180 비교도 31.39%에서 93.32%로 개선됐습니다. 화면 Canvas와 기준 PDF를 비교한 33.16% → 95.01%는 보조 진단 결과이며, 최종 비교값은 PDF끼리의 결과입니다.

F1은 흰 여백을 제외한 글자·선·채움 픽셀의 정밀도와 재현율을 합칩니다. 누락·추가 쪽의 픽셀도 분모에 포함합니다. 이 수치는 글꼴, 안티앨리어싱과 허용 오차의 영향을 받으며, 원문 정확도나 모든 문서의 호환성을 보증하지 않습니다. 쪽별 겹침 이미지, 오차가 큰 쪽과 원문 보존 검사를 함께 확인해야 합니다.

## 회귀 검사와 남은 차이

- 합성 저장 프레임의 표 높이·여백·후속 문단 위치, 닫히지 않는 프레임의 폴백, 원문 내보내기·재열기를 검사합니다.
- 기본·명시·잘못된 글머리표 참조를 구분하고 본문 글자 모양 상속을 검사합니다.
- 도형의 투명도 0·1·128·204·255, 둥근 모서리 비율, 저장·재열기와 실제 Canvas/SVG의 채움·테두리 픽셀 및 Canvas 상태 복원을 검사합니다.
- 기존 표 높이·중첩 표·쪽 경계·각주·미주·셀 텍스트 수정·실행 취소 검사도 새 코어에서 다시 실행합니다. 사용자 원본은 자동 편집하지 않습니다.

일부 문단·표의 세로 간격, 목차 리더의 점 크기·굵기, 특수문자와 대체 글꼴에는 차이가 남습니다. 이 차이를 가리거나 임의 픽셀 보정으로 없애지 않습니다. 다른 문서에도 적용할 수 있는 속성 규칙과 반례를 확인한 뒤 보완합니다.
