# Pwh 유지보수 안내

[문서 모음](README.md) · [기여 안내](../CONTRIBUTING.md) · [변경 이력](CHANGELOG.md)

Windows, Linux x64, Apple Silicon macOS는 같은 Pwh 공통 편집기와 조판 코어를 사용합니다. 파일 선택, 입력기, 글꼴 조회, 자격 증명 저장, 인쇄와 업데이트는 운영체제별 경로를 거칩니다. 같은 코어에서 통과한 시험과 운영체제의 실제 설치·실행 결과를 각각 기록합니다.

문제를 재현할 때 제품·Desktop·공통 코어의 버전, OS와 배포 경로, 작업 순서, 기대 결과와 실제 결과를 남깁니다. 장치·글꼴·배율·문서 크기는 결과에 영향을 주는 경우 함께 기록합니다. 기관 문서 대신 같은 구조의 합성 파일을 사용합니다. 원문과 출력 사본에 개인정보가 들어 있으면 로컬에서 비교합니다.

손상이나 내용 손실이 발생하면 저장 경로와 원본 보존부터 확인합니다. 편집·조판 오류는 rhwp 원천 코어, Pwh 공통 편집기·연결, Desktop 호스트 중 재현되는 계층에서 고칩니다. 코어 수정은 문서 이름이나 본문 문구에 의존하는 예외를 추가하기 전에 공통 구조와 범위를 확인합니다.

## 플랫폼별 실행 확인

| 환경 | 설치·업데이트 경로 | 해당 OS에서 확인할 항목 |
| --- | --- | --- |
| Windows x64 | Microsoft Store 제품과 별도 MSIX 시험판 | 설치된 앱과 시험판 식별, HWP·HWPX 연결, 파일 대화상자, 한글 입력기, 인쇄, 업데이트 표시·설치 |
| Linux x64 | 같은 GitHub 릴리스의 tar.gz 사용자 설치 | 기존 설치 경로의 전환과 재실행, Linux 파일 대화상자와 입력기, 글꼴·인쇄, 시스템 키 모음, 한글 파일 연결 |
| Apple Silicon macOS | 같은 GitHub 릴리스의 .app ZIP | Finder에서 앱·문서 열기, 한글 입력과 Command 단축키, 파일 선택, 키체인, 인쇄, 새 버전으로의 전환 |

Ubuntu WSL 시험은 그 환경으로, macOS의 자동 시험은 해당 러너와 시험 계정으로 기록합니다. Store 심사·게시, 서명된 설치판의 업그레이드, 실제 계정·프린터와 네이티브 입력기 확인도 각각 결과를 남깁니다.

## 반복해서 실행하는 개발 검사

Desktop 파일의 추가·변경 뒤에는 소스 manifest를 갱신하고 읽기 전용 검사를 실행합니다. 공통 편집기 또는 Desktop 어댑터가 바뀌었으면 먼저 [편집기 재빌드](../CONTRIBUTING.md#편집기-재빌드와-입력-검사)를 수행합니다.

~~~text
node desktop/verify-source.mjs --write
node desktop/verify-source.mjs
node scripts/verify-editor-build.mjs --check-inputs
npm run lint
~~~

런타임을 설치한 자동 시험은 기존 [기여 안내](../CONTRIBUTING.md#개발-환경)에 따라 코어와 편집 화면을 실행합니다. 넓은 회귀 검사 전에 변경 경로의 시험을 실행할 수 있습니다. 실패·건너뜀의 원인을 기록하고, 시험 환경에서 실행한 항목만 통과로 집계합니다. 패키지를 만들면 동봉된 Node와 코어로 모듈 로드, 빈 문서·기존 HWPX 열기, 구역 생성, DOCX 편집·같은 파일 저장·재열기를 검사합니다.

문서 탭 시작이 실패하면 Desktop 데이터 폴더의 `logs/document-startup.log`에 시각과 진단 코드가 남습니다. 설치 모듈 누락이 확인되면 모듈 이름을 함께 기록합니다. 예를 들어 `INVALID_DOCX`는 DOCX 구성을 읽지 못한 경우이며, `ENOENT`는 파일 또는 시작에 필요한 구성 요소가 없는 경우입니다. 지원 요청에는 오류 한 줄과 재현 순서를 전하고 문서 경로나 계정 정보는 제외합니다.

## 릴리스 확인 순서

1. Pwh와 Desktop의 버전, 커밋, 공통 런타임 ID·해시를 확인합니다. Linux·macOS와 Store 배포 작업은 릴리스 태그가 가리키는 커밋을 검사합니다. 아직 공개되지 않은 런타임은 로컬 시험에서 사용한 사본과 해시를 보존하고, 공개 배포의 고정값과 별도로 기록합니다.
2. 같은 태그를 기준으로 OS별 패키지를 확인합니다. 테스트 결과에 실제 실행 환경, 통과·실패·건너뜀, 빌드 채널, 패키지 해시와 서명 상태를 남깁니다. Windows 시험판과 Store 패키지의 식별자를 각각 확인합니다.
3. GitHub 공개, Linux·Mac 자산 첨부, Microsoft Store 제출, Store 게시와 설치판 업데이트 조회를 단계별로 확인합니다. 배포 직전에 문제를 발견하면 제출을 멈추고 직전 정상 버전의 자산과 검증 기록을 보존합니다. 게시 뒤에 발견한 문제는 수정 버전에서 같은 원본과 환경으로 재현·검증하고 기존 사용자 데이터 보존을 확인합니다.

## 다음 확인이 필요한 부분

- **Apple Silicon 실제 실행** — 해당 빌드의 Finder 파일 연결, DOCX 저장 대화상자, 키체인 로그인·연결 해제, 인쇄와 기존 사용자 설정 이전을 확인합니다.
- **장기 사용과 비정상 종료** — 여러 탭이 큰 문서를 편집하는 조건에서 디스크 사용량, 장시간 입력·저장 지연, 중단된 변환 작업 사본의 정리 범위를 측정합니다. 사용자의 미저장 복구본은 정리 과정에서 보존합니다.
