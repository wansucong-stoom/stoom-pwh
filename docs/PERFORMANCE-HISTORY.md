# Pwh 속도 개선 이력

[프로젝트 소개](../README.md) · [현재 편집 성능과 지원 범위](EDITOR-PERFORMANCE.md) · [조판 검증](LAYOUT-FIDELITY.md)

Pwh는 **가장 한글같은 한글, 가장 빠른 한글, 가장 정확한 한글**을 지향합니다. 이 페이지는 그중 편집 속도를 위해 바꾼 처리 방식과 확인한 결과를 초기 버전부터 정리합니다. 입력·선택·실행 취소·저장 결과를 보존하면서 반복 계산과 불필요한 전송을 줄이는 것이 기준입니다.

**기록 기준: 2026-11-16.** 공개 버전은 Pwh 0.6.61 · Desktop 0.1.42 · 공통 코어 r30이며, 마지막 절의 91~96번 코어 패치와 연결 개선을 함께 반영합니다. Store 설치판의 반영 시점은 Store 게시 상태를 따릅니다. 초기 버전은 해당 변경 커밋의 소스 버전이며, 당시 측정값을 현재 설치판의 재측정값으로 사용하지 않습니다.

| 사용자가 하는 일 | 누적 개선 | 상세 |
| --- | --- | --- |
| 문서 열기 | 비동기 WASM 초기화, 글꼴 설치 공유, 정확한 로컬 글꼴 우선 사용 | [초기 로딩·글꼴](#startup-fonts) |
| 상태 확인·AI 버튼 표시 | 표시용 문서 지문 캐시, 조작 중 조회 연기, 해시 없는 탭 상태 조회 | [초기 상태 조회](#presentation-selection), [Desktop 상태](#picture-motion) |
| 글·셀 선택 | 한 제스처의 글줄 계산 공유, 선택 양 끝의 쪽 전달, 보이는 쪽만 셀 좌표 조회 | [초기 선택](#presentation-selection), [큰 표 선택](#selection-font-metadata), [셀 크기 조절](#viewport-font-metrics) |
| 글자 입력·실행 취소 | 전체 쪽의 글꼴 조사 제거, 중복 선행 조판 제거, 바뀐 셀·상위 표만 측정 갱신 | [글꼴 준비](#selection-font-metadata), [실행 취소](#height-undo), [증분 조판](#incremental-layout) |
| 표 크기 조절·커서 이동 | 형제 표·글꼴 폭·셀 글줄·중첩 행 높이 재사용, 뒤쪽 쪽 계획 비교 | [r16](#height-undo), [r22](#viewport-font-metrics), [r23](#incremental-layout) |
| 그림 드래그 | 프레임의 최신 위치 반영, 전체 문서 내보내기 제거, 한 번의 이동 체크포인트 | [그림 이동](#picture-motion) |
| 큰 문서 전송·저장 | 분할 저장, 파일 크기에 따른 청크, 범위 읽기·스트리밍 해시·바이트 변환 개선 | [문서 전송](#large-transfer) |
| 인쇄 미리보기 | 준비된 쪽을 순차 표시하고 화면 처리에 실행 시간 양보 | [일괄 편집·미리보기](#batch-preview) |
| 반복 그림 조회·복구 저장 | 불변 그림 바이트, 같은 리비전의 내보내기, 진행 중 글꼴 전송, 압축 결과 재사용 | [r30 자원 재사용](#candidate-resource-reuse) |

측정은 **내부 코어 호출**, **입력부터 화면 프레임까지**, **전송**, **저장 내보내기**를 구분합니다. 서로 다른 문서·버전·환경의 감소율을 더하거나 곱해 누적 향상률로 계산하지 않습니다. 수치가 없는 항목은 구현된 처리 개선이며 별도 속도 향상률을 주장하지 않습니다.

## 초기 버전: 문서 로딩과 글꼴 전송

| 도입 기준 | 계층 | 바꾼 처리와 유지 조건 |
| --- | --- | --- |
| 0.4.1 | 초기 문서 클라이언트 | 큰 WASM의 동기 초기화를 비동기 초기화로 교체. 초기 클라이언트에서 시작한 변경이며 현재 Studio 전체의 로딩 시간 측정과 구분 |
| 0.5.8 | Pwh 공통 연결 | 편집기마다 시스템 글꼴 공급자를 한 번 준비하고 설치 중인 Promise 공유. 같은 편집기에서 반복 설치 방지 |
| 0.6.11 | Pwh 공통 글꼴 전송 | 512KiB 청크를 최대 4개씩 병행 요청. 완성된 파일은 SHA-256으로 검증하고 같은 TTC 파일의 다른 face에서 바이트 재사용 |
| 0.6.13 | Pwh 공통 글꼴 연결 | 정확한 full/PostScript 이름과 굵기·기울기가 일치하는 로컬 글꼴 우선 사용. 모호한 family 이름으로 대체하지 않으며 실패·미지원은 최대 1초 뒤 검증된 바이트 전송으로 전환 |
| 0.6.13 | Pwh 글꼴 호스트 | 파일 바이트·SHA-256을 최대 64MiB 안에서 보관하고 동시 파일 읽기 공유. 파일 크기·수정 시각과 허용된 목록을 확인해 변경된 글꼴 무효화 |

초기 TTC 재사용은 **완료된 전송 결과**를 공유합니다. Pwh 0.6.61에서는 서로 다른 face가 동시에 요청하는 **진행 중 전송**까지 공유하도록 보완했습니다. 여러 청크를 동시에 요청하는 것은 문서 조판을 여러 스레드에서 실행한다는 뜻이 아닙니다.

당시 13쪽 문서의 실제 편집 화면에서 로컬 글꼴 4개와 바이트 전송 대체 1개를 확인했습니다. 열기 속도의 정량 비교는 남아 있지 않아 개선율로 표시하지 않습니다. 초기 클라이언트와 이전 호스트가 함께 사용된 확인이므로 당시 모든 호스트 개선의 검증으로 확대하지 않습니다.

## 0.6.30~0.6.40: 여러 셀 편집과 미리보기 표시

- **0.6.30 · 여러 셀 속성 적용:** 선택한 셀의 속성 변경을 기존 코어의 `runInBatch` 안에서 묶어 처리합니다. 코어의 일괄 처리 기능을 Pwh 메뉴에 연결한 것으로, 셀마다 별도 완료 경계를 만드는 일을 줄입니다. 이 항목의 별도 시간 비교는 없습니다.
- **0.6.40 · 미리보기 순차 표시:** 이미 생성한 인쇄 SVG를 쪽별로 추가하면서 일정 간격으로 이벤트 루프에 실행 시간을 양보합니다. 첫 쪽부터 확인할 수 있고, 창을 닫으면 남은 표시를 중단합니다. 전체 SVG 생성이 비동기·병렬로 바뀐 것은 아니며 실제 인쇄 준비 완료 조건은 유지합니다.

## 0.6.35 · Desktop 0.1.16: 큰 표 선택과 입력 전 글꼴 준비

rhwp Studio에서 유래한 공통 편집기를 보완했습니다. 단어·문단 선택에는 **선택 양 끝의 실제 쪽 정보**를 전달해 문서 전체의 표를 조사하지 않게 했습니다. 글자 수정 때마다 모든 쪽의 렌더 트리를 만들던 글꼴 준비는 문서의 글꼴 메타데이터 조회로 바꿨습니다. 메타데이터가 불완전하면 기존 경로를 사용하고, 새 글꼴을 놓치지 않도록 수정 후 원본 목록을 다시 확인합니다.

| 43쪽 문서의 같은 셀에서 측정한 동작 | 이전 배포본 | 당시 수정 후보 |
| --- | ---: | ---: |
| 단어 더블클릭과 선택 문맥 확인 | 5,141ms | 15ms |
| 선택 해제 방향키 | 2,708ms | 9ms |
| 한 글자 입력과 상태 확인 | 3,130ms | 246ms |
| 실행 취소와 상태 확인 | 3,515ms | 980ms |

해당 계측에서 셀 선택 사각형 계산 합계는 약 7.8초에서 1ms 미만으로 줄었고, 입력·실행 취소의 글꼴 준비에 사용되던 **페이지 렌더 트리 조회 86회가 제거**됐습니다. 두 버전 모두 43쪽과 첫 쪽의 표시를 유지했습니다. 한 PC·한 위치의 과거 측정이며 전체 문서·현재 버전의 보장 수치가 아닙니다.

## 0.6.43 · Desktop 0.1.24 · r16: 높이 변경과 실행 취소

**공통 코어 22번 패치**는 높이만 바꾸는 독립 명령에서 변경되지 않은 형제 표의 측정값을 한 호출 안에서 재사용합니다. 바뀐 표·하위 표와 전체 쪽 나눔은 갱신하며, 폭 변경·미완료 조판·프로필 변경은 기존 계산으로 돌아갑니다. 표 경계 조회도 필요한 소유 표를 직접 찾도록 줄였습니다.

**공통 편집기**는 한 단계 평문 셀 입력을 취소할 때 삭제 역연산이 조판 완료를 담당하면 앞선 지연 미리보기 조판을 취소해 두 번 계산하지 않게 했습니다. 깊은 중첩·줄바꿈·탭·치환·예약 서식·문단 조각 복원은 이 생략 대상이 아닙니다.

| 실제 Electron 셸의 통제 비교 | 기준 중앙값 | 수정 중앙값 |
| --- | ---: | ---: |
| 셀 높이 변경 1회 | 714.1ms | 299.5ms |
| 높이 변경 키 5회 연속 | 3,321.3ms | 1,393.7ms |
| 일반 셀 글자 입력의 실행 취소 | 922.3ms | 528.3ms |
| 높이 변경의 실행 취소 | 523.0ms | 472.9ms |

39쪽 문서·동일 PC의 새 프로필에서 기준/수정 실행을 번갈아 세 쌍 비교했습니다. 키 입력부터 두 번의 화면 프레임 콜백까지이며 이전 정식 설치판과 직접 비교한 수치는 아닙니다. 글자 입력은 101.6ms와 98.4ms로 변동 범위가 겹쳐 **입력 속도 향상을 주장하지 않았습니다**. 제외된 초기 시도 중 선택 유실 1회의 원인은 미확정이며, 후속 50키에서 재현되지 않은 것과 구분합니다.

앞선 Chrome 후보의 표 경계 내부 조회는 205.9ms → 20.5ms였으나, 위 최종 통제 비교와 다른 바이너리의 기록입니다. [측정 조건·제외 내역](verification/editor-performance-0.6.43.json) · [높이 변경 회귀 시험](../tests/stored-cell-height-scope.test.mjs) · [코어 패치](engine-patches/README.md#r16-interaction-and-fallback)
