# 줄 간격 변경 응답 검증

대상은 Pwh 0.6.64 · Desktop 0.1.45의 공통 편집기입니다. rhwp Studio 유래의 Canvas 측정 준비 경로를 수정하며 공통 코어 r32 WASM은 변경하지 않습니다. Windows와 Linux 패키지는 같은 공통·Desktop 편집기를 포함합니다.

## 원인과 적용 규칙

줄 간격만 바꿔도 Canvas 화면의 변경 리비전마다 문서 전체를 순회해 글자 폭 측정 요청을 다시 수집했습니다. 준비된 목록은 소유 문서·문서 세대·글꼴 세대에 묶어 보관합니다. 줄 간격과 줄 간격 종류만 포함한 명령에서 이를 재사용하며, 다른 필드·알 수 없는 변경·본문과 셀의 글자 변경·스타일 변경·실행 취소·복원은 목록을 무효화합니다. 실제 글꼴 변경과 문서 교체는 측정 세대도 변경합니다.

글자 폭 캐시는 키가 같은 기존 측정을 재사용합니다. 일반 타이핑마다 측정값을 전부 버리지 않습니다. 비동기 작업의 세대 확인과 실패 시 기본 측정 대체는 유지합니다. 쪽 분할·커서·표 높이 계산과 화면 갱신을 생략하거나 문서별 조건을 추가하지 않습니다. 저장·충돌 확인·복구 검증도 유지합니다.

## 지연 측정

각 운영체제의 격리된 실제 Desktop 실행 환경에서 같은 282쪽 문서를 열고 8회 연속 줄 간격을 변경했습니다. 매 변경 뒤 50ms 타이머가 실행될 때까지의 시간을 기록했습니다. 다음 수치는 이 의도적 대기를 포함한 이벤트 처리 중앙값이며 순수 조판 시간이나 화면 표시 완료 시간은 아닙니다. Linux는 Windows 위 WSL2·WSLg 시험 환경입니다. 운영체제 간 우열을 비교하는 자료가 아닙니다.

| 환경 | 기존 중앙값 | 수정 중앙값 | 전체 측정 목록 수집 |
| --- | ---: | ---: | --- |
| Windows | 207.1ms | 68.1ms | 8회·1430.7ms → 0회 |
| Linux | 192.8ms | 62.7ms | 8회·1437.5ms → 0회 |

첫 변경의 캐럿·화면 준비 비용과 편집 문단의 조판 비용은 남습니다. 모든 문서·편집에서 같은 감소율을 보장하지 않습니다. 입력 중 주기적 상태 조회를 미루는 기존 정책을 사용했으며 검증을 끄거나 측정을 강제로 생략하는 시험용 대체를 사용하지 않았습니다.

## 기능 검증과 범위

- Windows·Linux의 일반 표와 3단 셀 경로, Windows 282쪽 본문에서 줄 간격 변경 후 실행 취소·다시 실행을 확인합니다. 원래 본문과 쪽별 글줄 좌표가 복원되고 줄 간격 변경 중 전체 요청 재수집은 0회입니다.
- 실제 Alt+Shift+A/Z와 Ctrl+Z 경로를 확인합니다. 글자 모양·본문/셀 텍스트·글꼴 세대를 바꾸면 새 목록을 수집합니다.
- 4쪽 표 사본은 저장·재열기 뒤 쪽 수와 글줄 좌표가 일치합니다. 합성 중첩 표는 내보내기의 제어 인덱스 재배정을 제외한 텍스트·기하가 일치합니다.
- 282쪽 문서의 별도 글자 모양·본문 삽입 후 저장·재열기는 기존 빌드와 수정 빌드의 출력이 동일합니다. 기존 내보내기 정규화에 따른 일부 빈 글줄·탭의 차이를 이번 변경으로 해결했다고 주장하지 않습니다. 줄 간격 실행 취소는 원래 전체 글줄 좌표로 복원됩니다.
- 단위 검사는 허용 필드와 변이·복원 경로의 무효화를 확인하고 공통·Desktop을 각각 두 번 재현 빌드하며 엄격한 TypeScript 검사를 수행합니다. 설치된 앱이나 사용자 원본을 변경하지 않습니다.

대형 문서의 표 조판과 저장 비용 전체를 제거하는 수정은 아닙니다. 초기 문서 로딩과 글자·글꼴이 바뀌는 편집에서는 필요한 수집을 계속 수행합니다.
