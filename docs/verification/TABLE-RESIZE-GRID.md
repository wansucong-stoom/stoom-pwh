# 공통 셀 높이 조절 검증

## 적용 상태와 원인

적용 버전: **Pwh 0.6.62 / Desktop 0.1.43 / 공통 코어 r31**. Store 설치판은 Microsoft 심사·게시 이후 업데이트됩니다. 고정 rhwp 0.8.7 소스에 기존 96개와 [97번 패치](../engine-patches/rhwp-0.8.7-table-resize-allocated-grid.patch)를 순서대로 적용하며, [편집기 연결](../../scripts/patch-table-resize-grid.mjs)을 공통·Desktop에 함께 빌드합니다.

rhwp 유래 상대 크기 조절은 저장된 `cell.height`에 이동량을 더했습니다. 저장값이 최소 높이이고 글 내용·표 전체 프레임이 더 큰 경우에는 값만 바뀌고 표시 높이가 그대로였습니다. Pwh의 평면·중첩 공통 경로와 Studio의 축소 한계·높이 맞추기에서도 이 차이를 다루지 못했습니다.

수정본은 기존 행 배치 계산을 사용해 쪽 분할 전의 셀 높이를 얻습니다. 명시적인 높이 조절 때 해당 표의 행 배분을 저장 치수에 반영합니다. 별도 `resizeHeight`는 조절용 값이며, `height`와 원문 속성 조회는 저장된 값을 유지합니다. 쪽별 조각이나 반복 머리행을 합산하지 않습니다. 안정된 원문 상태의 계산은 표별로 공유하고, 편집된 표·상위 표 또는 문서 전체에 대한 기존 캐시 무효화 규칙을 따릅니다.

## 확인한 범위

- 새 합성 회귀 10개: 일반·중첩 표, HWPX·HWP5, 작은 증가와 감소, 저장·재열기, 내용보다 과도한 축소, 실행 취소, 병합 셀, 쪽 분할, 행 사이 간격, 모든 셀이 세로 병합된 표, 다른 행의 높이 보존.
- 기존 측정 범위 회귀 8개와 그림 높이 보존 회귀 3개: 총 21개 통과. 즉시 편집과 일반 일괄 재조판의 전체 페이지·원문 결과가 같고, 이전 그림 이동의 여백 보존도 유지합니다.
- 실제 화면에서 아래 경계 드래그, 위쪽으로 축소, F5 셀 선택 후 Ctrl+↓·Ctrl+↑, Ctrl+Z를 확인했습니다. 대표 사례의 단축키 높이는 113.1 → 117.1 → 113.1px이며, 실행 취소는 원래 저장 최소값 282 HWPUNIT까지 복원합니다.
- 이전 기준 문서 46·65·39·17·78쪽, 총 245쪽과 추가 확인 문서 4쪽의 전체 글자 배치 JSON·인쇄 SVG가 r30과 동일합니다. 원본 파일은 수정하지 않았습니다. 같은 글꼴 환경에서의 전후 조판 보존 시험이며, 새로운 한컴 PDF 일치 판정이나 모든 표 오류의 해소를 뜻하지 않습니다.
- 전체 회귀: 148개 파일, 659개 통과·0개 실패·29개 조건부 생략. 소스를 지정한 추가 검증은 8개 파일의 58개 항목이 모두 통과했습니다. 두 실행에는 중복 항목이 있으므로 합산하지 않습니다.
- 공통·Desktop 독립 빌드 2회에서 6개 산출물 일치, 공통 소스 308개 엄격 타입 검사와 정적 검사 통과.

## 재현

고정 입력을 이용해 `scripts/build-patched-core.mjs`로 고정 코어를 빌드합니다. 빌드된 `rhwp.js`·`rhwp_bg.wasm` 경로를 `PWH_CORE_JS`·`PWH_CORE_WASM`으로 지정하고 다음 시험을 실행합니다.

```text
node --test tests/table-resize-allocated-grid.test.mjs tests/stored-cell-height-scope.test.mjs tests/cell-picture-height-floor.test.mjs
node scripts/verify-editor-build.mjs --check-inputs
```

사용자 실문서와 화면은 공개 시험 자산에 포함하지 않습니다. 원문 치수와 내용이 다른 합성 문서로 회귀를 재현합니다. 내용이 들어가는 최소 높이보다 작게 줄이는 동작은 계속 제한되며, 그림을 위로 움직이는 것만으로 이미 확보한 셀 여백이 줄어들지 않는 기존 규칙도 유지합니다.
