# 그림 이동의 응답과 실행 취소

적용 버전: **Pwh 0.6.60 / Desktop 0.1.41**. 정식 기준 Pwh 0.6.59 / Desktop 0.1.40과 비교했습니다. GitHub 공개와 Store 제출·심사·게시 상태는 구분하며 Store 설치판에는 게시 이후 반영됩니다. WASM 코어 r29와 폰트 자산은 같은 파일을 사용합니다.

## 확인한 원인

Desktop의 `reportWorkspace()`는 1.5초마다 탭의 준비·변경 상태를 확인하면서 전체 선택 문맥을 읽었습니다. 이 경로는 변경 신호로 무효화된 문서 해시를 계산하기 위해 HWPX 전체를 내보냈습니다. 약 10MiB TEST 문서의 표 셀 그림을 네 번 세로 이동하는 동안 2~3회 발생했고, 내보내기 한 번의 동기 처리에 약 468~709ms가 걸렸습니다. 그림 속성을 바꾸는 호출은 약 1ms 수준이었습니다. 이 수치는 해당 문서와 측정 기기의 관측값이며 다른 문서에 보장되는 지연 시간은 아닙니다.

rhwp Studio에서 유래한 공통 마우스 처리는 프레임 예약 뒤 도착한 좌표를 버리고 첫 이벤트를 사용했습니다. mouseup도 예약된 마지막 입력을 적용하지 않고 기록을 닫았습니다. 기존 이동 기록은 좌표 역연산만 저장하므로 문서에 저장된 행 높이·글줄 정보까지 원본으로 보존한다는 계약이 없었습니다.

## 변경한 경로

- 공통 `status()`와 `getPresentationDocumentRevision()`은 준비 상태·문서 세대·수정 순서·쪽 수·dirty만 반환합니다. Desktop의 탭 상태 보고와 최초 초점 확인은 전체 내보내기 없이 이 정보를 읽습니다. 해시가 없음을 API로 구분하며, 전체 문서 충돌 검증과 명시적 저장을 이 값으로 대체하지 않습니다.
- [포인터 모듈](../../src/latest-pointer-frame.mjs)은 프레임 내 최신 이벤트를 유지하고 mouseup에서 최종 좌표를 적용합니다. 문서·드래그 상태가 달라지거나 종료되면 남은 콜백을 적용하지 않습니다.
- [이동 기록](../../src/picture-move-history.ts)은 첫 실제 이동 직전에 네이티브 체크포인트를 한 번 생성합니다. 종료 시 기존 SnapshotCommand에 소유권을 넘기고, 기존 히스토리 예산·지연 redo 보관·discard를 사용합니다. 매 프레임 저장·재열기나 전체 HWPX 직렬화를 하지 않습니다. 원점 복귀·Esc 취소는 원본을 복원하고 기록을 추가하지 않습니다.
- 드래그 중 표 높이와 그림 배치는 기존 공통 조판 경로로 계속 갱신합니다. 특정 문서·쪽·표 번호나 원문 내용에 따른 분기는 없습니다.

## 검증 범위

TEST 문서 28쪽에서 실제 마우스 입력으로 세로 이동, Ctrl+Z, 다시 실행을 비교했습니다. 수정판은 드래그 중 전체 HWPX 내보내기가 0회였고, 실행 취소 후 28쪽 글자·개체 좌표가 각자의 편집 전 상태와 일치했습니다. 다시 실행도 각자의 이동 후 상태와 일치했습니다. 첫 체크포인트 생성의 관측 비용은 약 0.5ms였으며 매 프레임 비용과 구분합니다.

위쪽·아래쪽·양 축 이동 5가지는 비교 사본에서 확인했습니다. 저장된 셀 높이가 큰 별도의 9쪽 TEST 사본에서는 그림을 위로 움직인 뒤 Ctrl+Z를 눌러도 표가 크게 줄어든 상태로 남는 오류를 실제 마우스 입력으로 재현했습니다. 그림 좌표를 원래 값으로 복구해도 변경된 표·셀·글줄 상태가 남았고, 기존 이동 기록은 그 상태를 보존하지 않았습니다.

| 검사 | 기준판 | 수정판 |
| --- | --- | --- |
| Ctrl+Z 후 9쪽 글자·개체 좌표 | 편집 전과 다름 | 편집 전과 일치 |
| Ctrl+Z 후 해당 쪽의 실제 캔버스 픽셀 | 표가 줄어든 채 남음 | 편집 전과 일치 |
| 다시 실행 후 배치·화면 | 이동 후와 일치 | 이동 후와 일치 |
| Ctrl+Z 후 저장·재열기 | 2쪽의 인쇄 SVG·배치가 다름 | 9쪽 전체와 원문 XML 일치 |
| 드래그 중 전체 내보내기 | 2회, 회당 약 200ms | 0회 |

마지막 mouseup 좌표 반영, 한 드래그의 한 실행 취소 기록, Esc 취소 뒤 원래 픽셀 복원도 실제 입력으로 확인했습니다. 두 독립 빌드의 공통·Desktop 파일 6개가 일치하고 TypeScript 검사, Desktop 소스·해시 검증과 정적 검사를 통과했습니다. 관련 자동 시험은 실제 r29 코어를 지정해 **38건 통과·실패 0·생략 0**입니다.

합성 회귀 시험은 여러 쪽에 걸친 평면 셀과 중첩 표 셀에서 그림을 이동한 뒤 원본 XML·원문 배치 이력·글자 좌표·개체 좌표·인쇄 SVG의 복원, 반복 redo, 저장·재열기를 비교합니다. 큰 셀 높이를 저장한 경우에는 기존 좌표 역연산이 원본 높이를 잃는다는 사전 실패도 확인합니다. 포인터 시험은 프레임 합치기·최종 입력·포커스 이탈·종료 후 오래된 입력 차단을 확인합니다. 상태 조회 시험은 이동 중 수정 순서와 dirty가 최신임을 확인하면서 전체 문맥 호출을 금지합니다.

백그라운드 시험 화면의 requestAnimationFrame이 약 1초 간격으로 제한되어 전체 드래그 벽시계 시간이나 FPS를 실제 활성 앱의 성능으로 환산하지 않습니다. 위 측정은 동기 처리 시간과 불필요한 작업 횟수입니다. 기존 245쪽의 PDF 일치도 재측정이나 새 조판 개선 수치를 뜻하지 않습니다.
