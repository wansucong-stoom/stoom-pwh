# Pwh 플러그인의 HWPX 파일 열기

수정 계층은 **Pwh 플러그인의 MCP 연결·스킬**입니다. rhwp 원천 코어의 파일 파싱이나 쪽 분할 수정이 아닙니다. Pwh 0.6.66 · Desktop 0.1.47은 공통 코어 r32를 유지합니다.

## 원인과 연결 계약

서버가 구현하지 않은 최신 MCP 탐색 요청에 성공 형태의 응답을 반환했습니다. 호스트가 이 응답으로 최신 계약을 선택하면 초기화에 실패하고, 문서 편집 도구와 HWPX 파일 진입점도 등록되지 않을 수 있습니다. 이때 파일 탭은 일반 압축 파일 미리보기로 열릴 수 있습니다.

Pwh는 기존 초기화·단일 응답 계약을 사용하므로 최신 탐색 요청에 MethodNotFound를 반환합니다. 두 계약을 지원하는 호스트는 기존 initialize 방식으로 복귀할 수 있습니다. 지원하지 않는 최신 프로토콜을 구현했다고 표시하지 않으며, 기존 프로토콜의 도구·리소스·파일 접근 권한 검사는 유지합니다.

## 검증

- 탐색 요청의 오류 응답 뒤 기존 초기화·49개 도구·HWPX 파일 진입점과 버전별 편집기 리소스가 제공되는지 검사합니다.
- 배포 ZIP에서 다시 꺼낸 실제 서버를 실행해 같은 연결과 편집기 HTML 제공을 검사합니다. 합성 서버나 원본 소스 검사만으로 배포 파일의 연결 성공을 대신하지 않습니다.
- 파일 입력 알림과 호스트의 권한 있는 경로 메타데이터를 사용한 시험에서 HWPX 사본이 3쪽으로 로드되고 편집기 준비 상태와 폴링이 확인됩니다. 원본은 수정하지 않습니다.
- 스킬은 일반 파일 탭의 queued 응답, 네이티브 메모리 핸들, 실제 편집기 로드를 구분합니다. Pwh 도구가 없을 때는 서버 연결을 우선 확인하고 같은 일반 파일 열기를 반복하지 않습니다.

Codex가 이미 연 미리보기 탭이나 실패한 서버 상태를 보관할 수 있습니다. 플러그인을 지원되는 업데이트 절차로 갱신한 뒤 파일을 다시 열어 실제 Pwh 로드를 확인해야 합니다. 미저장 문서를 보존하고 연결 복구만으로 저장 완료를 보고하지 않습니다.

공통 편집기와 Desktop 편집기는 같은 소스·버전으로 생성합니다. 코어, 기존 줄 간격 변경의 측정 재사용과 표·그림 조판 규칙은 유지합니다.

참고: [MCP 버전 호환 규칙](https://modelcontextprotocol.io/specification/latest/basic/versioning), [파일 진입점](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#file-extension-entrypoint).

## 기존 파일과 빈 조판기

기존 HWPX는 읽기 전용 파일 접근·확장자·ZIP 시작 서명을 확인한 뒤 호스트의 우측 파일 패널 요청을 반환합니다. 이 준비는 문서 전체 유효성이나 조판 완료 검사가 아니며 새 파일·출력 폴더를 만들지 않습니다. 파일이 없거나 잘못된 경우 원본을 유지하고 오류를 반환합니다. 빈 조판기는 명시적인 새 문서 요청에만 생성합니다.

호스트가 패널 호출 오류를 반환할 수 있으며, Pwh의 열기 준비 성공만으로 이 오류가 해결됐다고 판단하지 않습니다. 실제 편집기의 source·ready와 호출 기록을 별도로 확인해야 합니다.
