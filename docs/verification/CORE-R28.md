# r28 편집 경로 보완과 사전·사후 검증

[문서 모음](../README.md) · [원본 대비 차이](../RHWP-DIFFERENCES.md#nested-paragraph-and-delete-metadata) · [upstream 검토](../UPSTREAM-0.9-REVIEW.md)

Pwh 0.6.55 / Desktop 소스 0.1.36 / 공통 코어 r28의 검증 기록입니다. rhwp 0.8.7 기준과 기존 86개 패치를 유지하고, 0.9.0의 관련 오류 수정 두 건을 87·88번으로 선택 반영했습니다. 문서명·쪽·개별 표 번호에 따른 보정은 없습니다. Store 반영은 별도 정기 제출입니다.

## 필요한 수정과 발생 계층

| 현상 | 확인한 원인 | 반영 |
| --- | --- | --- |
| 그림·수식 삭제 뒤 굵기·색 경계가 다른 문자로 이동 | rhwp 기반 코어가 문자 오프셋만 당기고 서식 등의 스트림 좌표는 유지 | 87번: 공통 문단 메타데이터 갱신. 해당 그림·도형·수식·표 삭제와 그룹화 경로에 적용 |
| 중첩 셀의 문단 정렬·간격이 적용되지 않음 | rhwp Studio 유래 공통 편집기가 빈 대상 목록을 반환하고 코어의 경로 기반 문단 API도 없음 | 88번: 조회·적용·모양 ID 복원과 공통 편집기 연결 |
| F5 셀 선택의 Ctrl+Shift+C가 복사로 처리됨 | Pwh 표 클립보드의 캡처 핸들러가 Shift를 구분하지 않음 | Shift 없는 복사만 처리. 정렬 명령은 셀 블록을 유지한 채 전달 |

Desktop 전용 우회는 추가하지 않습니다. 공통·Desktop 편집기는 같은 수정으로 빌드합니다.

문단 간격과 저장 세로 위치의 별도 upstream 변경은 현재 r27에서 같은 합성 재현의 간격 이동·재열기·ID 복원이 정상입니다. 본문·평면 셀 계산을 중복 교체하지 않고, 새 중첩 경로에 필요한 원점 갱신만 연결했습니다.

## 사전·사후 결과

같은 합성 시험을 r27과 정식 최적화 r28에서 실행합니다. 사용자 실문서는 편집하지 않았습니다.

| 시험 | 수정 전 r27 | 수정 후 r28 |
| --- | --- | --- |
| 문자열 중간 그림 삭제 후 글자 서식 | 실패 | 통과 |
| 앞쪽 그림 삭제 후 글자 서식 | 실패 | 통과 |
| 앞쪽 수식 삭제 후 글자 서식 | 실패 | 통과 |
| 이모지·탭이 섞인 스트림의 그림 삭제 | 실패 | 통과 |
| 깊이 2·3 문단 서식, 부분 테두리·배경, ID 복원과 잘못된 입력 무변경 | 경로 API 부재로 실패 | 통과 |

[개체 삭제 시험](../../tests/deleted-control-format-boundaries.test.mjs)은 HWP·HWPX 재열기를 포함합니다. [중첩 서식 시험](../../tests/nested-paragraph-format.test.mjs)은 상위·이웃 셀 보존, 무효 경로와 ID의 무변경을 검사합니다. 원래 모양 ID로 복원하므로 UI 픽셀 값을 원본 단위로 다시 저장하는 오차를 피합니다.

[실제 Rust 함수 추출 시험](../../tests/deleted-control-source-metadata.test.mjs)의 5개 사례는 문자·탭·보충평면 폭, 겹친 서식 경계, 연속 끝 개체, 누름틀 소유 번호·슬롯 수, 형광펜의 논리 위치와 스트림 위치, HWPX 두 글줄 축과 측정 키를 검사합니다. 다른 구현을 기대값으로 복사한 모형 시험과 구분합니다.

전체 정식 코어 시험은 **580건 통과 / 실패 0건 / 선택적 제외 13건**입니다. 기본 시험은 **250건 통과 / 실패 0건 / 제외 378건**입니다. 두 묶음은 겹치며, 제외된 시험을 통과 수에 더하지 않습니다.

## 실제 입력과 빌드 확인

ego-lite에서 최종 최적화 WASM의 로드 해시를 확인한 뒤 합성 문서를 시험했습니다. 커서 위치 준비는 시험 API를 사용하고, 아래 편집은 실제 `isTrusted=true` 키와 버튼으로 수행했습니다.

- 깊이 2·3 셀에서 F5 → Ctrl+Shift+C로 가운데 정렬, Alt+T의 문단 위 20pt 적용.
- 상위 셀·이웃 문단·원래 테두리 보존과 실행 취소·다시 실행.
- 그림 Delete → Ctrl+Z → Ctrl+Shift+Z에서 실제 개체 수와 앞뒤 글자 굵기 보존.

[브라우저 회귀 시험](../../tests/nested-paragraph-format-browser.test.mjs)을 CI에 추가했습니다. Windows IME·설치된 Electron의 모든 컨텍스트·실제 프린터까지 확인한 결과는 아닙니다.

공통·Desktop 번들과 manifest를 함께 생성했습니다. 최종 보존 입력에서 독립 빌드 두 번을 수행해 산출물 6개가 커밋할 파일과 바이트 단위로 같은 것을 확인했습니다. 엄격 타입 검사와 소스 무결성·개인 경로 검사도 통과했습니다. 런타임·패치·빌드 입력·검증 자료는 같은 릴리스에서 지문으로 묶습니다. 정확한 산출물 해시는 릴리스의 `BUILD-RECORD.json`, `runtime-lock.json`, `SHA256SUMS.txt`를 기준으로 합니다.

## 남은 범위와 되돌리기

중첩 셀의 글자·문단 통합 스타일과 경로 미지원 명령은 [지원 범위](../TABLE-COMMANDS.md)의 제한을 유지합니다. 이번 변경은 편집 정확성 보완이며 표 입력 지연을 추가로 줄였다는 성능 수치는 제시하지 않습니다.

문제를 확인하면 문서를 저장·종료한 뒤 이전 [0.6.54](https://github.com/wansucong-stoom/stoom-pwh/releases/tag/v0.6.54)의 플러그인과 고정 r27 런타임을 함께 사용합니다. 개별 editor.js나 WASM만 서로 다른 버전으로 섞지 않습니다. 문서·프로필을 삭제하지 않습니다. Store 설치판은 Store의 정기 제출 버전으로 관리합니다.
