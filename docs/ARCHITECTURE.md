# Pwh 아키텍처

[문서 모음](README.md) · [공통 코어 변경](RHWP-DIFFERENCES.md) · [Desktop](PWH-DESKTOP.md)

Pwh는 **Windows·Linux Desktop과 Codex 플러그인에서 사용하는 무료·오픈소스 한글 문서 편집기**입니다. 같은 공통 편집기와 rhwp 기반 WASM 코어를 사용합니다. AI는 선택적으로 연결하며 모델 가중치를 앱에 포함하지 않습니다.

Linux 시험판도 Windows판의 WASM과 편집기 번들을 그대로 사용합니다. 파일 대화상자·Unix 소켓·키 모음·앱 등록과 업데이트 설치는 운영체제 연결 계층에서 처리합니다. Windows Store판은 Store에서, Linux 사용자 설치판은 같은 GitHub 릴리스의 Linux 패키지로 업데이트합니다. [Linux 구성과 설치](LINUX.md)

Apple Silicon Mac 시험판도 같은 WASM과 편집기 번들을 사용합니다. Electron 앱 번들이 Finder 파일 열기와 macOS 대화상자를 받아 공통 작업 공간과 문서 탭에 연결합니다. 새 버전은 GitHub 릴리스에서 받습니다. [Mac 구성과 설치](MACOS.md)

## Codex 파일 열기 연결

기존 문서 열기는 pwh_open_document의 읽기 전용 경로 확인과 호스트 패널 호출로 나눕니다. 빈 조판기 생성은 별도 명령입니다. 파일 준비는 출력·런타임 폴더에 쓰지 않으며 호스트 호출 실패를 새 문서 생성으로 바꾸지 않습니다. 파일 준비 결과는 documentLoaded:false로 반환하고 실제 편집기 상태로 로드를 확인합니다.

Pwh MCP 서버는 2025-11-25까지의 초기화 방식과 단일 응답 계약을 사용합니다. 지원하지 않는 최신 탐색 요청에는 MethodNotFound를 반환해 호스트가 기존 초기화로 복귀하도록 합니다. 구현하지 않은 최신 계약을 성공 응답으로 광고하지 않습니다. 연결 뒤 도구 목록의 파일 진입점이 .hwpx를 Pwh 편집기 리소스로 연결하며, 파일 경로는 호스트가 권한 메타데이터로 전달합니다. 네이티브 rhwp-core의 메모리 문서 핸들과 UI 편집 세션은 별개입니다. [연결 검증](verification/PLUGIN-FILE-OPEN.md)

## Desktop 실행 자산과 배포 검증

모든 Desktop 배포는 공통 수집기에서 실행 모듈·화면·정적 자산을 복사합니다. 공통 모듈이 정적으로 참조하는 운영체제 어댑터는 해당 OS에서 동작을 실행하지 않더라도 패키지에 포함합니다. Node의 정적 참조 해석은 운영체제 분기 실행보다 먼저 수행되기 때문입니다.

Windows·Linux 패키징은 완성된 폴더의 Node로 모듈 불러오기와 새 문서·기존 HWPX 탭 시작을 검증합니다. Store 제출 검증은 최종 MSIX를 해제해 실행 자산 전체를 소스와 대조하고 같은 시작 검사를 반복합니다. 설치된 Codex 플러그인의 캐시와 Desktop의 내장 release-source는 별도 경로입니다.

## 문서의 수명주기

1. **열기:** 원본 바이트와 형식을 확인해 공통 코어의 문서 모델을 만듭니다. 전송이 필요한 호스트는 파일 크기와 수신 상한에 맞춰 청크를 나누고 무결성을 확인합니다.
2. **편집:** 사용자 입력과 AI의 승인된 수정은 같은 편집기 메모리 문서에 적용됩니다. 대상 셀 경로·선택·문서 상태를 확인한 뒤 기존 명령·실행 취소 경로를 사용합니다.
3. **조판:** 바뀐 원문과 속성으로 글줄·행 높이·개체 배치·쪽 경계를 계산합니다. 유효한 측정값과 뒤쪽 경계가 같을 때 기존 결과를 재사용합니다.
4. **저장:** 내보내기 손실 보고, 저장 대상과 원본 변경 여부를 확인합니다. HWP를 열었을 때는 HWPX 작업본을 사용하며, 저장 결과는 재열기로 검증합니다.

화면 좌표, XML 경로와 문서 모델의 커서 주소는 서로 다릅니다. 셀·중첩 표는 전체 경로를 사용하고, 표시된 조판부호나 저장 당시의 줄 좌표를 현재 개체 주소로 대신 사용하지 않습니다.

AI가 정확한 문장의 글자 모양을 바꿀 때는 공통 텍스트 검색 결과의 문서 리비전, 셀 경로, 글자 범위와 원문을 확인합니다. 검색 이후 문서가 바뀌거나 범위가 겹치면 다시 지정해야 합니다. 검증된 범위는 일반 편집과 같은 코어의 글자 모양 적용 경로에서 처리하며, 한 요청을 실행 취소 한 단계로 기록합니다. 문단 모양은 같은 주소에서 대상 문단 전체에 적용합니다. 글자 서식 검사는 편집기의 논리적 셀 목록과 글자 서식 구간을 사용해 표 디자인 분석의 크기 한도와 별개로 진행합니다. 다음 검사 위치는 문서 리비전에 묶고 읽을 수 없는 셀 목록 수를 반환합니다. 셀 전체의 테두리·배경은 별도의 표 서식 명령을 사용합니다.

## 편집 상태와 실행 취소

| 경로 | 사용하는 정보 | 목적 |
| --- | --- | --- |
| **가벼운 상태 조회** | 준비 상태, 문서 세대, 수정 순서, 쪽 수, dirty | Desktop 탭 표시와 반복 상태 확인 |
| **전체 편집 문맥** | 문서 상태·선택·원문 대상과 필요한 해시 | AI 수정·저장 시 오래된 요청 거절 |
| **명령 기록** | 편집 전후 위치와 원문 조각 또는 체크포인트 | 실행 취소·다시 실행 |
| **그림 이동** | 첫 실제 이동 전 체크포인트, 최신 포인터와 놓는 위치 | 표 높이·글줄 배치를 포함한 복원 |

가벼운 상태 조회는 문서 전체를 HWPX로 직렬화하지 않습니다. 이 값은 충돌 검증용 전체 해시를 대체하지 않습니다. 그림 이동 체크포인트도 매 프레임 만들지 않고, 기존 실행 취소 이력의 자원 예산과 해제 정책에 연결합니다. [관련 구현과 검사](verification/PICTURE-MOTION.md)

셀 높이 조절은 쪽 분할 전 논리 행 배치를 기준으로 합니다. 원문 최소 높이와 조절용 `resizeHeight`를 구분하며, 일반·중첩 표와 드래그·키보드·높이 맞추기가 같은 값을 사용합니다. 표별 계산은 기존 측정 캐시에서 공유하고 해당 표와 상위 표의 편집 때 무효화합니다. [검증 범위](verification/TABLE-RESIZE-GRID.md)

저장 프레임의 원본 자격·개체 예약·쪽 소유는 `StoredPageFramePlan`으로 정규화합니다. 로딩의 누락 글줄 보완과 쪽 분할이 같은 계획을 사용하고, 출력과 커서는 확정된 배치를 따릅니다. 호스트 원점에 이미 포함된 높이를 다시 더하지 않으며, 개체만 있는 쪽도 본문 내용으로 판정합니다. [통합 범위와 남은 조건](engine-patches/CONDITION-AUDIT.md)

## 두 제품의 호스트 경계

**Desktop**은 작업 공간과 문서 탭별 로컬 호스트를 사용합니다. Electron의 창·인쇄·파일 연결과 공통 편집기의 문서 모델을 분리하며, AI 대화도 문서 세션에 연결합니다.

**Codex 플러그인**은 MCP의 stdio 도구·자산과 문서 편집 패널을 사용합니다. 화면의 선택 문맥과 요청을 호스트 채팅에 전달하고 결과를 같은 편집기에 적용합니다. 별도의 네이티브 파일 편집 결과가 미저장 메모리 문서에 자동 반영되지는 않습니다.

두 경로 모두 전송 크기·오프셋·SHA-256과 문서·선택의 유효성을 검사합니다. 원본이 바뀌거나 문서·선택이 달라진 요청은 최신 상태로 다시 확인합니다.

## AI와 데이터

Desktop은 공식 Codex app-server 런타임을 이용한 ChatGPT 연결과 로컬 AI 연결을 제공합니다. Codex 플러그인에서는 호스트가 AI 요청을 처리합니다. 문서의 기본 편집은 AI 연결과 독립적입니다.

문서 편집과 저장은 로컬에서 처리합니다. AI 요청에 포함한 본문·문맥은 연결한 제공자에게 전달될 수 있으므로, 실제 전송 범위와 계정·복구 데이터 정책은 [개인정보 처리방침](PRIVACY.md)을 따릅니다. 로컬 AI 주소를 사용하더라도 그 서버가 외부 서비스를 중계할 수 있으므로 주소만으로 데이터가 PC 밖으로 나가지 않는다고 판단하지 않습니다.

## 그림·글꼴과 출력

그림의 자산 바이트와 배치 프레임은 별도입니다. 자산 교체는 크기·자르기·회전·효과와 실제 표시를 함께 확인합니다. 내장 그림의 전달에는 인라인 자산의 크기·정책과 개체 URL의 수명도 관리합니다.

공통 코어 r30에서는 불변 컨테이너의 자원 바이트를 문서 소유자·원래 키로 구분해 제한된 캐시에서 공유합니다. HWPX 쓰기에는 전체 자원 SHA-256·길이·파일명으로 구분한 압축 결과 캐시를 별도로 두며, 압축 바이트 32MiB·64항목을 넘기지 않습니다. 문서 지문과 복구본도 추적된 같은 리비전의 HWPX 내보내기를 재사용하며, fresh 충돌 검증은 별도로 유지합니다. 여러 TTC face의 전송은 SHA-256과 크기로 공유하고 face별 식별·취소와 독립 버퍼를 보존합니다. [범위와 검증](verification/CELL-PICTURE-RESOURCE-REUSE.md)

화면 조판은 글꼴 목록과 검증한 글꼴 자원을 사용합니다. 글꼴 이름·파일·TTC face와 인쇄 환경에 따라 측정과 출력이 달라질 수 있습니다. Canvas 화면, 별도 CLI 출력, PDF 비교 결과는 경로와 조건을 명시합니다. [글꼴 설정](CONFIGURATION.md) · [비교 기준](RENDER-COMPARISON.md)

## 로컬 서비스와 보안

로컬 호스트는 127.0.0.1에 바인딩하며 세션 토큰, Host·Origin 검사와 탭 소유권을 확인합니다. 파일 경로와 자산 요청은 허용된 범위에서 처리하며, 토큰이 포함된 주소·계정 정보·복구본은 공개 배포물에 포함하지 않습니다.

ZIP/XML 원문 수정 도구는 안전한 말단 텍스트와 명시한 서식 범위를 대상으로 합니다. 문단이 비어 보이더라도 구역·단·쪽 번호·표·그림 앵커를 지우는 근거로 사용하지 않습니다.

## 검증 원칙
