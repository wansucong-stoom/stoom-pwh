# 조판 판정 조건의 정리 기준

## 일반 규칙과 원본 해석을 구분

표·그림의 속성과 저장 형식을 읽는 조건은 배치 결과를 직접 결정하지 않습니다. 원본 좌표가 어느 공간을 설명하는지 확인해 공통 계획으로 정규화하고, 높이 보완·쪽 분할·그리기가 그 계획을 소비합니다.

| 단계 | 공통 판단 | 배치 경로의 책임 |
| --- | --- | --- |
| 입력 자격 | 원본 줄, 현재 재조판 이력, 중첩 셀 변경을 같은 기준으로 확인 | 편집으로 무효가 된 원본 프레임을 다시 사용하지 않음 |
| 개체 속성 | 글자 취급·줄 배치·기준 위치·겹침·흐름 속성을 해석 | 다른 속성을 같은 형태라는 이유로 강제 통합하지 않음 |
| 예약 소유권 | 호스트 원점에 이미 포함된 상자, 현재 흐름의 상자, 다른 쪽의 상자를 구분 | 같은 높이를 두 번 더하지 않음 |
| 쪽 소유권 | 실제 본문 수용 범위와 명시적 나눔을 적용 | 넘치는 그림을 위로 당겨 끼우거나 뒤 문단과 같은 쪽으로 합치지 않음 |
| 출력과 커서 | 확정한 개체 배치·원문 주소를 사용 | 그리기에서 크기만 보고 쪽을 다시 추정하지 않음 |

99번의 원본 프레임 근거를 100번 `StoredPageFramePlan`으로 모읍니다. 로딩은 이 계획을 좌표 재구성 전에 고정하고, 쪽 분할은 같은 계획에서 예약과 소유 쪽을 얻습니다. 출력은 확정된 배치를 사용합니다. 원본 자격과 문단 기준 자리차지 개체의 공통 조건도 공유합니다.

눈에 보이는 본문 개체가 있는 쪽은 글줄 목록이 비어 있어도 빈 쪽이 아닙니다. 아직 최종 목록으로 옮기지 않은 그림·저장 프레임·표의 이어지는 조각을 같은 본문 내용 판정에 포함합니다. 명시적 쪽 나눔이 이런 쪽을 지우거나 다음 본문과 합치지 않게 합니다.

## 고정 원본에 남은 문구 조건

rhwp 0.8.7 고정 원본 `1a76570e833917d15817415a53c09ad61ab3203f`의 Rust 소스에서 직접 문자열 비교를 검색하고 해당 실행 경로를 확인했습니다. 아래는 이 검색으로 확인한 항목이며 모든 수치·구조 지문 조건을 망라한 목록은 아닙니다. Pwh에서 새로 추가한 문구 조건이 아닙니다.

| 원본 경로 | 조건 | 영향 | 처리 상태 |
| --- | --- | --- | --- |
| `src/renderer/composer.rs` | BCP 관련 특정 문구 | 마지막 저장 글줄을 접음 | 기존 호환 처리 유지. 일반적인 짧은 마지막 줄과 구분할 원본 근거·기준 출력이 필요 |
| `src/renderer/layout/paragraph_layout.rs` | `수험번호` | 셀의 정렬 폭 보정 | 기존 처리 유지. 압축된 글자 폭·개체 앵커로 대체할 후보와 일반 라벨을 함께 검증해야 함 |
| `src/parser/hwp3/mod.rs` | `해답` | HWP3 단 정의 보완 | 기존 처리 유지. 변환 전 단·미주 정보의 보존 경로 확인 필요 |
| `src/renderer/composer.rs` | 조례 관련 특정 문구 | 환경 변수로 켜는 진단 로그 | 배치에 영향 없음. 배치 보정과 분리해서 관리 |

문구 조건을 삭제하고 모든 짧은 줄·라벨에 같은 보정을 적용하는 것은 공통화가 아닙니다. 정상 문단을 함께 접거나 정렬을 바꿀 수 있습니다. 대체 규칙은 원본 속성 또는 실제 기하 근거로 설명하고, 해당 조건이 없어야 할 문서도 함께 통과해야 합니다. 근거가 부족한 기존 조건은 미해결 항목으로 남기며 일반화 완료로 보고하지 않습니다.

## 회귀 검사

- 같은 구조의 글 내용·높이·여백·본문 줄 수를 바꿔도 예약과 쪽 소유가 일관적인지 확인합니다.
- 원본 상자가 글줄보다 작은 경우, 겹침·별도 기준 개체와 닫히지 않는 좌표는 보완 프레임의 근거로 승인하지 않습니다.
- 저장·재열기·실행 취소를 검사하고 이전 코어의 독립 제외 사례와 비교합니다.
- 쪽 수 보존, 내용의 물리 쪽 배정과 PDF의 픽셀 일치는 각각 확인합니다. 하나가 통과했다고 나머지를 통과로 간주하지 않습니다.
