# 공통 조판 소유권 규칙

표·문단·그림의 위치를 결정할 때, **어떤 원문과 속성이 해당 공간과 쪽을 소유하는지**를 먼저 확인합니다. 특정 문서의 화면에 맞춘 좌표 보정 대신 같은 속성에 공통으로 적용할 규칙을 관리하기 위한 문서입니다.

현재 배포 런타임은 **r13**입니다. 아래 내용은 기존 패치와 **미배포 후보의 설계·검증 기준**을 함께 정리한 것으로, 모든 규칙이 운영판에 구현·검증됐다는 뜻은 아닙니다. 후보의 적용 조건과 상태는 [코어 패치 상세](README.md), 실제 출력의 검증 범위는 [조판 일치 검증](../LAYOUT-FIDELITY.md)을 따릅니다. 승인은 기록된 연속 구간에 한정하며, 일부 쪽의 통과를 문서 전체의 완료로 확대하지 않습니다.

## 원문에서 배치를 결정하는 기준

| 구분 | 공통 규칙 |
| --- | --- |
| 컨트롤 앵커와 표시 순서 | 컨트롤이 저장된 문자 위치는 앵커입니다. 그것만으로 표가 호스트 글보다 먼저 그려진다고 판단하지 않습니다. 원래 글줄의 위치, 개체 오프셋·여백, 다음 문단의 원점이 같은 배치를 설명하는지 확인합니다. |
| 원본 줄과 재조판한 줄 | 원본처럼 보이는 줄 태그나 해제된 dirty 상태만으로 저장 좌표를 신뢰하지 않습니다. 재조판은 원래 태그를 유지하면서 깨끗한 줄을 다시 발행할 수 있습니다. `layout_space_metrics` 같은 현재 줄 구성의 출처와 실제 구성된 줄도 함께 확인합니다. |
| 물리 프레임과 내용 커서 | 쪽에 보이는 테두리·빈 공간의 높이와 원문을 어디까지 소비했는지는 별개입니다. 저장된 첫 물리 프레임은 원래 경계와 소유자가 입증될 때만 보존합니다. 빈 공간을 채우기 위해 다음 쪽의 글이나 표를 미리 소비하지 않습니다. |
| 선언 높이의 의미 | 표 높이가 모든 문서에서 전체 내용 높이이거나 모든 조각의 높이인 것은 아닙니다. 셀 높이도 최소 높이와 여러 물리 조각의 합을 구분해야 합니다. **선언 셀 높이에서 앞 조각 높이를 빼는 식을 보편 규칙으로 사용하지 않습니다.** |
| 안쪽·바깥 여백 | 부모 셀의 안쪽 여백과 자식 표의 바깥 여백을 별도 소유 공간으로 계산합니다. 자식 프레임이 위·아래 바깥 여백을 소유한다면 예약 높이, 실제 표 원점, 뒤따르는 흐름에 각각 한 번만 반영합니다. 앞 쪽에서 이미 사용한 앵커 오프셋도 다시 더하지 않습니다. |
| 본문 수용 범위 | 개체 본체만 들어간다는 이유로 저장 프레임 전체가 들어간다고 판단하지 않습니다. 실제 원점부터 앞 내용·오프셋·여백·개체 끝까지 현재 본문 영역에 수용되는지 확인합니다. 수용되지 않거나 근거가 불완전하면 일반 분할 경로를 유지합니다. |

같은 높이를 만드는 속성 조합만으로 소유권이 증명되지는 않습니다. 작은 내부 표의 로컬 좌표 재시작, 합성 줄, 혼합 컨트롤, 겹침 개체와 지원하지 않는 병합 범위는 해당 규칙의 적용 조건에서 구분합니다. 원문 글자·글꼴·셀 크기를 바꾸거나 표시를 가려 출력 차이를 숨기지 않습니다.

## 예약·그리기·커서는 같은 근거를 사용

쪽 나눔의 예약 높이, 실제 그리기, 커서·클릭 위치는 같은 소유권 판정과 시작·끝 커서를 사용해야 합니다. 자식 표의 행·셀 분할은 명시적인 `RowCut` 등으로 전달하고, 그리기 단계에서 높이만 보고 다시 추정하지 않습니다. 내용이 끝난 라벨 셀을 다음 조각에서 재사용하거나, 텍스트 줄 범위가 비었다는 이유로 그 조각이 소유한 내부 표를 생략하지 않습니다.

한 경로에 새 판정을 추가할 때는 관련 측정·일반 배치·부분 배치·커서 경로를 함께 확인합니다. 같은 원본 근거를 공통 함수나 명시적인 분할 정보로 전달합니다. 물리 프레임을 보존하는 정보와 내용 소비량은 분리해, 테두리 높이를 복원해도 다음 원문 주소가 달라지지 않게 합니다.

캐시로 재사용하는 판정은 문서·구역·표의 안정된 입력으로 계산합니다. 마지막으로 그린 쪽의 본문 영역이나 렌더링 호출 순서에 따라 원본 자격이 달라지면 안 됩니다. 실제 쪽에 남은 공간은 별도의 `RowCut` 수용 예산으로 검사합니다.

## 편집과 실행 취소

원본 저장 배치를 위한 규칙은 그 원본 근거가 유지되는 동안만 적용합니다. 글 수정이나 폭 변경으로 줄이 다시 구성되면 현재 내용을 기준으로 재조판하며, 이전의 빈 프레임을 강제로 유지하지 않습니다. 원본 저장 줄과 재생성한 줄의 구분은 HWP/HWPX 및 중첩 편집 경로에 맞춰 확인합니다. 전역 편집 상태 하나가 모든 경로를 대신한다고 가정하지 않습니다.

실행 취소는 원문뿐 아니라 줄 구성의 출처와 해당 배치도 복구해야 합니다. 시험에서는 같은 수정의 일반 재조판 결과를 독립된 기준과 대조하고, 저장·재열기 및 실행 취소 후에 원문 주소·주변 셀·테두리·표시 위치가 유지되는지 확인합니다. 새 후보의 잘못된 결과를 기대값으로 삼지 않습니다.

## 검증과 승인

1. 속성별 합성 문서로 적용 사례와 제외 사례를 함께 검사합니다. 위·아래 여백이 서로 다른 경우, 저장 줄 없음, 재조판된 줄, 작은 로컬 좌표 재시작, 본문에 들어가지 않는 프레임 등을 포함합니다.
2. 실제 WASM으로 내용 커서·원문 주소·프레임·편집·실행 취소를 검사하고, 실제 브라우저의 클립 적용 뒤에도 누락·중복·잘림이 없는지 확인합니다. 컴파일이나 소스 함수 시험만으로 화면 검증을 대신하지 않습니다.
3. 같은 원본에서 만든 한글 기준 PDF와 Pwh의 실제 인쇄 PDF를 같은 물리 쪽·원점·크기로 비교합니다. 출력 이동·확대·쪽 재배열로 오차를 숨기지 않습니다.
4. **매번 최신 후보 엔진 하나로 전체 출력을 다시 만들고 1쪽부터 연속 구간을 검증합니다.** 예전 엔진의 앞쪽 결과와 새 엔진의 뒤쪽 결과를 이어 붙이지 않습니다. 점수와 내용·경계 검사를 모두 통과해야 다음 쪽으로 이동합니다.
5. 기존 승인 구간과 다른 문서의 회귀 검사, Pwh·Pwh Desktop의 공통 런타임 검증을 통과한 뒤 배포 여부를 결정합니다. 후보 시험 통과와 운영 반영은 구분합니다.

구체적인 점수·감사 조건은 [쪽별 조판 검증 기준](../LAYOUT-QUALITY-GATES.md), 비교 절차는 [한글과 Pwh의 출력 비교 도구](../RENDER-COMPARISON.md)를 참고하세요. 오류의 발생 계층과 원본 유래 여부는 [rhwp 원본과 Pwh의 차이](../RHWP-DIFFERENCES.md)에 구분해 기록합니다.
