# 코어 패치: 표 조판과 원문 소유 범위

이 디렉터리는 rhwp 0.8.7에 적용한 변경을 검토할 수 있도록 보존합니다. Pwh의 Studio·클라이언트 패치와 구분되는 **조판 코어 변경**입니다. 문서 원문의 텍스트, XML에 저장된 셀 높이, 글꼴이나 여백이 아니라 계산된 배치를 변경합니다. 넘친 글자를 잘라 가리거나 줄 간격을 압축하지 않으며, 문서 전체에 `reflowLinesegs` 복구를 호출하지 않습니다.

개별 패치를 설계·검증할 때 따르는 [공통 조판 소유권 규칙](LAYOUT-OWNERSHIP-RULES.md)을 별도로 관리합니다. 원문 앵커와 표시 순서, 물리 프레임과 내용 커서, 여백·편집 상태의 기준을 설명하며, 각 규칙의 실제 적용 범위와 배포 상태는 아래 패치별 기록을 따릅니다.

<a id="cause-and-scope"></a>
## 원인과 적용 범위

한글 호환 단축키의 편집 상태 분기는 [Pwh 공통 Studio 빌드 패치](../../scripts/patch-hancom-key-contexts.mjs)에 있습니다. 고정 크기 표 조절과 행 삭제는 r22 코어 API를 사용합니다. [편집기 변경과 적용 범위](../RHWP-DIFFERENCES.md#한글-호환-단축키의-편집-상태-구분)


<a id="continued-flow-picture-anchor"></a>
### 79번 패치의 연속 셀 자리차지 그림

[공통 코어 패치](rhwp-0.8.7-continued-flow-picture-anchor.patch)는 현재 연속 조각이 소유한 문단 기준 TopAndBottom 흐름 그림을 그 조각의 문단 시작점에 배치합니다. 셀 세로 정렬을 다시 적용해 앞의 제목·문단 높이를 지우지 않습니다. 개체 첫 단위의 소유권을 기존 분할 원장에서 확인하며 용지 상대 그림이나 제한을 끈 그림의 배치를 바꾸지 않습니다.

[합성 회귀 시험](../../tests/continued-flow-picture.test.mjs)은 그림 앞 제목 1~3개, 같은 문서의 저장·재열기, 편집 후 스냅샷 복원과 명시적 용지 상대 배치를 검사합니다. 익명 실제 TEST 문서에서는 17쪽 유지와 해당 쪽의 제목·그림 분리를 인쇄 PDF로 확인합니다. [전후 수치와 범위](../RHWP-DIFFERENCES.md#continued-flow-picture-anchor)

<a id="source-owned-render-measurement-reuse"></a>
### 78번 패치의 커서·그리기 측정 재사용

[패치 소스](rhwp-0.8.7-source-owned-render-measurement-reuse.patch)는 문서가 소유하는 표·문단만 등록해 원본 글줄 계산을 커서 조회와 화면 그리기에 전달합니다. 그리기용 임시 복제본은 이 목록의 소유 주소를 가지지 않으므로 별도로 계산합니다. 그리기의 중첩 행 높이는 같은 용지·단 프레임 안에서 재사용하고 다음 프레임에서 초기화합니다.

원본이 dirty가 되면 그리기 재사용을 중지합니다. 지연 셀 입력도 표와 셀 문단의 측정값을 무효화하므로, 쪽 분할 전 그리기가 이전 글줄을 읽지 않도록 합니다. 원본의 소유 목록은 전체 무효화 이후 다음 조판에서 등록합니다. [성능·조판 검증](../RHWP-DIFFERENCES.md#source-owned-render-measurement-reuse)

후보 WASM 경로를 지정해 자동 실행되는 [커서·그리기 회귀 시험](../../tests/cursor-layout-cache.test.mjs)을 실행할 수 있습니다. 기본 비교는 같은 원본의 표시 설정을 같은 값으로 다시 적용해 캐시를 비운 뒤 계산합니다. 직전 코어의 바인딩과 WASM을 PWH_RENDER_CACHE_BASE_JS·PWH_RENDER_CACHE_BASE_WASM으로 지정하면 별도 코어의 계산과도 대조합니다. 지연 입력의 긴 줄에서 재사용을 무효화하는 회귀를 포함합니다. 현재 배포 런타임 r23에 포함됩니다.

<a id="incremental-table-edit-measurements"></a>
### 77번 패치의 표 편집 증분 계산

[패치 소스](rhwp-0.8.7-incremental-table-edit-measurements.patch)는 최외곽·중첩 셀의 크기 조절과 중첩 셀의 문자 삽입·삭제에 같은 측정 소유권을 적용합니다. 변경 경로의 모든 상위 표와 실제로 줄을 다시 나누는 셀 문단을 갱신합니다. 같은 원본의 중첩 표 측정, 용지·본문 영역과 안 여백 조건이 같은 행 높이, 폭과 글꼴 문맥이 같은 평문 셀 글줄을 재사용합니다. 캐시는 문서 코어가 소유하고 전체 재조판·구조 변경·실행 취소 경계에서 초기화합니다. 각 캐시의 항목 수에 상한을 둡니다.

뒤쪽 쪽의 계획과 원본 의존성을 비교한 뒤 동일한 쪽의 계획·렌더 트리를 유지합니다. 편집된 호스트를 참조하는 본문·어울림·연속 표·각주·머리말·꼬리말은 갱신합니다. 분할 경계 확인 순회는 계속 수행합니다. 기존 셀 치수·그림·여백·쪽 분할의 산식은 같은 입력으로 계산합니다. [측정과 검증 범위](../RHWP-DIFFERENCES.md#incremental-table-edit-measurements)

후보 코어의 두 경로를 지정해 합성 시험을 실행합니다.

~~~powershell
$env:PWH_CORE_JS = '<candidate>/rhwp.js'
$env:PWH_CORE_WASM = '<candidate>/rhwp_bg.wasm'
node --test tests/incremental-table-layout.test.mjs tests/inline-picture-frame.check.mjs tests/nested-capacity-rewind.test.mjs
~~~

[증분 회귀 시험](../../tests/incremental-table-layout.test.mjs)은 각 편집의 모든 쪽 글자 좌표·인쇄 SVG를 일괄 편집으로 강제한 전체 재계산과 대조합니다. 바깥 셀 폭 변경, 셀 문단 재할당, 일괄 편집 후 로컬 편집, 독립된 뒤쪽 쪽, 저장·재열기와 스냅샷 복원 뒤의 재입력을 포함합니다. 현재 배포 런타임은 r23입니다.

<a id="inline-picture-frame-trailing-spacing"></a>
### 76번 패치의 쪽 끝 인라인 그림

[패치 소스](rhwp-0.8.7-inline-picture-frame-trailing-spacing.patch)는 한 셀이 쪽을 넘겨 이어지는 HWPX 표의 원본 줄을 검사합니다. 그림 하나가 글자처럼 놓여 저장 글줄 높이와 일치하고, 뒤 문단이 새 쪽 좌표에서 시작하며, 그림 끝과 셀 안 여백이 선언 프레임 안에 들어갈 때 다음 줄로 가는 간격을 현재 쪽의 그림 단위에서 제외합니다. 분할의 실제 가용 높이 검사와 그리기는 같은 셀 단위를 읽습니다. 현재 용지에 공간이 부족해 그림을 옮겨야 할 때도 그림 뒤의 확인된 쪽 경계를 유지합니다. [출력 검증 범위](../RHWP-DIFFERENCES.md#inline-picture-frame-trailing-spacing)

후보의 `PWH_CORE_JS`와 `PWH_CORE_WASM` 경로를 지정하고 `node --test tests/inline-picture-frame.check.mjs`로 그림과 뒤 표의 쪽 배치, 저장·재열기를 검사할 수 있습니다.

<a id="nested-text-capacity-continuation"></a>
### 75번 패치의 중첩 표 연속 조각

[패치 소스](rhwp-0.8.7-use-capacity-after-nested-text-frame-displacement.patch)는 실제 가용 높이로 나뉜 HWPX 중첩 표의 연속 조각에서, 다음에 만나는 평문 저장 좌표가 현재 쪽을 비우도록 강제하는 문제를 보완합니다. 같은 자식 표에서 앞서 소비한 내용 범위, 분할 속성, 명시적 쪽·단 나눔, 독립된 저장 개체 프레임과 현재 조각의 실제 높이를 확인합니다. 기존 평문 규칙과 같이 남은 공간이 해당 조각에 주어진 예산의 절반보다 커야 하며, 이어지는 줄도 그 예산 안에 들어가야 합니다. 한 단만 선언한 메타데이터는 쪽·단 나눔으로 읽지 않습니다. 원문 줄 좌표와 문서 여백은 수정하지 않습니다. [합성 조판 회귀 시험](../../tests/nested-capacity-rewind.test.mjs)

<a id="reuse-font-metric-decisions-per-run"></a>
### 74번 패치의 글꼴 폭 표 재사용

<a id="rebuild-cell-flow-after-width-change"></a>
### 73번 패치의 셀 폭 변경 뒤 문단 위치

[패치 소스](rhwp-0.8.7-rebuild-cell-flow-after-width-change.patch)는 최외곽 표와 중첩 표의 폭 변경에서 실제 폭이 달라진 셀만 재조판하고, 기존 표 나누기 경로와 같은 문단 높이 누적 규칙으로 줄의 세로 위치를 다시 계산합니다. 합성 시험과 여러 단계로 중첩된 시험 사본에서 문단 겹침, 실행 취소와 HWPX 저장·재열기를 확인했습니다.

<a id="prepare-font-measurement-per-run"></a>
### 72번 패치의 글꼴 판별 재사용

[패치 소스](rhwp-0.8.7-prepare-font-measurement-per-run.patch)는 글줄의 문자 폭을 계산할 때 기본 글꼴과 영문 구두점 슬롯의 글꼴 이름을 미리 판별합니다. KoPub 이름의 Unicode 소문자 변환 결과와 기존 폭 계산을 그대로 사용합니다. 재사용 범위는 해당 글줄로 한정합니다. [성능과 출력 검증](../RHWP-DIFFERENCES.md#prepare-font-measurement-per-run)

<a id="viewport-table-cell-selection"></a>
### 71번 패치의 셀 선택 좌표 조회

[패치 소스](rhwp-0.8.7-viewport-table-cell-selection.patch)는 행·열·병합 구조를 모델에서 조회하고, 선택을 그릴 때 요청한 물리 쪽의 셀 경계만 조회합니다. 키보드 조절의 대상은 표 전체의 구조에서 결정하므로 화면 밖 행이나 병합 셀도 포함합니다. 기존 좌표 조회와 치수 변경 후 조판 경로를 유지합니다. 정식 r22에 71~75번 패치가 포함됩니다.

<a id="hwpx-owned-table-insets-and-reset-suffix"></a>
### 70번 패치의 표 바깥 여백과 쪽을 이은 문단

[패치 소스](rhwp-0.8.7-hwpx-owned-table-insets-and-reset-suffix.patch)는 원본 글줄에 의해 원점이 확인된 셀 끝 부동 표와, 쪽을 넘기는 문단의 인라인 표를 다룹니다. 셀 끝 부동 표의 점유 상자에는 이미 두 바깥 여백이 있으므로 그리기에서 위 여백으로 테두리만 옮깁니다. 인라인 표는 제어 문자 위치와 저장 줄 높이로 각각의 줄 소유자를 확인합니다. 쪽을 넘기기 직전 표에는 위 여백을 한 번 적용하고, 새 쪽에서 마지막 표 뒤에 이어지는 글줄은 그 쪽에 수용되는 범위에서 한 번 내보냅니다. 합성 HWPX에서 이전 코어의 본문 누락과 새 코어의 원래 쪽 복원을 확인했습니다. [실제 인쇄 비교](../LAYOUT-FIDELITY.md#test-b-final-65)

<a id="hwpx-nested-column-left-anchor"></a>
### 65번 패치의 중첩 표 왼쪽 앵커

[패치 소스](rhwp-0.8.7-hwpx-nested-column-left-anchor.patch)는 원본 HWPX의 셀 안쪽에 있는 단 기준 왼쪽 정렬 위아래 배치 표를 대상으로 합니다. 행 단위 나눔을 선언한 여러 열 표의 오프셋이 0이고, 표와 좌우 바깥 여백이 상위 셀 내용 폭 안에 들어가면 셀 내용 상자의 왼쪽에 표의 왼쪽 바깥 여백을 더해 배치합니다. [TEST 문서 B 실제 인쇄 비교](../LAYOUT-FIDELITY.md#test-b-nested-column-left)

<a id="print-font-snapshot"></a>
### 66번 패치의 인쇄용 글꼴 조판 사본

[패치 소스](rhwp-0.8.7-print-font-snapshot.patch)는 HWPX 글꼴표에서 언어별 원본 이름과 대체 이름이 일치하는 비내장 TTF 선언을 읽습니다. Desktop은 인쇄 창이 실제로 로드한 글꼴만 선택해 별도 조판 사본에 넘깁니다. 사본은 출력용 좌표를 계산하는 동안 편집기의 조판과 기록에서 분리됩니다. 원래 설정으로 돌아가면 인쇄 창도 처음에 준비한 쪽을 다시 사용합니다.

<a id="hwpx-terminal-object-only-float-origin"></a>
### 67번 패치의 쪽 끝 표 원점

[패치 소스](rhwp-0.8.7-hwpx-terminal-object-only-float-origin.patch)는 앞 인라인 표의 원본 줄 높이·줄간격과 문단 간격의 합이 다음 부동 표의 저장 앵커와 일치하는지 확인합니다. 다음 문단이 명시적으로 새 쪽에서 시작하고 표 전체가 현재 쪽에 들어가면 그 저장 원점과 위 바깥 여백을 배치에 사용합니다. [TEST 문서 B 실제 인쇄 비교](../LAYOUT-FIDELITY.md#test-b-terminal-object-float)

<a id="hwpx-adjacent-source-table-anchors"></a>
### 68번 패치의 인접 원본 글줄과 표 원점

[패치 소스](rhwp-0.8.7-hwpx-adjacent-source-table-anchors.patch)는 기존 저장 인라인 표 줄의 뒤 원점 확인에 앞 글줄의 전진량 확인을 추가합니다. 두 방향에서 저장 좌표가 이어지고 선행 표를 침범하지 않으면 쪽 안의 표 원점을 복원합니다. 쪽 끝 부동 표는 앞의 일반 글줄이 저장 원점을 증명하고 아래쪽 캡션까지 쪽에 들어갈 때 같은 경로에서 처리합니다. [TEST 문서 B 실제 인쇄 비교](../LAYOUT-FIDELITY.md#test-b-adjacent-source-anchors)

<a id="hwpx-terminal-cut-merged-frame"></a>
### 69번 패치의 마지막 내용 컷과 병합 표 높이

[패치 소스](rhwp-0.8.7-hwpx-terminal-cut-merged-frame.patch)는 마지막 행의 내용이 모두 소비된 원본 HWPX의 표에서, 전체 높이를 가로지르는 병합 셀과 마지막 행의 선언 높이가 표 상자를 입증하는지 확인합니다. 다음 문단의 명시적 쪽 나누기와 현재 쪽 예산도 확인합니다. 조판 예약과 테두리는 확정된 마지막 행의 물리 높이를 함께 쓰고, 내용 컷은 보존합니다. ### 28번 패치의 HWPX 표 분할

[패치 소스](rhwp-0.8.7-hwpx-parallel-row-page-edge.patch)는 고정 rhwp 원천 코어의 표 분할을 보완합니다. Pwh와 Pwh Desktop이 공유하는 WASM 빌드에 적용합니다.

반복 머리행 아래에서 나뉘는 마지막 행의 첫 조각을 대상으로 합니다. 선언 높이 안에 글줄과 셀의 위아래 여백이 들어가고, 그 뒤 줄간격을 더했을 때만 선언 경계를 넘는지 검사합니다. 같은 행의 셀들이 각각 저장한 첫 되감김도 비슷한 높이에서 다음 쪽 원점으로 돌아와야 합니다. 합성 줄, 편집한 줄, 병합으로 이어진 행, 셀의 개체가 끼어든 경계는 기존 경로를 사용합니다.

기존 컷 선택과 조각 높이 계산이 같은 규칙을 사용합니다. 현재 쪽의 본문 한계와 셀 안쪽 여백을 적용한 상태에서 줄 수용 여부를 결정합니다. 원문 속성에 저장된 줄간격 값도 보존합니다.

[합성 HWPX 시험](../../tests/hwpx-parallel-row-page-edge.test.mjs)은 글줄이 한 번만 나타나고 표 아래선 안에 들어가는지, 반복 머리행이 유지되는지 검사합니다. 다른 셀의 되감김이 없거나 본문에 글줄이 실제로 들어가지 않는 경우에는 기존 분할을 확인합니다. 배포 r18에서 재현한 기존 동작과 후보의 결과를 구분합니다.

실제 Desktop 인쇄 경로에서 같은 HWPX를 출력해 확인했습니다. 한컴과 1쪽 표 아래선의 차이는 **18.21pt → 1.21pt**, 150dpi·2픽셀 허용의 일반 잉크 F1은 **97.65% → 98.89%**, 진한 잉크 F1은 **96.36% → 98.19%**입니다. 마지막 줄이 한 번만 1쪽에 배치됐고, 저장·재열기에서도 이 위치가 유지됐습니다. 같은 후보의 전체 출력은 48쪽이며 한컴 기준은 46쪽입니다. 2쪽의 글 두 구간이 3쪽으로 밀려 순차 검증은 1쪽까지 통과했습니다. 별도 문서 3건의 71쪽 인쇄 SVG와 텍스트 위치는 기존 코어와 일치했습니다.

[패치 소스](rhwp-0.8.7-hwpx-parallel-row-continuations.patch)는 28번의 경계 판정을 이어지는 표 조각에도 적용합니다. 현재 셀의 실제 조각 시작 줄부터 다음 저장 원점까지의 범위를 찾고, 같은 행의 다른 셀이 같은 순서의 물리 경계를 저장했는지 대조합니다. 다음 원점이 같은 문단 안에 기록된 경우에도 이 기준을 사용합니다. 실제 쪽에 들어가는 높이는 기존 수용 계산에서 검사합니다.

합성 문서로 첫 조각과 후속 조각, 서로 다른 저장 원점, 실제 높이 부족을 비교합니다. 먼저 내용이 끝나는 형제 셀은 다음 저장 경계를 제공할 수 없어 이 적용 범위에 들지 않습니다.

현재 쪽에 들어갈 글줄과 셀 안쪽 여백을 먼저 계산합니다. 본문 가용 공간 안에서 허용된 같은 조각 높이를 테두리에도 사용합니다. 이어짐이 끝나는 표는 마지막 내용이 차지하는 높이로 닫힙니다. 문서명이나 쪽 번호, 고정 용지·셀 크기로 분기하는 조건은 없습니다.

합성 문서에서 짧은 셀의 좌우 위치를 바꿔 같은 결과를 검증합니다. 잘못된 저장 원점, 가용 높이 부족, 본문 하단 넘침, 마지막 조각의 과도한 높이를 함께 검사합니다. 현재 배포판은 r20입니다.

실제 Desktop 인쇄 PDF에서 6~9쪽 표 아래선 차이는 한컴 대비 **16.77pt → 0.23pt**, 10쪽의 마지막 표 조각은 **68.21pt → 0.21pt**입니다. 본문 높이와 셀 크기를 저장한 원문 속성은 보존합니다. 1~10쪽까지 순차 검증했으며 11쪽은 미통과입니다. 별도 3문서의 71쪽은 기존 r20과 인쇄 SVG 및 텍스트 위치가 같았습니다. 전체 코어 시험 477건 통과, 환경별 제외 64건, 실패 0건입니다.

### 개발 중인 31번 패치의 중첩 표 경계

[패치 소스](rhwp-0.8.7-nested-inline-projected-opening-owner.patch)는 Pwh 공통 WASM에서 안쪽 표를 개별 행으로 분해한 뒤에도 첫 행이 원본의 다음 쪽 시작 위치를 이어받도록 합니다. 확인하는 근거는 원본 개체 높이와 바깥 여백을 담은 글줄, 다음 문단의 저장 위치, 그리고 앞쪽에서 나뉜 부모 행의 선언 범위입니다. 안쪽 표의 원본 행 높이 합계도 선언된 높이와 맞아야 합니다.

원문의 쪽 경계와 현재 측정한 높이를 구분합니다. 현재 조각의 가용 높이는 기존 분할 예산을 따릅니다. 원본 경계를 확인한 경우에만 같은 저장 높이를 앞 조각의 수용과 테두리 계산에 공유합니다. 편집한 줄이나 개체 상자 불일치, 조각 중간 커서는 기존 경로를 사용합니다.

합성 문서에서 글줄과 안쪽 표가 각 쪽에 한 번만 표시되는지, 원본 조각의 아래선 높이, 저장·재열기, 저장 상자 불일치 반례를 확인합니다. 현재 배포판은 r20입니다.

실제 Pwh Desktop 인쇄 PDF에서 11쪽의 일반 잉크 F1은 **84.56% → 97.70%**, 진한 글자·선 F1은 **73.11% → 94.56%**입니다. 바깥 표 아래선의 차이는 **23.72pt → 0.33pt**, 안쪽 표는 **22.55pt → 0.27pt**입니다. 11쪽의 정규화 문자 610개는 같은 줄 위치에서 일대일로 대응했고, 안쪽 표의 다음 조각은 12쪽에서 시작했습니다. 1~10쪽은 r21 인쇄와 픽셀 단위로 동일합니다.

검증은 11쪽까지 통과했습니다. 12쪽은 일반 F1 **54.54% → 65.01%**, 13쪽은 **54.25% → 53.40%**이며, 전체 쪽 수는 한컴 46쪽과 Pwh 48쪽입니다. 별도 문서 3개의 71쪽은 r21과 인쇄 SVG·텍스트 위치가 같았고 저장·재열기 결과도 유지됐습니다. 코어 시험 478건 통과, 환경별 제외 64건, 실패 0건입니다.

### 개발 중인 32번 패치의 중첩 표와 글줄 배치

[패치 소스](rhwp-0.8.7-hwpx-displaced-nested-table-line.patch)는 저장된 HWPX에서 셀 첫 글줄의 세로 위치가 그 문단이 소유한 자리 차지 표의 본체 높이와 위·아래 바깥 여백의 합과 일치하는 경우를 처리합니다. 현재 측정값도 같은 상자를 확인하면, 표 뒤에서 시작하는 글줄에 표 높이를 다시 더하지 않습니다. 한 단 설정이 함께 저장된 문단도 같은 배치 근거를 사용합니다.

표와 글줄은 각자 원본 순서를 유지하고, 셀의 세로 정렬과 다음 행은 그 점유 범위를 사용합니다. 편집으로 원본 글줄을 다시 계산했거나 표 상자가 일치하지 않으면 일반 흐름을 사용합니다. 합성 문서에서 표 아래 안내문과 다음 행의 한 번 표시, 선언 높이, 저장·재열기 및 저장 좌표 불일치 반례를 검사합니다.

### 개발 중인 33번 패치의 표 안 사진 분할

[패치 소스](rhwp-0.8.7-hwpx-parallel-picture-band.patch)는 HWPX 셀의 두 원본 문단에 걸친 사진을 처리합니다. 첫 글줄 뒤에 오는 사진 두 장의 저장 세로 좌표가 같은 배치 범위를 가리키고 가로 범위가 분리되어 있으면, 두 사진을 한 높이로 계산합니다. 두 사진을 모두 수용할 수 있는 쪽에서 함께 배치하며, 사진마다 원래 제어문자와 그리기 소유권을 유지합니다. 다음 쪽에서 그릴 때도 분할에 예약한 묶음의 시작 위치를 사용해 뒤 행과 겹치지 않도록 합니다. 가로 범위가 겹치거나 저장 좌표가 바뀐 경우는 기존 계산을 사용합니다.

합성 문서에서 두 사진이 모두 다음 쪽에 한 번씩 배치되는지, 테두리 안에 그려지는지, 후속 내용과 저장·재열기가 유지되는지 확인합니다. 사진의 가로 범위가 겹치는 반례도 비교합니다.

32·33번을 함께 적용한 실제 Pwh Desktop 인쇄 PDF에서 12쪽 안내문이 안쪽 표 아래로 복원됐습니다. 한컴 대비 안내문 상단 오차는 1.07pt이며, 다음 바깥 행의 시작점 오차는 125.86pt에서 1.22pt로 줄었습니다. 사진 두 장은 모두 13쪽에 한 번씩 배치됩니다. 두 사진 상단의 차이는 0.15pt이며, 가장 낮은 사진과 다음 행 사이에는 1.41pt가 남습니다.

12쪽의 일반 잉크 F1은 **65.01% → 78.02%**, 진한 글자·선 F1은 **43.99% → 62.55%**입니다. 13쪽은 일반 **53.40% → 92.53%**, 진한 글자·선 **41.58% → 88.50%**입니다. 1~11쪽은 r22와 픽셀 단위로 같습니다. 12쪽의 정규화 본문 문자 408개를 대조했고, 이 쪽의 아래선은 한컴보다 56.55pt 위에 있어 일치도 기준은 11쪽까지 통과했습니다. 전체 쪽 수는 Pwh 48쪽에서 47쪽으로 줄었으며, 한컴은 46쪽입니다.

별도 3개 문서 71쪽의 코어 인쇄 SVG와 텍스트 위치는 r22와 동일하고, 저장·재열기 결과도 유지됐습니다. 전체 코어 시험은 480건 통과, 환경별 제외 64건, 실패 0건입니다. 현재 배포판은 r20이며 이번 결과는 로컬 후보입니다.

[패치 소스](rhwp-0.8.7-hwpx-nested-rowspan-opening.patch)는 직접 작성된 HWPX의 자리 차지 중첩 표에서, 이미 시작된 세로 병합을 통과하는 행의 일반 셀을 원본 줄에서 나눕니다. 두 셀 이상에서 이어지는 글줄의 저장 세로 위치와 가로 범위가 맞고, 먼저 끝나는 셀도 첫 조각 안에 들어가야 합니다. 원본 표 높이에서 앞의 완전한 행들을 뺀 높이를 첫 조각에 사용합니다. 글자나 셀 속성이 다시 계산된 문서에는 저장 경계를 그대로 적용하지 않습니다.

### r14: 저장 프레임과 중첩 개체 소유권

Pwh 0.6.41과 Desktop 0.1.22는 같은 **r14** 코어를 사용합니다. `scripts/build-patched-core.mjs`는 고정 원본에 기존 열네 패치와 다음 네 패치를 순서대로 적용합니다. 열여덟 패치와 코어·연결부·편집기를 검증한 불변 런타임의 해시는 `runtime-lock.json`과 보존 아카이브에 기록합니다.

1. [`rhwp-0.8.7-stored-parallel-frame-minimum.patch`](rhwp-0.8.7-stored-parallel-frame-minimum.patch)는 빈 저장 호스트의 표 바깥 여백과 나란한 셀의 공통 선언 최소 높이를 실제 조각 상자에 보존합니다. 승인된 `source_parallel_frame`만 그리기·커서에 전달합니다.
2. [`rhwp-0.8.7-page-number-source-activation.patch`](rhwp-0.8.7-page-number-source-activation.patch)는 쪽 번호 설정이 실제 소유 조각의 원문 순서에서 시작하도록 합니다. 기존 번호 재시작·감추기·일반 글줄 판정은 유지합니다.
3. [`rhwp-0.8.7-stored-nested-float-frames.patch`](rhwp-0.8.7-stored-nested-float-frames.patch)는 중첩 개체의 첫 물리 프레임·자기 바깥 여백과 이미 소비한 형제 표 앵커를 측정·그리기에 일치시킵니다. 가시 호스트 줄 아래 float는 실제 한 줄·다음 원본 줄이 닫는 프레임·본문 용량을 함께 확인합니다. 현재 재조판의 공간 측정값은 원본 증거로 인정하지 않습니다.
4. [`rhwp-0.8.7-stored-nested-tail-owner.patch`](rhwp-0.8.7-stored-nested-tail-owner.patch)는 다음 쪽 행의 원문을 미리 소비하지 않도록 일반 스캐너·행 전체 수용·상위 표 커서가 같은 경계를 사용하게 합니다. 원래 행의 여백·중첩 위치·그림 문단 기준점을 유지하고, 그림 공간 속성 편집 뒤에는 해당 호스트의 저장 배치 캐시를 무효화합니다. [안정된 본문·소스 조건과 반례](STORED-NESTED-TAIL.md)를 참고하세요.

발생 위치는 **rhwp 조판 코어**입니다. 일부 float 표시 순서 문제는 Pwh r13 코어 패치의 회귀이며 수정 전 upstream 전체의 결함으로 설명하지 않습니다. Pwh·Desktop이 공유하는 WASM으로, Studio 메뉴나 Desktop 호스트에서 문서별 좌표를 보정하지 않습니다. 패치·단계별 소스 해시는 빌드 스크립트에 고정하며 원본 ZIP에 열여덟 패치를 적용해 재현합니다. [프레임 소유권](STORED-FRAME-OWNERSHIP.md), [중첩 개체의 조건·반례](NESTED-FLOAT-FRAMES.md)를 참고하세요.

소스 함수 시험은 원본 프레임 19건, 쪽 번호 22건, 닫힌 float 33건, 형제 오프셋 9건, 중첩 개체 프레임 18건으로 구분합니다. 합성 시험은 원문 소유 범위·여백·편집·실행 취소·실제 SVG 클립을 확인하며 기관 문서를 포함하지 않습니다. 새 원문 소비 조건 87건도 원본 Rust 함수로 검사했습니다. 정식 코어의 실제 전체 PDF에서 **1~7쪽**은 고정 기준과 별도 감사를 순차 통과했습니다. 다음 검증 대상은 **8쪽**이며 전체 39쪽 품질 승인을 뜻하지 않습니다. [쪽별 점수와 한계](../LAYOUT-FIDELITY.md#r14-source-frame-candidate)를 함께 확인하세요.

### r13: 혼합 문단의 표·본문 순서와 프레임 점유

`rhwp-0.8.7-mixed-block-flow-ledger.patch`는 r12 뒤에 추가하는 **rhwp 원천 코어** 패치입니다. 계산과 일반·부분 셀의 배치가 같은 명시적 자식 분할 단위 순서를 사용합니다. 단일 위아래 배치 표가 원문 글의 앞·뒤에 있는 경우에 적용하며 중간 앵커, 겹침 개체, 여러 컨트롤은 기존 경로를 유지합니다. 컨트롤 텍스트 위치는 문자 인덱스이므로 UTF-16 저장 길이와 혼용하지 않습니다.

`CELL`의 용량에 따른 분할은 저장 프레임의 강제 쪽 나눔과 별개입니다. 교차 행 병합을 기존 경로에 두고, 실제 저장 프레임을 가진 행의 선언 높이에 포함된 빈 공간을 자식 단위에 다시 배분하지 않습니다. 글줄 선택 범위가 없어도 해당 조각의 자식 행 범위가 있으면 표를 배치합니다. 원문의 글·글꼴·여백·선언 셀 높이·클리핑 정책은 바꾸지 않습니다.

Pwh 0.6.40과 Desktop 0.1.21의 최종 런타임은 r13이며 총 열네 패치를 적용합니다. r12는 중간 검증 후보이며 별도로 공개 배포하지 않았습니다. 정확한 변경 전후 해시와 ABI 검사는 `scripts/build-patched-core.mjs`와 코어 `BUILD-RECORD.json`에 보존합니다. 시험용 진단 API는 배포 코어에 포함하지 않습니다.

긴 중첩 표 PDF는 43 → 39쪽(한컴 39쪽), F1 53.1177% → 66.8308%, 진한 글자·선 42.6597% → 53.6753%로 개선됐습니다. 쪽 수가 같아도 일부 배치 차이가 남습니다. 다른 문서의 71쪽 인쇄 SVG는 유지합니다. [측정 범위와 한계](../LAYOUT-FIDELITY.md#r13-mixed-block-flow), `tests/mixed-block-source-order.test.mjs`, `tests/nested-declared-row-pagination.test.mjs`를 함께 확인하세요.

### r12: 저장된 중첩 행의 분할과 인라인 개체 줄

`rhwp-0.8.7-nested-declared-frame-cuts.patch`는 **rhwp 원천 코어**의 중첩 표 분할을 보완합니다. 기존 열두 패치에 추가하며 Pwh와 Desktop이 같은 WASM을 사용합니다.

- 빈 문단에 담긴 단일 위아래 배치 표도 혼합 문단과 같은 자식 분할 커서를 전달합니다. 선언 높이가 있는 행이라도 실제 저장 줄이 다음 프레임으로 이어지면, 일반 글과 안쪽 표를 가진 셀의 일부를 남은 공간에 넣을 수 있습니다. 수정되었거나 합성된 좌표로 저장 경계를 새로 증명하지 않으며, 행을 가로지르는 병합은 기존 경로를 유지합니다.
- 부모의 분할 후보에는 자식의 실제 시작·끝 커서를 기록합니다. 기존 일반 텍스트 소유자 동기화 판정을 빈 호스트에서도 사용해, 저장된 프레임 경계를 지나 뒤쪽 원문을 미리 소비하지 않게 합니다. 임의의 셀 좌표 재시작이나 새 컨트롤 호스트를 물리 쪽 경계로 승격하지 않습니다.
- 빈 문단의 인라인 표가 하나의 실제 저장 줄 상자 안에 온전히 들어 있으면, 그 개체 줄을 하나의 분할 단위로 유지합니다. 내부 표의 첫 행만 앞 쪽에 떼어 넣지 않습니다. 저장 줄 상자가 전체 표보다 작거나 줄 배치가 없거나 편집된 경우에는 기존 재귀 분할을 유지합니다. 캡션이 있는 개체도 기존 경로를 유지합니다.

선언 셀 높이·글꼴·여백·원문 텍스트와 클리핑 정책은 바꾸지 않습니다. 특정 문서 이름이나 쪽 번호에 따른 분기는 없습니다. `tests/nested-declared-row-pagination.test.mjs`는 남은 공간 사용, 원문 셀 주소, 크기 보존, 내보내기·재열기·편집·실행 취소와 저장된 인라인 줄의 완전·불완전 상자를 검사합니다. 사용자 원문은 공개 시험에 포함하지 않습니다.

중간 r12 후보는 총 열세 패치를 적용했습니다. 코어 WASM은 13,782,475바이트이며 SHA256은 `1349c8d702e0c966a47236531fc0129a6c09234975b0bd1d002880d28515bd61`입니다. JavaScript 연결부는 기존 ABI와 같은 `e4b17c467ec6e5955393f7b9b162150ea0f16271085dcec7955bcd87c0014d47`입니다. 새 패치의 SHA256은 `54d274f77865dc18586d6726558394a47b28bbb304d075318d61ea9ea9037d87`이고, 수정된 `table_layout.rs`의 최종 해시는 `d2c51ac55b1b560f7ab6c965ba0837332c7e72012e42fcaad88eaa0f99128dbf`입니다. 고정 입력·연쇄 적용 전후 해시는 `BUILD-RECORD.json`으로 검증합니다.

긴 중첩 표 PDF 비교는 F1 53.1177% → 61.0154%, 진한 글자·선 42.6597% → 49.3457%이며 43쪽이 41쪽으로 줄었습니다. 한컴 기준은 39쪽이라 쪽 흐름 차이가 남습니다. 다른 65·4·2쪽의 인쇄 SVG 71개는 r11과 동일했습니다. [PDF 비교 방법](../RENDER-COMPARISON.md#pdf-comparison)를 함께 확인하세요.

### 저장 쪽 원점과 빈 중첩 표 호스트

r11은 기존 열 패치 뒤에 두 **rhwp 원천 코어** 패치를 추가합니다. Pwh와 Desktop은 같은 WASM과 일치하는 JavaScript 연결부로 빌드합니다.

- rhwp-0.8.7-stored-page-leading-margin.patch: 첫 줄의 앞 간격과 다음 줄까지의 높이·줄 간격·앞뒤 간격을 함께 확인합니다. 다음 앞 간격 0과 명시적 쪽 나눔도 처리합니다. 전체 바깥 상자가 확인되는 첫 TAC 표는 같은 앞 간격을 측정·렌더에 전달하며, 메모·구역 설정 같은 폭 중립 부호를 허용합니다. 첫 호스트 개체 뒤에도 검증한 쪽 원점을 유지합니다. 합성·편집·다른 쪽·불일치 사다리와 별도 개체 원점은 구분하고, 큰 정수의 차는 넓은 정수로 계산합니다.
- rhwp-0.8.7-stored-nested-block-host.patch: 셀 원점에 저장된 단일 빈 호스트 문단의 단일 위아래 배치 표에서는 글줄과 표가 같은 점유 상자를 소유합니다. 높이 측정의 합산을 큰 쪽의 높이로 바꿔 이미 같은 상자를 쓰는 분할 원장·렌더와 맞춥니다. 가시 글·추가 문단·편집된 호스트·오프셋·겹침 표는 기존 경로를 유지합니다. 저장된 셀 크기는 바꾸지 않습니다.

공개 회귀는 tests/stored-page-margin.test.mjs, tests/stored-nested-block-host.test.mjs에 있습니다. 첫 표·도형·메모, HWP·HWPX 재열기, 부모 셀과 자식 표의 상자·쪽 경계·원문 크기 보존과 반례를 검사합니다. 65쪽 PDF의 전체 F1은 95.4732% → 97.4468%, 진한 글자·선은 93.3195% → 95.6349%입니다. 6쪽 개선·59쪽 유지·악화 0쪽이며, 43쪽의 후속 표 간격 등은 남아 있습니다. [측정 조건과 한계](../LAYOUT-FIDELITY.md)를 함께 확인하세요.

### r9·r10의 유지 범위

r10은 아래 r9 코어와 같은 WASM·JavaScript 연결부를 사용합니다. 변경은 Pwh·Desktop 번들의 경로 정규화, 빌드 입력 기록과 CI 재현 검사에 있으며 Rust 패치는 추가하지 않았습니다.

Pwh 0.6.38과 Desktop 0.1.19의 린트·엄격한 타입 검사 보완도 기존 r10 런타임을 유지합니다. 공통·Desktop 편집기 JavaScript는 이전 배포본과 바이트까지 같으며, Pwh 어댑터와 빌드 선언의 타입을 정리했습니다. [정적 검사 범위](../STATIC-CHECKS.md)를 참고하세요.

### 저장 프레임·기본 글머리표·도형 속성

r9는 기존 일곱 패치 뒤에 다음 세 패치를 적용합니다. 모두 **rhwp 원천 코어** 변경이며, Pwh와 Desktop의 같은 편집기 WASM을 사용합니다.

- `rhwp-0.8.7-closed-float-successor-frame.patch`: 빈 호스트 표의 lane 경로도 기존 `stored_empty_control_table_frame`이 확인한 다음 문단 원점을 유지합니다. 측정한 표 높이와 바깥 여백이 저장된 다음 줄 위치를 정확히 닫고, 단·편집 상태·재조판·겹침·쪽 예산이 맞을 때만 사용합니다. 저장된 셀 크기나 원문은 바꾸지 않습니다.
- `rhwp-0.8.7-implicit-bullet-marker.patch`: `BULLET`의 참조 0에 내장 원형 글머리표와 본문 글자 모양을 사용합니다. 명시 참조 1을 대신 쓰지 않으며 잘못된 비영 참조에는 글머리표를 새로 만들지 않습니다.
- `rhwp-0.8.7-shape-fill-transparency.patch`: HWPX 채움의 0~255 투명도 바이트를 읽고 같은 값으로 저장합니다. `ShapeStyle.fill_opacity`를 별도로 두어 채움 때문에 윤곽선까지 사라지지 않게 하며 Canvas·SVG·그리기 JSON과 관련 Skia 경로에 전달합니다. 둥근 사각형은 짧은 변에 비율을 적용하고 반지름을 절반으로 제한합니다.

이 변경에는 문서 이름·기관명·쪽 번호·특정 문단 번호를 이용한 분기가 없습니다. [조판 일치 검증](../LAYOUT-FIDELITY.md)과 `tests/stored-float-frame.test.mjs`, `tests/shape-fill-transparency.test.mjs`가 범위와 반례를 설명합니다.


### 각주·미주의 커서·클릭·삭제 주소

`rhwp-0.8.7-note-cursor-source-offsets.patch`는 **rhwp 원천 코어**의 본문 주석 참조를 보완합니다. 화면에 보이는 번호와 조판부호는 여러 글자 폭이지만, 원문에서는 하나의 논리 컨트롤 슬롯입니다. 기존 클릭 경로는 이 표시를 본문 글자처럼 읽거나 주석 슬롯을 빠뜨리고, 삭제 조회는 논리 주소 대신 순수 텍스트 위치를 사용했습니다. 서로 다른 주소 체계 때문에 주석 뒤를 클릭해도 앞의 본문이 지워질 수 있었습니다.

주석 번호·부호에 컨트롤 인덱스와 논리 위치를 연결하고, 문장 중간의 부호도 실제 주석 옆에서 생성합니다. 커서 조회·클릭·키보드 삭제가 같은 경계를 사용합니다. 표시 문자열을 검색해 원문 대상을 추측하지 않습니다. 주석 삭제 시에는 기존 `Paragraph::control_utf16_positions`로 개별 원본 컨트롤의 시작 위치를 구해 글자 모양과 범위 정보를 이동합니다. 문단 끝에 주석이 있을 때 위치를 0으로 간주해 이전 서식이 무너지는 경우도 포함합니다.

코어의 논리 위치와 Studio 본문 편집 API의 순수 글자 위치는 별도 계약입니다. Pwh 공통 편집기에서 기존 변환 API로 두 좌표를 연결하고 주석 바로 앞·뒤의 방향을 보존합니다. 주석 옆 글자의 실행 취소에는 기존 문단 조각 복원을 사용해 원문 컨트롤 위치와 서식을 함께 복원합니다. 이 연결은 WASM 소스 패치와 구분되는 Studio 빌드 변경이며 [편집기 검증](../EDITOR-PERFORMANCE.md)에 설명합니다.

이 보완은 본문의 각주·미주 참조에 적용하며, 표 셀 내부 주석 편집 전체를 새로 지원한다는 뜻은 아닙니다. 문장 앞·중간·끝, 조판부호 표시·숨김, 여러 주석, 인접 본문·혼합 글자 서식·저장 후 주소를 합성 문서로 검사합니다. 실제 입력의 삭제 확인·취소·실행 취소는 공통 편집기 브라우저 검사로 구분합니다. 원본 기준과 소스 변경 전후 해시는 `scripts/build-patched-core.mjs` 및 배포 코어의 `BUILD-RECORD.json`에 보존합니다.

### 문단 중간의 떠 있는 표 위치

`rhwp-0.8.7-interior-float-anchor.patch`는 한 줄의 보이는 텍스트 사이에 떠 있는 표가 들어간 경우, 앞뒤 글자와 표의 실제 문자 오프셋을 확인한 뒤 해당 줄의 저장된 위치 또는 계산된 위치를 표의 호스트로 사용합니다. 문자 오프셋이 불완전하거나 여러 줄에 걸치는 경우, 겹침 여부가 확실하지 않은 경우에는 기존 경로를 유지합니다. 특정 문서의 이름이나 좌표를 기준으로 보정하지 않습니다.

제공받은 4쪽 HWP 문서는 한글에서 출력한 PDF와 새 엔진의 출력을 겹쳐 확인했습니다. 3쪽의 두 번째 표와 앞 문단 간격이 가까워졌고 나머지 세 쪽의 비교 결과는 이전과 같았습니다. 글꼴 및 출력 방식의 차이는 남아 있으므로 이것이 모든 문서의 동일한 조판을 보장하지는 않습니다. 원본·출력물은 공개 패치에 포함하지 않습니다. 합성 문서의 중첩 표 및 줄 나눔 회귀 검사도 통과했습니다.

높이 측정 단계에서는 줄바꿈한 텍스트에 맞게 행을 늘리고, 표 전체 높이를 유지하기 위해 다른 행의 여유 공간을 회수할 수 있습니다. 이후 `LayoutEngine::trust_declared_row_heights`는 행 높이의 합이 같고 차이가 기존 허용 범위 안에 있으면 각 행의 원래 높이를 복원할 수 있습니다. 저장된 LINE_SEG 정보가 없는 생성 HWPX는 ViewText 내용 격자로 판정될 수 있습니다. 이때 지정된 높이를 복원하면 표 전체 높이는 그대로여도 실제 내용에 필요한 최소 높이가 사라질 수 있습니다.

`rhwp-0.8.7-nols-row-content-floor.patch`는 높이를 복원하기 전에 조건을 한 번 더 확인합니다. 높이가 줄어들 가로쓰기 NO_LS 셀에 대해 렌더러의 기존 기준 너비, 안쪽 여백, 줄바꿈 및 내용 높이 계산을 재사용합니다. 내용과 여백이 지정된 행 높이에 들어가지 않으면 측정된 행 높이를 유지합니다. 내용이 들어가는 ViewText 격자, 저장된 배치 정보가 있는 셀, 높이가 줄지 않는 행에는 기존 보정을 그대로 사용합니다. 세로쓰기도 변경하지 않습니다. 패치에는 특정 문서 ID, 기관명, 글꼴, 행 개수 또는 셀 번호를 넣지 않았습니다.

첫 번째 패치는 `src/renderer/layout/table_layout.rs`만 변경합니다. 보조 함수에는 유일한 호출 위치에서 기존에 해석한 스타일을 전달합니다.

두 번째 패치 `rhwp-0.8.7-inline-table-affect-line-spacing.patch`는 `affectLSpacing` 속성이 켜진 새 인라인 표 뒤의 간격을 보완합니다. 기존 대체 경로는 퍼센트 줄 간격을 항상 표를 담은 문단의 글꼴 높이로 계산했습니다. 그 밖에 내용이 없는 문단에 표 하나만 있는 경우에는 이 속성에 따라 개체 줄 상자(표 높이와 위·아래 바깥 여백)를 퍼센트 계산의 기준으로 사용합니다. 현재 검증된 기준은 저장된 개체 줄의 배치 정보로 확인한 **지정 표 프레임**(`table.common.height`와 바깥 여백)입니다. 셀 내용이 늘어난 뒤 달라진 측정 높이는 이 보조 함수에서 추정하지 않습니다. 검증된 원래 배치에서 해당 속성을 무시하면 다음 문단이 한컴 한글보다 표에 지나치게 가깝게 그려질 수 있습니다.

`src/renderer/mod.rs`의 보조 함수가 표 내용 높이와 추가 간격을 제공합니다. `src/renderer/composer/line_breaking.rs`는 다음 문단들의 세로 위치를 누적하기 전에, 새 호스트의 합성 LINE_SEG를 만들면서 이 간격을 기록합니다. 이후 높이 측정, 조판, 그리기 및 커서 위치 조회가 같은 계산 위치를 사용할 수 있습니다. 뒤쪽 대체 경로만 바꾸는 것으로는 충분하지 않습니다. 가져오기 과정에서 이미 글꼴 기준 간격의 합성 호스트 구간을 만들 수 있기 때문입니다. 해당 구간이 없거나 다시 생성될 때는 `src/renderer/layout.rs`의 기존 표 호스트 측정 대체 경로와 그리기 흐름도 같은 보조 함수를 사용합니다. DPI는 호출 측에서 전달합니다.

이 변경은 다음 조건을 모두 만족할 때 적용됩니다. **실제로 저장된** LINE_SEG가 없고, 문단 텍스트가 없으며, TAC 표가 정확히 하나이고, `affectLSpacing=1`이며, 퍼센트 줄 간격이 100%를 초과해야 합니다. 기존 합성 태그 판별로 식별되는 내부 생성 구간은 계속 적용 대상입니다. 개체 줄 프레임이 호스트 글꼴 높이보다 클 때만 적용합니다. 속성이 꺼진 경우, 실제 저장 LINE_SEG, 작은 개체, 혼합 컨트롤, 보이는 텍스트, 100% 간격 및 다른 간격 방식은 기존 경로를 유지합니다. 그림과 도형의 측정값도 변경하지 않습니다. 바깥 여백은 퍼센트 기준에 한 번만 포함합니다. 흐름 계산이 여백을 별도로 반영하므로 보조 함수의 내용 높이에서는 제외합니다. 기존 표 배치 진행량 뒤에 간격을 중복해서 더하지 않습니다.

차이에 포함된 원본 코드와 주석은 원래 저작자 표시를 유지합니다. rhwp의 저작권은 Edward Kim과 기여자에게 있으며 MIT 라이선스로 배포됩니다. 소스 ZIP의 `LICENSE`, 저장소의 `THIRD_PARTY_NOTICES.md` 및 원본 프로젝트 <https://github.com/edwardkim/rhwp>를 참고하세요.

### 중첩 표의 원문 소유 범위

`rhwp-0.8.7-nested-source-ownership.patch`는 기존 자식 `RowCut` 경로를 첫 번째 컨트롤 위치에 비인라인 `TopAndBottom` RowBreak 표 하나가 있는 혼합 문단으로 확장합니다. 호스트 텍스트는 자신의 줄, 간격 및 나눔 단위를 유지합니다. 자식 행·셀 커서는 고정 높이의 단순 조각에서 다시 구성하지 않고 부분 배치에 전달합니다.

자식 분할은 남아 있는 보이는 내용의 소유 범위가 원래 일반 텍스트 문단의 재시작 위치에서 시작할 때에만 저장된 원문 프레임 경계를 사용할 수 있습니다. 이미 끝난 라벨 셀은 다음 페이지의 이어지는 내용을 소유하지 않습니다. 중첩 컨트롤 조각, 합성되었거나 오래된 줄 배치, 지원하지 않는 병합 범위 및 소유 범위가 불분명한 경우에는 그 권한을 부여하지 않습니다. 표는 유형이 지정된 표 단위를 포함한 분할에서만 그립니다. 일반 호스트 텍스트가 같은 블록 표를 다시 그리지 않습니다.

저장된 문단에서 유형이 지정된 자식 실행 구간은 선택된 자식 `RowCut`의 실제 높이도 확보하며, 각 조각의 셀 안쪽 여백을 포함합니다. 실행 구간에 자식 분할의 명시적인 출처가 있으면 자리 표시용 시각 줄이 있는 빈 호스트도 포함합니다. 완전한 행은 부분 행 분할과 같은 실행 구간을 공유할 수 있습니다. 자리 표시용 줄 범위만으로는 실제 높이 확보를 승인하지 않습니다. 같은 확보 높이를 쪽 나눔과 부분 행 렌더링에 사용합니다. 이전에는 부모가 원문 단위에서 투영한 높이만 예약하는 동안 자식은 안쪽 여백도 그려 내부 테두리가 부모 프레임 아래로 내려갈 수 있었습니다. 분리된 혼합 호스트 텍스트 단위는 문단 간격을 유지하고, 빈 호스트는 기존 가장자리 간격의 소유 범위를 유지합니다. 유형이 지정되지 않은 저장 스칼라 투영은 기존 경로를 사용합니다. 고정된 여백이나 픽셀 보정은 추가하지 않습니다.

이 패치는 계산된 쪽 나눔과 렌더링을 바꾸면서 원문 텍스트와 원본 커서 주소를 유지합니다. 저장된 셀 크기를 바꾸거나 보기 설정으로 넘친 내용을 가리지 않으며, 특정 문서나 쪽 식별자를 포함하지 않습니다.

## 별도의 후보 코어로 재빌드

`scripts/build-patched-core.mjs`는 모든 경로를 인수로 받습니다. 유지 관리자의 홈·작업 공간 경로를 사용하거나, 런타임을 설치하거나, 엔진 잠금 파일을 수정하거나, 기존 소스·출력 디렉터리를 덮어쓰지 않습니다. 패치를 적용하기 전에 소스와 패치를 검증하고 예상하지 않은 소스 리비전은 거절합니다. r20 소스는 스물아홉 패치를 기록된 순서대로 적용합니다. r17의 스물여섯 패치와 앞선 런타임 기록은 각 릴리스에 보존합니다. Windows의 전역 `core.autocrlf` 설정이 소스 해시를 바꾸지 않도록 패치를 적용할 때 Git의 줄바꿈 변환을 명시적으로 끕니다.

저장소를 내려받고 필요한 입력과 도구를 로컬에 준비한 뒤 실행하는 예입니다.

```powershell
$env:RUSTUP_TOOLCHAIN = '1.93.1-x86_64-pc-windows-gnu'
node scripts/build-patched-core.mjs `
  --source-archive C:\pwh-inputs\pwh-upstream-rhwp-0.8.7-1a76570e8339.zip `
  --blank-template C:\pwh-inputs\blank2010.hwp `
  --source-root C:\pwh-rebuild\source `
  --output-root C:\pwh-rebuild\candidate-core `
  --wasm-bindgen C:\pwh-tools\wasm-bindgen.exe
```

Node.js 22.12 이상, Python 3.11 이상, Git과 고정된 Rust 도구가 PATH에 있어야 합니다. 또는 `--python`, `--cargo`, `--rustc`, `--wasm-bindgen`으로 경로를 지정할 수 있습니다. `RUSTUP_HOME`과 `CARGO_HOME`은 상속되며 격리된 빌드 환경을 가리킬 수 있습니다. `--target-dir`로 기존 컴파일 캐시를 재사용할 수 있습니다. `--offline`은 Cargo의 의존성 다운로드를 막으므로 필요한 의존성이 이미 있어야 합니다. `--prepare-only`는 컴파일러를 실행하지 않고 소스·해시·패치·작업 공간·양식을 준비합니다. 실행할 때마다 새로운 소스·출력 경로를 선택하세요. 실패한 후보 디렉터리는 삭제하지 않고 검토용으로 보존합니다.

실제 빌드 명령은 다음과 같습니다.

```text
cargo build --lib --target wasm32-unknown-unknown --release
wasm-bindgen --target web --out-name rhwp --out-dir <candidate-core> <target>/wasm32-unknown-unknown/release/rhwp.wasm
```

원본의 기본 기능을 유지하며, 요청한 경우에만 `--offline`을 추가합니다. Cargo 의존성과 Rust·wasm-bindgen 설치 파일은 이 스크립트에 포함되지 않습니다. 따라서 고정된 입력으로 재현하는 절차이며, 모든 도구가 포함된 완전한 오프라인 도구 체인이라는 뜻은 아닙니다.

<a id="workspace-and-dependency-lock-handling"></a>
## 작업 공간과 의존성 잠금 파일 처리

보존된 소스 ZIP에는 원래 작업 공간 목록에 이름이 남아 있는 독립 `tools/` 프로젝트가 없습니다. 스냅샷을 그대로 빌드하면 없는 작업 공간 manifest를 해석하는 과정에서 실패합니다. 이 WASM 라이브러리 빌드에서는 루트 작업 공간의 `members`만 `[".", "crates/*"]`로 제한하고, `default-members`, 루트 의존성 선언 및 각 크레이트 manifest는 유지합니다. 제외되는 구성원은 `tools/rhwp-subsecond`, `bindings/Native`, `tools/batch-convert` 및 세 개의 `tools/llm_verifier` 프로젝트입니다.

첫 빌드는 의도적으로 `--locked`를 사용하지 않습니다. 제외한 작업 공간 구성원에게만 필요한 잠금 항목을 Cargo가 정리해야 하기 때문입니다. 빌드 직후 스크립트는 Python의 TOML 파서로 결과 잠금 파일과 원본 ZIP의 잠금 파일을 비교합니다. 패키지가 추가되거나 유지된 패키지의 전체 잠금 레코드에서 버전, 소스, 체크섬 또는 의존성 목록이 하나라도 달라지면 **후보를 거절합니다**.

검증된 빌드에서는 원래 408개 패키지 레코드가 373개로 정리됐습니다. 35개가 삭제되고, 추가는 0개, 유지된 레코드의 변경도 0개였습니다. 여기에는 로컬 작업 공간 패키지 6개와 더 이상 쓰지 않는 레지스트리 의존성의 제거가 포함됩니다. 유지된 의존성의 버전은 갱신하지 않았습니다. 정리된 `Cargo.lock`의 SHA256은 `775639086168903cd7b5978704decf498aac7235b6a5e89c5a4fe8be325b3b06`입니다. 이 파일은 빌드 작업 공간에서 생성한 결과물이며 원본의 잠금 파일을 대체하지 않습니다.

<a id="output-and-release-boundary"></a>
## 산출물과 배포 범위

스크립트는 생성된 `.wasm`, JavaScript 연결 코드, 타입 선언, 원본 라이선스와 입력·출력 해시, 도구 버전, 잠금 파일 감사 결과가 담긴 `BUILD-RECORD.json`을 출력합니다. r9의 Canvas 상태 복원은 생성된 연결 코드에 `globalAlpha` 읽기를 추가합니다. 빌드 스크립트의 `expectedGlueSha256`은 이 정확한 생성 결과를 고정하며, 공통·Desktop 인라인 편집기도 같은 연결부로 다시 빌드합니다. 보존 스크립트는 호스트 WASM 로더 한 곳만 정규화한 뒤 전체 연결부 해시가 새 코어와 일치하는지 검사합니다. 과거 r8의 연결부와 같다고 표기하지 않습니다.

독립적으로 반복한 **첫 번째 패치만 적용한** 빌드는 13,751,774바이트이고 SHA256은 `2af00b34b622b33d341d0be5a78f00d56dcd50d74fddca1ec71dd5d5474af907`입니다. 이는 행 최소 높이 보완의 과거 검증 기록입니다. 현재 재빌드 스크립트는 스물일곱 패치의 입력·출력 소스 해시를 `BUILD-RECORD.json`에 기록하며, 27번에서 추가한 WASM API와 JavaScript 연결 코드의 해시도 확인합니다.

검증된 **두 패치 운영 빌드**는 13,752,323바이트이고 SHA256은 `a9c082330122e79120f8e0976f94837cc62625261fbb77c2fa2f51d6cb3e09d8`입니다. 그 정확한 산출물에 대해 두 합성 WASM 검사 모음이 모두 통과했습니다. 행 안에 내용이 들어가는지, 저장된 간격 대조군, 표 뒤 텍스트 커서 위치, 연속된 표와 쪽 경계를 포함해 25개 통과, 0개 실패, 0개 건너뜀입니다. 재빌드할 때마다 실제 해시를 기록하고, 컴파일러 경로나 빌드 환경 차이가 생기면 같은 빌드로 임의 표기하지 말고 원인을 확인해야 합니다.

패키징 전에 재빌드한 코어로 합성 회귀 테스트 자료를 실행하세요. 줄바꿈한 NO_LS 행에 내용이 들어가고, 내용이 들어가는 행은 기존 보정을 유지해야 합니다. 내보내고 다시 열었을 때 문서 내용과 원본 셀 높이가 유지되고, 스냅샷 실행 취소로 원래 상태가 복원되어야 합니다. 컴파일 성공이나 패치 해시 확인만으로 렌더링이 검증되는 것은 아닙니다.

인라인 표 간격은 표 높이, 바깥 여백, 속성 켜짐·꺼짐과 퍼센트 설정을 각각 바꿔 비교합니다. 기존 배치가 유지되는지 확인할 수 있도록 100% 대조군과 저장 LINE_SEG 대조군을 포함합니다. 내보내기·다시 열기 후 보존 및 쪽 경계 사례와 함께, 뒤따르는 문단의 표시 위치와 커서 위치를 모두 확인합니다. 공통 줄 상자 계산을 특정 문서에만 맞춘 픽셀 보정으로 대체하지 않습니다.

후보 코어를 지정해 두 검사 모음을 실행합니다.

```powershell
$env:PWH_CORE_JS = 'C:\pwh-rebuild\candidate-core\rhwp.js'
$env:PWH_CORE_WASM = 'C:\pwh-rebuild\candidate-core\rhwp_bg.wasm'
node --test tests/rowbreak-table-height.test.mjs tests/tac-table-line-spacing.test.mjs
```

이 테스트 자료에는 합성 텍스트와 배치 정보만 있습니다. 사용자 문서, 기관 보고서, 원본 문서 경로 또는 연구 원고는 포함하지 않습니다. 두 환경 변수를 모두 지정하지 않으면 코어 의존 검사가 건너뛰어지며, 건너뛴 실행은 후보 엔진을 검증한 것이 아닙니다.

수정한 코어를 배포할 때는 **새로운 불변 엔진 리비전**, 별도의 출처 정보 및 런타임 manifest가 필요합니다. engine-r2와 원래 npm 코어 바이트를 유지하세요. `scripts/preserve-engine.py`가 원래 코어가 바뀌지 않았는지 확인하는 조건을 우회하거나, 변경된 바이트를 기존 식별자로 허용하도록 바꾸면 안 됩니다. 패치한 리비전은 명시적인 배포 절차로 준비·검증합니다. 재빌드 스크립트는 이를 게시하거나 `runtime-lock.json`을 수정하지 않습니다.

<a id="preserve-a-later-patched-runtime"></a>
## 이후 패치 런타임 보존

`scripts/preserve-engine.py`는 원본 바이너리를 보존하며 최초 소스·라이선스 보존에 계속 사용합니다. 패치된 코어를 패키징하기 위해 원래 코어 검사를 약화해서는 안 됩니다.

`scripts/preserve-patched-runtime.py`는 이전 불변 런타임 아카이브와 전체 manifest, 새로 최적화한 코어의 `BUILD-RECORD.json`, 현재 패치의 모든 해시, 버전이 지정된 인라인 클라이언트 파일의 해시를 검증합니다. 인라인 빌드에서 호스트가 제공한 WASM을 찾는 부분도 정규화해 나머지 JavaScript 연결 코드가 재빌드한 코어와 정확히 일치함을 확인합니다. 통과한 회귀 검사 근거는 정확한 WASM 및 빌드 기록 다이제스트를 식별해야 합니다. 스크립트는 새 출력 디렉터리에 새 런타임 ZIP, 소스·빌드 입력 아카이브, 검증 기록 및 제안된 잠금 파일을 생성합니다. 프로젝트의 잠금 파일이나 설치된 런타임에는 쓰지 않습니다.

코어와 인라인 클라이언트 회귀 검사를 완료한 뒤 실행하는 예입니다.

```text
python scripts/preserve-patched-runtime.py --base-lock <preserved-r3-runtime-lock.json> --base-archive <verified-r3.zip> --candidate-core <optimized-core> --client-root client --client-build-root <studio-build-root> --regression-evidence <passing-core-regression.json> --revision 4 --output-dir <new-r4-output>
```

현재 Pwh와 Desktop 인라인 클라이언트는 새로운 공통 코어를 사용합니다. 별도로 보존한 과거 전체 Studio 구성 요소는 기본적으로 이전 바이트를 유지합니다. 묶여 있는 WASM은 ABI가 일치할 것이라는 추측만으로 교체하면 안 됩니다. 전체 교체에는 선택적 `--studio-replacement`와 `--studio-verification` 입력을 통해 명시적인 트리 해시와 스모크 테스트 근거가 필요합니다. 이 적용 범위는 manifest와 검증 파일에 기록합니다. 기존 원본 소스, 의존성 및 라이선스 자산은 변경되지 않는 기존 URL을 유지합니다.
