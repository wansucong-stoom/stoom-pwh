## PDF 출력 비교

같은 HWP 또는 HWPX 문서를 한컴 한글과 Pwh에서 각각 출력한 결과를 겹쳐서 비교할 수 있습니다. 도구는 원본과 두 출력물을 읽기만 하며, 결과는 새 폴더에 저장합니다.

1. 한글에서 원본을 열고 PDF로 출력합니다. Pwh에서도 같은 원본을 열고 실제 인쇄 경로로 PDF를 출력합니다. 최종 대조는 두 PDF를 같은 렌더러로 이미지화하는 방법을 우선하며, 화면용 쪽 이미지는 보조 진단으로 사용할 수 있습니다.
2. Python 3.11 이상에서 `python -m pip install -r requirements-render-compare.txt`로 검증된 의존성을 준비합니다. 이미지 출력은 `page-0001.png`부터 빠짐없이 번호를 붙인 폴더나 다중 페이지 TIFF로 전달할 수 있습니다. 두 이미지 출력의 해상도는 같아야 합니다.
3. 아직 존재하지 않는 결과 폴더를 지정해 실행합니다.

```powershell
python scripts/compare-pages.py --source "원본.hwpx" --hancom "한글.pdf" --pwh "Pwh.pdf" --dpi 150 --out "비교결과"
```

특정 쪽만 보려면 `--pages 1,3,5-7`을 추가합니다. 각 겹침 이미지에서 빨강은 한글에만 나타난 위치, 파랑은 Pwh에만 나타난 위치, 회색은 일치 위치, 주황은 가까운 차이를 뜻합니다. `report.json`에는 파일 해시, 쪽 수, 설정과 쪽별 차이가 기록됩니다. 두 출력물이 정말 같은 원본에서 생성됐는지는 사용자가 확인해야 합니다.

PDF는 둘 다 같은 `--dpi`로 렌더링합니다. 이미지는 원래 픽셀 크기를 유지합니다. 페이지 원점 이동·크기 맞춤·다른 쪽으로의 대응은 하지 않습니다. 한글 PDF의 용지 반올림은 1포인트 이하인 경우에만 가장자리를 흰색으로 채워 처리합니다. 이미지 폴더의 해시는 순서대로 정렬한 쪽 파일명과 내용으로 계산하며, 글꼴·프로필·기타 진단 파일은 읽지 않습니다.

기본 명도 임계값은 245이고 위치 허용 오차는 2픽셀입니다. `tolerantInkPrecision`은 Pwh의 글자·선·채움 픽셀 중 기준의 허용 범위 안에 있는 비율, `tolerantInkRecall`은 기준 픽셀 중 Pwh의 허용 범위 안에 있는 비율입니다. `tolerantInkF1`은 두 비율의 조화평균입니다. 전체 점수는 쪽별 퍼센트의 단순 평균이 아니라 전체 픽셀 수로 계산합니다. 흰 여백은 점수를 높이지 않으며, 누락·추가 쪽의 잉크는 일치하지 않는 것으로 포함합니다. `exactInkF1`은 위치 허용 오차 없이 계산합니다. 크기 불일치 등으로 비교하지 못한 쪽이 있으면 `aggregate.complete`가 false이므로 전체 일치율로 해석하지 않습니다.

원문 글자나 색상이 같은지, 셀과 문단의 편집 주소가 보존되는지까지 이 점수가 증명하지는 않습니다. 허용 오차를 바꾸면 점수도 바뀌므로 전후에는 동일한 설정을 사용하고, 오차가 큰 쪽의 겹침 이미지와 합성 회귀 검사를 함께 확인합니다. 검증 예와 남은 범위는 [조판 일치 검증](LAYOUT-FIDELITY.md)에 있습니다.

겹침은 글자와 선의 위치를 빠르게 찾기 위한 도구입니다. 글꼴·안티앨리어싱·PDF 출력 방식에 따라서도 색이 나타나며, 수치가 문서의 정확도를 보증하지는 않습니다. 색상이나 편집 가능 여부도 별도로 확인해야 합니다. 원본 문서와 비교 결과에는 개인 정보가 들어갈 수 있으므로 공개 저장소에 올리지 않습니다.

## 쪽별 조판 검증 기준

Pwh의 조판 개선은 한글에서 출력한 기준 PDF와 같은 원본 문서의 Pwh 출력 PDF를 비교한다. 앞쪽 쪽 나눔의 차이가 뒤쪽까지 전파되므로 **1쪽부터 연속으로 통과한 구간**을 관리한다. 전체 평균이 높아졌다는 이유로 앞쪽의 미해결 차이를 건너뛰지 않는다.

### 통과 조건

각 물리 쪽에 다음 조건을 함께 적용한다.

| 구분 | 고정 기준 |
| --- | --- |
| 비교 위치 | 같은 쪽 번호, 같은 용지 원점과 물리 크기 |
| 래스터화 | 150 dpi, 흰색 배경 |
| 일반 잉크 | 임계값 245, 2픽셀 허용 F1 **0.95 이상** |
| 진한 잉크 | 임계값 180, 2픽셀 허용 F1 **0.90 이상** |
| 내용 | 원문 누락·중복과 다른 쪽으로의 잘못된 배정 없음. PDF 내부 그리기 순서 차이는 별도 대조 |
| 영역 | 본문·표·그림의 실제 넘침 없음. 테두리·여백·쪽번호의 소유 쪽 확인 |
| 이전 구간 | 이미 통과한 앞쪽 구간이 새 출력에서도 모두 통과 |

F1은 지정한 허용 거리 안의 잉크 위치를 비교한 지표이며, “문서 전체가 그 비율만큼 동일하다”는 뜻이 아니다. 숫자가 기준을 넘더라도 테두리 높이나 쪽번호가 잘못됐으면 통과로 인정하지 않는다. 비교를 위해 쪽을 재배열하거나 이미지를 이동·확대·축소해 오차를 숨기지 않는다. 기준을 낮춰 다음 쪽으로 넘어가지 않는다.

### 실행 흐름

1. 누적 수정이 반영된 엔진으로 원본 문서 전체를 다시 조판한다. 이전 엔진에서 남겨 둔 뒤쪽 PDF나 비교 점수로 다음 쪽을 판정하지 않는다. 원본, 한글 기준 PDF, 새 Pwh 출력 PDF와 실행 엔진의 SHA-256을 기록한다. 실문서는 시험 사본만 사용하며 저장소에 넣지 않는다.
2. `scripts/compare-pages.py`로 **모든 물리 쪽**을 각각 일반 잉크와 진한 잉크 조건에서 비교한다. 진단용 일부 쪽 출력은 전체 검증 자료로 사용할 수 없다.
3. 현재 검토 중인 쪽의 텍스트, 조판부호와 개체의 배치 근거, 경계 넘침을 확인한다. 확인하지 않은 검사는 명시적으로 미검증 상태로 남긴다.
4. 보고서 바이트와 문서 해시에 묶인 감사 자료를 `scripts/check-layout-gates.mjs`에 전달한다. 수정 전 승인 기록이 있으면 `--previous`로 전달하여 앞쪽 구간도 다시 검증한다.
5. 처음 미통과한 쪽을 개선한다. 그 쪽이 통과하면 다음 쪽으로 이동한다. 새 엔진 출력마다 이전 승인 구간을 다시 검사한다.

```text
node scripts/check-layout-gates.mjs --normal NORMAL.json --dark DARK.json --audit AUDIT.json --previous PREVIOUS.json --output NEW-GATE.json
```

첫 실행에는 `--previous`를 생략한다. 출력 파일은 기존 검증 기록을 덮어쓰지 않는다. 종료 코드는 전체 통과 `0`, 미통과 구간 존재 `1`, 자료·해시·조건 오류 `2`이다. `acceptedThrough`는 연속 승인한 마지막 쪽, `currentPage`는 다음에 해결할 첫 쪽이다. 뒤쪽 쪽이 우연히 점수 기준을 넘더라도 앞쪽이 미통과하면 `not-reached`로 남는다.

감사 자료의 형식은 도구의 `--help`에 명시돼 있다. 자료가 없거나 원본·출력·보고서 해시가 다르면 승인할 수 없다. 이전에 승인한 구간이 깨지면 `previous-prefix-regression`으로 표시한다. 해시는 자료 연결을 검증하며, 사람이 확인하지 않은 내용을 자동으로 검증했다고 증명하지는 않는다.

다른 쪽에 나와야 할 내용이 현재 쪽에 먼저 표시되는 경우에는 `content.misplaced`에 확인한 글자 수를 기록한다. 전체 문서에 한 번만 존재해 누락·중복 수가 0이어도 `text-on-wrong-physical-page`로 보류한다. 기존 감사 형식에서는 이 항목을 생략할 수 있지만, 생략 자체가 쪽 소유 관계를 확인했다는 근거는 아니다.

### 실행 엔진과 출력 연결

엔진 교체 시험에는 위 명령에 `--engine-wasm CORE.wasm --export EXPORT.json`을 함께 전달한다. 출력 기록은 시험 호스트가 실제 렌더러의 WebAssembly 컴파일·초기화 입력에서 관찰한 바이트 해시와 크기를 포함해야 한다. 서버에 배치한 파일이나 버전 표시만 확인한 기록은 대신 사용할 수 없다.

도구는 지정한 WASM 파일, 출력 기록의 예상 엔진과 실제 관찰 엔진, 원본 및 출력 PDF 해시가 모두 연결되는지 검사한다. 출력 중 원본이 바뀌거나 미저장 편집 상태가 남은 기록도 거부한다. 결과의 `engineBinding`에 실행 엔진과 출력 기록의 해시를 보존한다. 실행 엔진을 연결한 승인 기록 이후에는 이 증거를 생략할 수 없다. 새 엔진의 해시는 달라질 수 있지만, 새 출력 자료와 앞쪽 승인 구간의 재검증이 필요하다.

이 검사는 시험 기록의 일관성을 확인한다. 출력 기록을 수집하는 호스트가 정확하다는 전제까지 독립적으로 증명하거나, 내용·화면 검토를 대신하지는 않는다. 기존 비교 자료는 엔진 연결 옵션 없이 읽을 수 있지만 새 엔진의 실행 근거로 취급하지 않는다.

### 수정과 배포의 경계

차이의 원인은 rhwp 원천 코어, rhwp Studio에서 유래한 Pwh 공통 편집기, Pwh Desktop 호스트로 구분해 기록한다. 코어 수정은 원본을 꾸미거나 잘라내는 보정 대신 문서의 여백·높이·줄 정보·개체 소유 관계가 조판에 적용되는 규칙을 수정한다. 단일 문서에서 개선됐다는 결과만으로 전체 문서의 일치도를 보장하지 않는다.

쪽별 진척 자료는 해당 시험 문서에 한정된다. 엔진을 배포하기 전에는 합성 문서의 음성 사례와 다른 문서의 회귀 검사, Pwh와 Pwh Desktop의 공통 런타임·번들 검증을 함께 수행한다. 실문서, 기준 PDF와 비교 이미지는 공개 저장소·릴리스에 포함하지 않는다.

## SVG 글자의 실제 잉크와 잘림 검증

이 보완의 발생 위치는 **검증 도구**입니다. 제품의 조판 코어·공통 편집기·Desktop 호스트를 바꾸는 패치와 구분합니다.

SVG의 `getBBox()`는 실제로 칠한 글자보다 큰 글꼴 상자를 반환할 수 있습니다. 설치된 글꼴과 대체 글꼴에 따라 이 상자가 달라지므로, 상자의 일부가 셀 경계를 넘었다는 이유만으로 글자가 잘렸다고 판정하지 않습니다. 기존 상자 검사는 위치 진단 자료로 유지합니다.

### 실제 잉크 검사 절차

익명 합성 SVG의 각 글자 런을 따로 표시하고, 나머지 글자와 표 선·그림은 진단 화면에서 숨깁니다. 같은 위치·크기에서 원래 클립을 적용한 PNG와 클립을 해제한 PNG를 비교합니다. 스크린샷을 다시 Canvas로 읽어 실제 알파 잉크의 손실과 경계 깊이를 측정합니다. 글자 상자는 진단 영역을 확보하는 용도로만 사용합니다.

- PDF 품질 판정과 같은 **150 dpi · 2픽셀**을 [공통 정책](../scripts/check-layout-gates.mjs)에서 가져옵니다. 기존 F1 목표 0.95·0.90과 허용 오차를 변경하지 않습니다.
- 원문 런 전체가 보이지 않으면 허용 오차 안이어도 실패합니다. 경계에서 2픽셀보다 깊은 잉크 손실도 실패합니다. 허용 범위 안의 작은 잉크 잔차는 개수·최대 깊이를 결과에 남깁니다.
- 부모 셀 클립과 물리 쪽 경계를 함께 검사합니다. 회전된 클립, 지원하지 않는 마스크·필터 등을 발견하면 한계로 보고해 통과시키지 않습니다.
- 진단 여백은 쪽 밖의 잉크를 관찰하기 위한 공간입니다. 원래 SVG의 크기와 상대 위치를 유지하며, 실제 제품 출력이나 한컴 PDF 비교에 이동·맞춤을 적용하지 않습니다.

원래 글꼴과 통제한 Arial 대체 글꼴에서 같은 원문의 첫 프레임·이어지는 프레임 소유권을 확인합니다. 일부 글자를 잘라 놓은 반례와 런 전체를 숨긴 반례를 함께 실행해, 클립을 무시하거나 잘린 글자를 성공으로 처리하는 검사를 방지합니다.

이 검사는 합성 문서의 잉크·원문 소유권 검증입니다. 사용자 문서 전체의 조판 일치 승인과는 별개이며, 실제 PDF는 계속 고정된 쪽별 점수와 내용·기하 감사를 통과해야 합니다.
