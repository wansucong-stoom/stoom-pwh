# rhwp 0.9.0 검토와 선택 반영

[문서 모음](README.md) · [현재 원본 대비 차이](RHWP-DIFFERENCES.md)

Pwh의 기준 코어를 통째로 교체하지 않고, 원본에서 수정한 결함이 현재 Pwh에도 있는지 확인해 필요한 변경을 옮깁니다. 기준은 rhwp 0.8.7 `1a76570e833917d15817415a53c09ad61ab3203f`와 [0.9.0 고정 커밋](https://github.com/edwardkim/rhwp/tree/c9095c5f67632e6721e800ccc7fb43ea49d26682)입니다. 아래는 관련 편집·표·조판 경로의 검토 결과이며 0.9.0의 모든 변경을 검토했다는 뜻은 아닙니다.

## 이번에 반영한 오류 수정

| 문제와 발생 계층 | Pwh의 처리 | 근거 |
| --- | --- | --- |
| rhwp 기반 코어·Studio 연결: 중첩 셀 문단 서식 미지원 | r28의 전체 경로 API와 명령·ID 실행 취소 연결. Pwh의 부분 테두리·배경 병합을 유지합니다. | [원본 수정 b96229c](https://github.com/edwardkim/rhwp/commit/b96229c141d0b16a511a8b26c1fc4dae2f5eabe0) |
| rhwp 기반 코어: 개체 삭제 뒤 글자 서식 경계가 남음 | r28에서 스트림 메타데이터를 함께 당깁니다. Pwh 원본 좌표계·측정 키·누름틀 소유 범위를 추가 보존합니다. | [원본 수정 33da3e8](https://github.com/edwardkim/rhwp/commit/33da3e8248179f209d1879246d1bc0a7d2265031) |
| rhwp Studio 유래 공통 편집기: 시스템 클립보드 복사 실패 뒤에도 선택 원문을 잘라냄 | 네이티브 Cut 이벤트는 코어 복사와 이벤트 데이터 기록이 성공해야 삭제합니다. 빈 이벤트 데이터와 예외는 삭제하지 않습니다. | [원본 수정 17a8d2e](https://github.com/edwardkim/rhwp/commit/17a8d2e906159ac4f796812c19e04dcb2819d17d) |
| 같은 편집기: 표·그림의 비동기 복사를 기다리지 않고 먼저 삭제 | 쓰기 완료 후 같은 문서 세대·문서 핸들·실행 취소 이력·선택 개체·경로·포커스인지 검사합니다. 중복 Cut과 취소 후 삭제를 막고 리스너·진행 상태를 정리합니다. | [원본 수정 d50535c6](https://github.com/edwardkim/rhwp/commit/d50535c65cdb70a874bc26aac7a6ef34037be51b) |
| 같은 편집기: 구역을 걸친 선택을 단일 구역 삭제 API에 전달 | 지원하지 않는 교차 구역 선택 편집은 변경 전에 거절하고, 삭제 명령에도 방어 검사를 둡니다. 구역 병합을 새로 구현한 것은 아닙니다. | [원본 수정 c575ae38](https://github.com/edwardkim/rhwp/commit/c575ae384aa4ac343d1b64531f2490206ee9ccfe) |

Pwh는 표·그림 Cut에서 평문만 기록한 성공을 개체 보존 성공으로 취급하지 않습니다. HTML·이미지 내보내기나 rich clipboard 기록이 실패하면 원문을 남깁니다. Copy의 평문 대체 경로는 유지합니다. 기존 붙여넣기의 이벤트 데이터 사전 보관과 지연 후 포커스 검사도 유지합니다.

[보존한 Studio 패치](engine-patches/studio/clipboard-safety.patch), [Pwh 적용·보완](../scripts/patch-clipboard-safety.mjs), [회귀 시험](../tests/clipboard-cut-safety-browser.test.mjs)에서 범위를 확인할 수 있습니다. 시험은 합성 문서와 신뢰된 브라우저 Ctrl+X 입력을 사용하며 실패·지연은 해당 시험 컨텍스트의 클립보드 API로 모형화합니다. 사용자 시스템 클립보드나 실제 문서를 수집하지 않습니다. OS 클립보드의 모든 형식을 실제 외부 앱과 왕복한 시험이라는 뜻은 아닙니다.

## 추가 검토 대상으로 분리한 변경

다음 항목은 소스 변경을 찾았지만 이번 반영·검증을 완료한 항목에 포함하지 않습니다. 필요한 경우 각각 합성 문서로 이전 실패를 재현한 뒤 옮겨야 합니다.

| 항목 | 확인할 계약 |
| --- | --- |
| 잘린 줄·중첩 셀 hit-test, 병합 셀 W/H | 현재 Pwh의 쪽 조각 소유권·선택·크기 조절 우선순위와 충돌하지 않는지 확인 |
| PDF 가져오기·네이티브 렌더러 | 별도 기능·구조 변경입니다. 현재 WASM 조판 코어에 단순 병합하거나 멀티스레드 가속으로 표시하지 않습니다. |

r28의 [전후 보고서](verification/CORE-R28.md)는 사전 오류 재현, 수정 후 실제 키·버튼 시험과 기존 245쪽 조판 유지 검사를 구분합니다. 0.9.0 전체 교체는 하지 않습니다.

## 적용 원칙과 확인 범위

코어 계산은 문서명·쪽 번호·개별 표 번호로 분기하지 않습니다. 원본 속성, 글줄·개체의 소유권과 쪽 경계를 기준으로 같은 규칙을 사용합니다. Studio 변경도 공통·Desktop 번들에서 함께 빌드하고 manifest와 소스 지문을 검사합니다.

r25의 최적화 빌드로 기존 익명 TEST 문서 167쪽의 글자 좌표와 인쇄 SVG가 직전 r24와 같은 것을 확인했습니다. 새 78쪽 TEST 문서는 쪽 수를 유지하며 저장된 도형 줄 뒤 간격이 누락된 위치를 고칩니다. 전체 PDF 일치율을 새로 측정한 수치와 혼동하지 않도록 구분합니다. 상세 결과는 [현재 변경과 검증](RHWP-DIFFERENCES.md)에 연결합니다.
